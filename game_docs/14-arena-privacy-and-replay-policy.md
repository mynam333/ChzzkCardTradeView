# 치카포 아레나 개인정보 및 리플레이 정책

## 1. 목적

이 문서는 치카포 아레나에서 저장하는 데이터, 리플레이 공개 범위, 스트리머 카드 비활성화 시 데이터 처리, 로그 보관 기간, 운영자 접근 기준을 정의한다.

아레나는 치카포의 이미지와 코스메틱 리소스를 활용하지만, 전투력 계산에는 치카포의 경제 데이터나 방송 데이터를 사용하지 않는다.

전투력에 사용하지 않는 데이터:

- 카드 시세
- 후원 금액
- 방송 중 여부
- 시청자 수
- 채팅량
- 팔로워 수
- 치카포 포인트
- 카드 보유 수량
- 특정 사용자의 구매력

## 2. 데이터 분류

### 2.1 공개 가능한 데이터

서비스 화면에 표시될 수 있는 데이터.

- 스트리머 카드명
- 카드 이미지 또는 프로필 이미지
- 카드 클래스
- 카드 역할군
- 공개 스킬 설명
- 시너지 태그
- 시즌 랭킹 닉네임
- 랭킹 점수 또는 티어
- 승률, 픽률 등 집계 통계

주의:

- 공개 통계는 개인을 특정할 수 있는 세부 로그가 아니라 집계된 지표로 제공한다.
- 내부 밸런스 계산값, 난수 시드, 어뷰징 점수는 공개하지 않는다.

### 2.2 사용자 본인에게만 제공되는 데이터

- 본인 매치 히스토리
- 본인 덱 목록
- 본인 MMR 변경 이력
- 본인 리플레이
- 본인 제재 또는 보정 이력의 요약

### 2.3 내부 운영 데이터

운영자와 시스템만 접근한다.

- 매치 시뮬레이션 원본 이벤트 로그
- 라운드별 전술 설정 스냅샷
- 매치 검증 해시
- MMR 처리 idempotency key
- 어뷰징 탐지 점수
- queue sniping 탐지 로그
- 관리자 조작 로그
- 스트리머 카드 비활성화 신청 및 처리 로그

## 3. 저장 데이터

### 3.1 매치 요약

매치 종료 후 저장한다.

필드 예:

```text
match_id
season_id
match_format = best_of_3
rounds_to_win = 2
winner_user_id
loser_user_id
round_count
round_results
rating_delta
created_at
```

용도:

- 전적 조회
- 랭킹 산정
- 장애 복구
- 어뷰징 조사
- 시즌 통계

### 3.2 덱 스냅샷

매치 시작 시점의 덱 상태를 저장한다.

저장 이유:

- 매치 후 카드 밸런스가 바뀌어도 당시 경기를 재현하기 위함
- 클라이언트 조작 여부를 검증하기 위함
- 리플레이와 결과 화면을 안정적으로 제공하기 위함

덱 스냅샷에는 당시 카드 버전, 클래스, 스킬, 태그, 전술 슬롯 정보가 포함된다.

### 3.3 라운드별 전술 설정

5판 3선승 구조에서는 라운드별 전술 계획을 매치 시작 전에 확정한다.

저장 항목:

- round_no
- formation_id
- focus_rule
- target_priority
- skill_timing_rule
- plan_hash

운영 원칙:

- 매치 진행 중에는 사용자가 추가 입력하지 않는다.
- 서버는 사전 저장된 전술 계획만 사용한다.
- 클라이언트가 전투 결과를 제출하지 않는다.

### 3.4 전투 이벤트 로그

리플레이와 검증에 필요한 최소 이벤트만 저장한다.

예:

```text
tick
actor_card_id
event_type
target_card_id
value
state_hash
```

저장 최소화 원칙:

- 매 프레임 좌표를 모두 저장하지 않는다.
- 리플레이 연출은 서버 이벤트와 클라이언트 보간으로 구성한다.
- 봇전 상세 로그는 짧게 보관한다.
- 랭킹전 상세 로그는 장애 및 어뷰징 조사에 필요한 기간만 보관한다.

## 4. 리플레이 공개 정책

### 4.1 MVP 기준

MVP에서는 리플레이 공개 범위를 좁게 유지한다.

- 본인 경기 리플레이 조회 가능
- 상대방 닉네임과 덱은 경기 결과 화면 기준으로 표시
- 제3자 공개 리플레이는 제공하지 않음
- 상위 랭킹 리플레이 공개 기능은 정식 시즌 이후 검토

이유:

- 개인정보와 권리 이슈를 줄인다.
- 리플레이 저장량을 제한한다.
- 초기 서버 부하를 낮춘다.
- 밸런스 악용 가능성을 줄인다.

### 4.2 정식 시즌 이후 확장안

검토 가능한 공개 리플레이:

- 상위 랭킹 공개 리플레이
- 사용자가 직접 공개 설정한 리플레이
- 시즌 대표 경기
- 운영자가 선정한 밸런스 참고 경기

확장 조건:

- 비공개 설정 기능 제공
- 스트리머 비활성화 정책과 충돌하지 않음
- 리플레이 저장 비용이 허용 범위 내
- 어뷰징 악용 가능성 점검 완료

### 4.3 공개하지 않는 정보

리플레이에 표시하지 않는다.

- match_seed 원본
- round_seed 원본
- 내부 state_hash
- MMR 계산 내부값
- 어뷰징 탐지 플래그
- 서버 처리 시간
- 내부 카드 예산 점수

## 5. 스트리머 카드 비활성화와 데이터 처리

### 5.1 비활성화 적용 범위

스트리머가 자신의 카드 사용을 원하지 않으면 신규 매치 카드 풀에서 제외한다.

적용 항목:

- 신규 덱 생성 제외
- 랜덤 카드 풀 제외
- 봇 덱 생성 제외
- 추천 덱 제외
- 카드 도감에서 제한 표시 또는 비공개 처리

### 5.2 기존 매치 기록

이미 종료된 매치 기록은 경기 무결성을 위해 보존할 수 있다.

처리 원칙:

- 매치 결과는 유지한다.
- 랭킹과 MMR은 소급 삭제하지 않는다.
- 리플레이는 정책에 따라 제한 표시할 수 있다.
- 카드 이미지는 대체 이미지로 표시할 수 있다.
- 카드명은 “비활성화된 카드” 또는 제한된 표시명으로 대체할 수 있다.

### 5.3 신청 처리 로그

비활성화 신청은 운영 분쟁에 대비해 처리 로그를 남긴다.

저장 항목:

- channel_id
- 신청자 식별 정보
- 본인 확인 방식
- 신청 시각
- 처리 시각
- 처리 상태
- 처리 관리자

## 6. 보관 기간

권장 보관 기간:

| 데이터 | MVP 보관 기간 | 정식 시즌 보관 기간 | 비고 |
| --- | ---: | ---: | --- |
| 봇전 상세 이벤트 로그 | 0~3일 | 0~3일 | 필요 시 저장 안 함 |
| 랭킹전 상세 이벤트 로그 | 7~14일 | 14~30일 | 장애/어뷰징 조사용 |
| 매치 요약 | 180일 이상 | 시즌 단위 장기 보관 | 전적/통계용 |
| MMR 변경 이력 | 시즌 전체 | 시즌 전체 + 30일 | 보정 가능성 |
| 랭킹 스냅샷 | 시즌 전체 | 시즌 전체 | 보상 기준 |
| 관리자 조작 로그 | 1년 이상 | 1년 이상 | 감사 목적 |
| 스트리머 비활성화 로그 | 유지 | 유지 | 권리 처리 증빙 |
| 어뷰징 조사 로그 | 90일 이상 | 180일 이상 | 제재 이의 처리 |

서버 저장 공간이 부족하면 상세 이벤트 로그부터 삭제한다.

삭제 우선순위:

1. 봇전 상세 로그
2. 오래된 랭킹전 상세 로그
3. 리플레이 보간 데이터
4. 비핵심 통계 캐시

삭제하면 안 되는 데이터:

- 시즌 보상 기준 랭킹 스냅샷
- MMR 보정에 필요한 최소 이력
- 스트리머 비활성화 처리 로그
- 관리자 조작 로그

## 7. 운영자 접근 정책

운영자 접근은 필요한 범위로 제한한다.

접근 권한:

- 고객 응대: 매치 요약, 본인 문의 대상 리플레이
- 밸런스 담당: 익명화된 카드 통계, 승률, 픽률
- 보안 담당: 어뷰징 로그, 큐 매칭 패턴
- 최고 관리자: 스트리머 비활성화 처리, 랭킹 보정, 관리자 로그

필수 로그:

- 누가 조회했는지
- 어떤 데이터를 조회했는지
- 언제 조회했는지
- 어떤 사유로 조회했는지

## 8. 사용자 권리와 문의

사용자가 요청할 수 있는 항목:

- 본인 매치 기록 확인
- 본인 리플레이 문제 신고
- 랭킹/MMR 보정 문의
- 보상 미지급 문의
- 계정 제재 이의

스트리머가 요청할 수 있는 항목:

- 자신의 아레나 카드 비활성화
- 카드 이미지 표시 제한
- 카드명 표시 제한
- 비활성화 처리 상태 확인

즉시 처리하지 않는 항목:

- 이미 종료된 경기 결과 삭제
- 다른 사용자의 리플레이 전체 삭제
- 랭킹 보상 지급 후 임의 순위 변경
- 내부 어뷰징 점수 공개

## 9. 클라이언트 표시 기준

리플레이와 결과 화면에서는 아래 원칙을 지킨다.

- 현재 카드 정보가 아니라 매치 당시 스냅샷을 우선 표시한다.
- 비활성화된 스트리머 카드는 제한 표시 정책을 따른다.
- 전투 결과는 서버 확정값만 표시한다.
- 클라이언트 계산값을 MMR 또는 보상에 반영하지 않는다.
- 오류가 있으면 “리플레이를 불러올 수 없음”과 “경기 결과는 정상 반영됨”을 구분한다.

## 10. 금지 사항

아래 기능은 도입하지 않는다.

- 방송 중인 스트리머 카드에 전투 버프 부여
- 시세가 높은 카드에 전투 보너스 부여
- 후원 또는 유료 결제로 전투 능력 상승
- 카드 보유 수량에 따른 전투력 증가
- 팔로워 수 또는 시청자 수 기반 능력치 증가
- 유저가 클라이언트에서 제출한 전투 결과 반영
- 공개 리플레이에서 내부 난수 시드 노출

# 치카포 아레나 리스크 등록부 및 검수 기준

## 1. 목적

이 문서는 치카포 아레나를 상용 서비스 수준으로 출시하기 전에 반드시 관리해야 할 리스크와 단계별 합격 기준을 정의한다.

이 문서의 기준을 통과하지 못하면 기능이 구현되어도 정식 시즌을 열지 않는다.

## 2. 절대 원칙

아래 항목은 출시 후에도 변경하지 않는 핵심 원칙이다.

- 아레나 전투력은 후원, 시세, 방송 여부, 포인트, 카드 보유량과 연결하지 않는다.
- 치카포에서 가져오는 데이터는 이미지와 코스메틱 중심으로 사용한다.
- 스트리머는 자신의 카드가 아레나에 사용되지 않도록 비활성화할 수 있다.
- 스트리머가 직접 설정하지 않은 카드는 `channel_id` 기반 고정 랜덤 템플릿을 사용한다.
- 같은 스트리머 카드는 모든 사용자에게 같은 능력을 가진다.
- 빠른대전은 5판 3선승 세트 매치다.
- 한 세트는 리플레이 체감 기준 7~12분을 목표로 한다.
- 서버는 매칭 시 덱/시드만 고정하고 각 라운드 커밋 시점에 해당 라운드만 확정하며, 실시간 상주 매치룸을 기본 구조로 삼지 않는다.
- 아레나 MMR과 랭킹은 치카포 본편과 분리한다.
- 백엔드와 MySQL이 같은 저사양 서버에서 안정적으로 돌아가는 것을 최우선 기준으로 둔다.

## 4. MVP 범위 합격 기준

MVP는 “상용 서비스 가능성을 검증하는 완성된 최소 버전”이다. 단순 프로토타입이 아니다.

필수 기능:

- 아레나 홈
- 카드 목록과 카드 상세
- 덱 편성
- 라운드별 전술 계획 1~5라운드 설정
- 빠른대전 대기열
- 서버 권위 5판 3선승 세트 시뮬레이션
- 매치 결과
- 기본 리플레이
- AI 연습게임
- 아레나 전용 MMR
- 랭킹 스냅샷 조회
- 스트리머 카드 비활성화
- 스트리머 카드 프리셋 설정
- 미설정 카드 결정론적 템플릿 생성
- 관리자 kill switch

MVP에서 제외 가능한 기능:

- 실시간 공개 리플레이
- 실시간 관전
- 길드/팀전
- 시즌 패스
- 유료 코스메틱 상점
- 실시간 채팅 연동
- 대규모 토너먼트
- 카드 애니메이션 고급 연출

합격 기준:

| 항목 | 기준 |
| --- | --- |
| 전투 | 같은 입력과 버전이면 항상 같은 결과 |
| 세트 구조 | 3:0, 3:1, 3:2로 정상 종료 |
| 플레이 체감 | 리플레이 기준 7~12분 |
| 서버 시뮬레이션 | p95 CPU 시간 500ms 이하 목표 |
| MMR | 중복 반영 방지 |
| 랭킹 | 스냅샷 기반 조회 |
| 봇전 | MMR 미반영 |
| 비활성화 | 신규 매치 카드 풀에서 즉시 제외 |
| P2W 차단 | 금지 데이터가 전투 계산에 사용되지 않음 |
| 로그 | 장애 복구에 필요한 최소 로그 존재 |

## 5. 클로즈드 베타 합격 기준

클로즈드 베타는 제한된 사용자로 기능, 부하, 밸런스를 검증한다.

진행 조건:

- 내부 QA 통과
- kill switch 동작 확인
- 랭킹 초기화 가능
- 보상 미지급 또는 테스트 보상 명시
- 장애 공지 템플릿 준비

측정 지표:

| 지표 | 목표 |
| --- | ---: |
| 매치 생성 실패율 | 1% 이하 |
| MMR 반영 실패율 | 0.1% 이하 |
| 중복 결과 반영 | 0건 |
| 빠른대전 API p95 | 300ms 이하 |
| 매칭 상태 API p95 | 150ms 이하 |
| 리플레이 조회 실패율 | 2% 이하 |
| 첫 매치 진입 완료율 | 70% 이상 |
| 봇전 완료율 | 90% 이상 |

밸런스 기준:

- 상위 사용 조합 세트 승률 57% 이하 권장
- 특정 클래스 픽률 25% 초과 시 검토
- 특정 스킬 상위권 채용률 35% 초과 시 검토
- 3:0 비율이 과도하거나 3:2 장기전 비율이 과도한 조합은 핫픽스 후보

## 6. 오픈 베타 합격 기준

오픈 베타는 실제 트래픽에서 상용 운영 가능성을 확인한다.

필수 조건:

- 시즌 초기화와 종료 절차 검증
- 랭킹 스냅샷 자동 생성
- 보상 dry-run 가능
- 스트리머 비활성화 신청 처리 가능
- 운영자 감사 로그 확인 가능
- 리플레이 보관 기간 자동 적용

운영 기준:

| 항목 | 기준 |
| --- | --- |
| 서버 안정성 | 본편 API에 의미 있는 영향 없음 |
| 장애 대응 | SEV-1 공지 15분 이내 가능 |
| 랭킹 | 스냅샷 누락 시 재생성 가능 |
| 보상 | 지급 전 대상자 검수 가능 |
| 어뷰징 | 의심 매치 목록 조회 가능 |
| 밸런스 | 핫픽스 적용 후 카드 버전 관리 가능 |

## 7. 정식 시즌 오픈 기준

정식 시즌은 보상, 랭킹 신뢰, 스트리머 권리 처리가 모두 준비된 뒤 시작한다.

정식 시즌 전 필수 확인:

- 시즌 기간과 보상 공지 완료
- 랭킹 보상 지급 기준 확정
- 비활성화 신청 경로 공개
- 개인정보 및 리플레이 정책 공개
- 장애 대응 runbook 준비
- 커뮤니케이션 템플릿 준비
- 서버 부하 테스트 통과
- 밸런스 시뮬레이션 통과
- 관리자 기능 접근 권한 점검

정식 시즌 금지:

- 테스트 데이터가 랭킹에 남아 있는 상태로 시작
- 보상 기준이 불명확한 상태로 시작
- 리플레이 정책 없이 공개 리플레이 제공
- 비활성화 기능 없이 스트리머 카드 사용
- 실시간 전체 랭킹 정렬 쿼리로 운영
- 클라이언트 전투 결과를 신뢰하는 구조로 운영

## 8. 출시 전 Go/No-Go 체크리스트

### Go 조건

- 빠른대전이 5판 3선승으로 정상 종료된다.
- 밴픽과 시즌 로테이션 카드 풀 경로가 존재하지 않는다.
- 8인 컵이 랭크 MMR과 분리되어 정상 종료된다.
- 관전은 완료 리플레이만 조회한다.
- 관리자 통계는 스냅샷 테이블만 조회한다.
- 서버에서 세트 결과를 확정한다.
- 동일 입력의 재시뮬레이션 결과가 일치한다.
- MMR 중복 반영 방지가 검증됐다.
- 랭킹은 스냅샷으로 조회된다.
- 스트리머 비활성화 카드가 신규 매치에 나오지 않는다.
- 금지 데이터가 전투 계산 코드에 없다.
- kill switch가 기능별로 동작한다.
- 장애 공지와 복구 공지 템플릿이 준비됐다.
- 보상 지급 dry-run이 성공했다.

### No-Go 조건

- 본편 API 지연이 증가한다.
- MySQL CPU 또는 메모리가 위험 수준으로 상승한다.
- 전투 결과가 클라이언트 입력에 의존한다.
- MMR 중복 반영 사례가 있다.
- 비활성화된 카드가 신규 매치에 등장한다.
- 랭킹 보상 기준이 확정되지 않았다.
- 관전 공유 링크/리플레이 권한 정책이 없다.
- 상위 조합 독주가 심각하지만 핫픽스 기준이 없다.
- 장애 시 아레나만 중단할 수 없다.

## 9. QA 시나리오

### 9.1 매치 기본

- 정상 덱으로 빠른대전 참가
- 상대 매칭
- 1~3라운드 연속 승리로 3:0 종료
- 초반 열세 후 5라운드까지 진행해 3:2 종료
- 제한 시간 초과 라운드 처리
- 동률 판정 처리
- 결과 화면 표시
- 리플레이 조회

### 9.2 덱 검증

- 카드 수 부족
- 카드 수 초과
- 중복 금지 카드 중복 선택
- 비활성화 카드 포함
- 금지 조합 포함
- 라운드별 전술 계획 누락
- 만료된 카드 버전 사용

### 9.3 MMR 및 랭킹

- 승리 시 MMR 증가
- 패배 시 MMR 감소
- 봇전 MMR 미반영
- 같은 match_id 중복 반영 차단
- 랭킹 스냅샷 생성
- 랭킹 보정 후 재생성

### 9.4 스트리머 비활성화

- 본인 카드 설정 조회
- 본인 카드 비활성화
- 신규 덱 생성에서 제외
- 빠른대전 매칭 카드 풀에서 제외
- 봇 덱 생성에서 제외
- 기존 매치 결과 유지
- 리플레이 제한 표시 확인

### 9.5 장애 대응

- 빠른대전 kill switch
- 봇전 kill switch
- 리플레이 kill switch
- 랭킹 조회 kill switch
- 시뮬레이션 워커 중단
- 랭킹 스냅샷 재생성
- MMR 재계산

### 9.6 이탈 및 재접속

- 큐 대기 중 화면 이탈 시 본인 큐만 취소 또는 만료
- 큐 대기 중 연결 종료가 즉시 DB write 폭증으로 이어지지 않음
- 매칭 확정 직후 한쪽 클라이언트 종료
- 남은 유저가 대기 없이 match result와 replay 조회 가능
- 종료한 유저가 재접속 후 같은 match id로 결과 조회 가능
- 아레나 메인 진입 시 시즌과 큐 상태에 관계없이 진행 중인 본인 match를 조회하고 재접속 가능
- 빠른대전 항복 시 상대 승리, 본인 패배, MMR이 한 번만 반영되고 즉시 새 대전 가능
- 이미 완료된 매치에 대한 중복 항복 요청이 기존 승패와 MMR을 변경하지 않음
- 8인전 개별 매치에는 항복이 노출되지 않고 재접속만 가능
- 매칭 확정 후 cancel 요청이 match를 취소하지 않음
- 리플레이 중 나가기가 상대 화면, MMR, 보상에 영향 없음
- 반복 큐 취소만 재큐 쿨다운 대상으로 기록

## 12. 확장 기능 합격 기준

5판 3선승:

- 3:0, 3:1, 3:2 결과가 모두 정상 기록된다.
- 라운드별 전술 선택은 제한 시간과 검증된 선택지 안에서만 반영된다.
- 라운드 사이 실시간 입력이 없다.

8인 컵:

- 8명 참가, 브래킷 생성, 1~8위 산정이 가능하다.
- 컵 결과는 기본 랭크 MMR에 반영되지 않는다.
- 컵 상세 로그 저장량이 제한된다.
- 컵 kill switch가 동작한다.

관전:

- 완료된 매치/컵만 공개 가능하다.
- 권한 없는 리플레이는 조회되지 않는다.
- 관전자 진행 위치를 서버에 저장하지 않는다.

관리자 통계:

- 클래스/스킬/스탯/태그/전술 칩/전장 규칙 승률을 스냅샷으로 조회한다.
- 표본 부족 항목은 숨김 또는 경고 표시된다.
- 관리자 화면 요청 중 대량 실시간 집계 쿼리가 없다.

금지 확인:

- 밴픽 없음.
- 시즌 로테이션 카드 풀 없음.
- 실시간 관전 tick stream 없음.

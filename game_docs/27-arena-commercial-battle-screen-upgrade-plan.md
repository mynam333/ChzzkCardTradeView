# 치카포 아레나 상용 전투 화면 고도화 계획

## 1. 목적

실제 게임 페이지를 단순 리플레이 화면이 아니라 상용 카드 배틀 게임처럼 보이게 만든다. 서버 권위 전투, 저부하 원칙, 비P2W 정책은 그대로 유지하며, 프론트엔드에서 이미 확정된 라운드 이벤트를 더 명확하고 매력적으로 재생한다.

## 2. 상위 원칙

- 서버는 라운드 결과와 이벤트만 확정한다.
- 프론트는 결과를 임의 계산하지 않고 서버 리플레이 이벤트를 시간순으로 재생한다.
- 결과, 스코어 변화, 로그 상세는 전투 연출 종료 전까지 선노출하지 않는다.
- 전투 연출은 한 턴에 한 행동이 명확히 보이도록 구성한다.
- 모든 추가 연출은 클라이언트 렌더링 전용이며 DB 쓰기, 추가 서버 계산, 상시 폴링을 만들지 않는다.
- 저사양 기기에서는 `arena:vfx-quality` 설정과 `prefers-reduced-motion`을 우선해 파티클과 흔들림을 줄인다.

## 3. 게임 페이지 정보 구조

### 3.1 상단 매치 HUD

상단 HUD는 다음 정보를 즉시 보여준다.

- 현재 라운드
- 최종 목표: 5판 3선승
- 현재 스코어
- 상태: 준비, 대기, 전투 중, 완료
- 현재 액션: 전술 선택, 상대 대기, 리플레이 재생, 결과 확인

상단 HUD는 텍스트 설명이 길어지지 않도록 작은 메트릭 카드와 강한 상태 배지를 사용한다.

### 3.2 전장 영역

전장 영역은 다음 순서로 구성한다.

1. 전장 규칙 헤더
2. 라운드 진행 배너
3. PixiJS 전투 보드
4. 라운드 준비 시 출전 카드 편성
5. 완료 후 리플레이 컨트롤과 전투 로그

전장 규칙 헤더는 기능 안내가 아니라 현재 전장의 이름과 효과만 간결하게 보여준다.

전투 연출이 길게 느껴질 때는 사용자가 `결과만 보기` 또는 `둘 다 스킵`으로 현재 라운드 연출을 끝낼 수 있어야 한다. 봇전과 완료 리플레이는 이미 받은 리플레이 이벤트의 마지막 상태로 클라이언트 표시만 이동한다. 진행 중인 PvP는 한쪽만 결과를 먼저 보지 않도록 `/arena/realtime`의 휘발성 스킵 동의를 사용하며, 양쪽 플레이어가 모두 스킵했을 때만 결과 화면으로 이동한다. 이 과정은 서버 결과를 새로 계산하지 않고 DB에 저장하지 않는다.

### 3.3 사이드 패널

사이드 패널은 라운드 선택, 전술 선택, 리플레이 제어를 담당한다. 너무 많은 설명 문구는 넣지 않고, 현재 할 행동이 무엇인지 버튼과 상태 배지로 전달한다.

## 4. PixiJS 전투 HUD 기준

### 4.1 중앙 행동 HUD

중앙 HUD는 다음을 표시한다.

- 행동 단계: 준비, 조준, 타격, 정리
- 행동 타입: 기본 공격, 스킬, 궁극기, 회복, 보호, 제어, 전투불능
- 행동자 이름
- 대상 이름
- 턴 진행률
- 리플레이 내 현재 턴 번호

행동자와 대상은 텍스트뿐 아니라 같은 색상 계열의 링, 연결선, 카드 테두리로 연결되어야 한다.

### 4.2 행동자/대상 포커스

- 행동자는 외곽 오라와 작은 `ACTION` 배지를 가진다.
- 대상은 타격 방향을 알 수 있는 모서리 브래킷과 `TARGET` 배지를 가진다.
- 대상이 여러 장이면 첫 대상은 강하게, 보조 대상은 약하게 표시한다.
- 행동과 무관한 생존 카드는 살짝 낮은 투명도로 뒤로 물러나 보이게 한다.

### 4.3 카드 상태

카드에는 다음 상태가 즉시 읽혀야 한다.

- HP 수치와 HP 바
- 스킬 3개 슬롯
- 전열/후열
- 클래스
- 주요 스탯
- 전투불능 오버레이
- 상태 변화 배지: 피해, 회복, 보호, 제어, 궁극기

HP가 0이거나 `DEATH` 이벤트가 반영된 카드는 더 이상 행동자처럼 연출하지 않는다.

## 5. 전투 연출 리듬

전투는 다음 박자를 따른다.

1. 예고: 행동자 오라와 HUD 갱신
2. 준비: 공격자는 살짝 뒤로 당기거나 스킬 에너지를 모은다.
3. 실행: 공격자는 대상 표면까지 돌진하거나 투사체를 발사한다.
4. 히트스톱: 접촉 순간 80~120ms 정도 충격감을 준다.
5. 결과: 피해/회복 숫자, HP 변화, 상태이상, 전투불능을 표시한다.
6. 정리: 카드 위치와 화면 흔들림을 원복하고 다음 턴으로 넘어간다.

라운드 전체가 느려지지 않도록 일반 턴은 520~760ms 안에 끝내고, 궁극기만 900ms 내외까지 허용한다.

## 6. VFX 언어

| 타입 | 색상 | 핵심 연출 |
| --- | --- | --- |
| 기본 공격 | 로즈/화이트 | 카드 돌진, 표면 충돌, 슬래시, 짧은 화면 흔들림 |
| 스킬 | 로즈/보라 | 투사체, 궤적, 대상 폭발 |
| 궁극기 | 앰버/화이트 | 큰 링, 화면 플래시, 다중 파편 |
| 회복 | 그린 | 상승 입자, 회복 링, 플러스 숫자 |
| 보호 | 블루 | 방패 돔, 보호막 링, 실드 배지 |
| 제어 | 바이올렛 | 속박선, 룬 링, 짧은 흔들림 |
| 화상/중독 | 레드/그린 | 잔류 입자, 버블/불꽃, 디버프성 숫자 |
| 전투불능 | 슬레이트 | 어두운 오버레이, 파편, 전투불능 텍스트 |

Pixi 렌더러는 위 표의 VFX 언어를 같은 이펙트로 재활용하지 않고, 액션 종류별로 다른 실루엣을 가져야 한다. 기본 공격은 슬래시와 충돌 플래시, 스킬은 룬 링과 방사선, 궁극기는 십자 플래시와 큰 링, 회복은 상승 링과 플러스 모양, 보호는 방패 돔과 가로 레일, 제어는 사슬/구속선, 화상/중독은 잔류 입자와 버블, 템포는 속도선 중심으로 표현한다. 저사양 기기에서는 같은 색상 언어를 유지하되 입자 수와 화면 흔들림을 줄인다.

VFX 해석은 `vfx_kind`, `damage_type`, `skill_type`, `effect_tags`를 `arenaVfxPresets` 프리셋으로 매핑해 처리한다. 새 스킬이 추가되어도 렌더러 내부 조건문을 늘리기보다 프리셋 매핑과 서버 이벤트 태그를 조정한다.

### 6.1 VFX 프리뷰 QA

아레나 설정 페이지의 전투 VFX 프리뷰는 실제 Pixi 전투 렌더러에 로컬 샘플 리플레이 이벤트를 주입해 기본 공격, 스킬, 궁극기, 회복, 보호, 제어, 화상, 중독, 템포, 전투불능을 즉시 확인할 수 있어야 한다. 이 프리뷰는 API 호출, 매치 생성, 리플레이 저장, DB write를 만들지 않는다. 사용자가 선택한 `arena:vfx-quality` 설정을 그대로 따르며, 운영 중 문제 제보나 디자인 QA 때 같은 화면에서 품질 설정과 이펙트 검수를 함께 수행한다.

설정 페이지의 `실제 매치 화면으로 QA` 버튼은 `/arena/matches?match_id=__arena_vfx_preview__` 로 이동해 실제 매치 상세 화면의 HUD, 결과 카드, 리플레이 컨트롤, Pixi 전장을 같은 로컬 샘플 데이터로 검증한다. 이 QA 매치는 공유 링크 생성, 서버 매치 조회, 리플레이 조회를 수행하지 않으며 관전 공유 버튼은 비활성화된다.

## 7. 결과 모달 기준

경기 종료 시 결과 모달은 다음을 보여준다.

- 승패와 최종 스코어
- 5개 라운드 점 표시
- MVP 카드
- 결정적 라운드 하이라이트
- 가장 큰 피해/회복/보호 수치
- 관전 링크 복사, 다시 플레이, 덱 수정 CTA

결과 모달은 전투 종료 후 표시하며, 전투 중 하단에 최종 승패를 선노출하지 않는다.

## 7.1 리플레이 스키마와 저장 정책

리플레이는 서버 권위 이벤트 로그와 라운드 유닛 스냅샷만 저장한다. 프론트는 `DAMAGE`, `HEAL`, `SHIELD_GAIN`, `DEATH`, `ROUND_RESULT` 이벤트를 재해석해 전투를 재생하지만 승패를 다시 계산하지 않는다.

필수 규칙은 다음과 같다.

- 라운드 필수 필드: `round_no`, `duration_ms`, `winner_side`, `unit_states`, `events`
- 이벤트 필수 필드: `t`, `type`
- 행동 이벤트: `BASIC_ATTACK`, `SKILL_CAST`는 `actor`를 가져야 한다.
- 결과 이벤트: `DAMAGE`, `HEAL`, `SHIELD_GAIN`은 `targets`, `value`, 가능한 경우 `hp_after` 또는 `shield_after`를 가진다.
- 전투불능 이벤트: `DEATH`는 전투불능 대상 토큰과 `alive_after=false`를 가져야 한다.
- `DEATH` 이후 같은 토큰이 다시 행동자로 등장하면 진단 오류로 본다.

저장 정책은 `arena_match_replays`를 기본 경로로 사용하고, `arena_matches.replay_json`은 기존 데이터 읽기 fallback으로만 유지한다. 저장 전 `max_events_per_round`, `max_bytes`, `prune_retention_days`를 적용하며, 저장된 리플레이에는 `replay_schema_version=2`, `storage_policy`, `diagnostic_summary`를 포함한다.

## 7.2 관리자 전투 진단

아레나 관리자 페이지의 `전투 진단` 탭은 매치 ID를 직접 입력했을 때만 `/admin/arena/matches/:match_id/replay-diagnostic`을 호출한다. 이 화면은 다음을 보여준다.

- 리플레이 존재 여부
- 저장 정책
- 라운드별 이벤트 수, 생략 수, 오류/경고 수
- 스키마 이슈 코드와 설명
- JSON 내보내기

이 진단은 운영자가 “프론트에서 죽은 카드가 살아 보인다”, “스킬 수치가 이상하다” 같은 제보를 받은 뒤 특정 매치를 확인하는 용도다. 상시 폴링이나 대량 스캔을 수행하지 않는다.

## 8. 모바일 기준

- 모바일에서도 상대 진영은 위, 내 진영은 아래를 유지한다.
- 카드 크기는 캔버스 폭과 높이를 기준으로 자동 clamp한다.
- 전투 HUD는 중앙에 너무 크게 뜨지 않고, 카드와 겹칠 경우 더 작아진다.
- 로그는 전장 아래 접힌 영역처럼 보이고, 페이지 전체를 과하게 밀어내지 않는다.
- 툴팁은 화면 경계 안으로 보정한다.

## 9. 성능 기준

- Pixi 애플리케이션은 전투 스테이지당 1개만 유지한다.
- 턴 연출 컨테이너만 교체하고 정적 장면은 필요할 때만 다시 그린다.
- 이미지 텍스처는 내부 LRU 캐시 상한을 지킨다.
- 파티클 수는 `high`, `low`, `off` 품질에 따라 제한한다.
- 서버/DB에 추가 부하를 만들 수 있는 실시간 tick stream, 추가 리플레이 조회, 상시 저장은 금지한다.
- 봇전의 `결과만 보기`와 완료 리플레이의 `마지막 장면`은 프론트 재생 위치만 변경하며 API 호출을 만들지 않는다.
- 진행 중인 PvP의 `둘 다 스킵`은 `/arena/realtime` 웹소켓에 휘발성 동의 상태만 남기고 DB write를 만들지 않는다. 연결 실패나 상대 미동의 시에는 기존 전투 타이머로 자연 종료된다.
- 실제 매치 화면은 낮은 빈도의 성능 샘플을 `/arena/telemetry/performance`로 1회 전송할 수 있다. 이 샘플은 API 프로세스 메모리에만 집계하고 DB에 저장하지 않는다.
- 관리자 운영 상태는 인메모리 성능 샘플의 평균 초기화 시간, 리플레이 시간, 이벤트 수만 보여주며, 프로세스 재시작 시 초기화되어도 무방하다.

## 10. 구현 체크리스트

- 상단 매치 HUD가 현재 상태와 다음 행동을 명확히 보여준다.
- Pixi 중앙 HUD가 행동자, 대상, 진행률, 턴 번호를 보여준다.
- 행동자와 대상 카드가 같은 액션 색상으로 연결된다.
- 기본 공격은 대상 카드 표면을 실제로 타격하는 돌진 모션을 가진다.
- 스킬/회복/보호/제어/궁극기는 서로 다른 VFX 언어를 가진다.
- Pixi impact burst와 signature effect는 액션 종류별 다른 실루엣을 사용하며, 궁극기/화상/공격은 더 강한 hit-stop을 가진다.
- 피해/회복 숫자가 카드 밖에서 잘리지 않는다.
- 완료 리플레이와 관전 현재 장면은 피해, 회복, 보호, 제어, 전투불능 요약 칩을 제공해 긴 로그를 읽지 않아도 핵심 효과를 알 수 있다.
- 전투불능 카드는 이후 행동자처럼 보이지 않는다.
- 결과 모달은 전투 종료 후 표시된다.
- 봇전은 전투 중 `결과만 보기`가 가능하고, PvP는 양쪽 모두 동의한 경우에만 스킵된다.
- 완료 리플레이에서 `마지막 장면`으로 이동할 수 있다.
- 관전 페이지도 실제 게임 페이지와 같은 전투 HUD, 현재 행동 문구, 마지막 장면 이동을 제공한다.
- 설정 페이지의 전투 VFX 프리뷰에서 모든 액션 타입을 서버 부하 없이 재생할 수 있다.
- `__arena_vfx_preview__` 로컬 QA 매치에서 실제 매치 화면도 서버 부하 없이 전투 렌더러를 검수할 수 있다.

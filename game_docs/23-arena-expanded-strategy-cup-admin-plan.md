# 치카포 아레나 확장 전략, 8인 컵, 관전, 관리자 운영 기획서

## 1. 목적

이 문서는 치카포 아레나를 5판 3선승 기반의 더 깊은 전략 게임으로 확장하면서도, 백엔드와 MySQL에 과도한 부하를 만들지 않는 운영 기준을 정의한다.

확정 방향:

- 기본 랭크 빠른대전은 5판 3선승으로 확장한다.
- 한 매치의 유저 체감 시간은 7~12분을 목표로 한다.
- 서버는 매치 전체를 선계산하지 않는다. 매칭 성사 시 덱 스냅샷과 전장만 고정하고, 각 라운드 종료 시점에 해당 라운드 결과만 확정한다.
- 밴픽은 넣지 않는다.
- 전략성은 라운드별 전술 선택, 덱 구성, 전술 칩, 전장 규칙, 컵 제출 전략으로 만든다.
- 8인 컵은 랭크와 분리된 별도 모드로 제공한다.
- 관전은 실시간 상주 관전방이 아니라 완료된 매치/컵 리플레이 관전으로 시작한다.
- 관리자 페이지는 실시간 전체 집계가 아니라 스냅샷/배치 통계를 조회한다.

## 2. 5판 3선승 랭크 구조

5판 3선승은 전략성을 높이기 위한 핵심 변경이다.

기본값:

```text
MATCH_FORMAT = best_of_five
ROUNDS_TO_WIN = 3
MAX_ROUNDS_PER_MATCH = 5
TARGET_USER_FACING_MATCH_TIME = 7~12분
SERVER_SIMULATION_TARGET_P95 = 500ms 이하
SERVER_SIMULATION_HARD_TIMEOUT = 2초 이하
```

5판 3선승의 목적:

- 단판 운 요소를 줄인다.
- 덱 구성과 라운드별 대응 플랜의 의미를 키운다.
- 1라운드 패배 후 역전 전략을 가능하게 한다.
- 카운터 카드와 예비 카드의 가치를 만든다.
- 리플레이와 하이라이트가 상용 게임처럼 풍부해진다.

부하 제한:

- 최대 라운드 수는 5지만, 한쪽이 3승을 먼저 달성하면 남은 라운드는 계산하지 않는다.
- 라운드 시간 상한은 45초 권장으로 낮춘다.
- `MAX_ROUND_TICKS = 180`, `MAX_MATCH_TICKS = 900`을 기본 목표로 둔다.
- 상세 이벤트 로그는 상한을 초과하면 요약 이벤트로 압축한다.
- 5판 3선승으로 늘어난 계산량은 동시 시뮬레이션 워커 제한으로 제어한다.

## 3. 전략 요소 확장

### 3.1 덱과 출전 구조

권장 구조:

```text
덱 크기: 10장
라운드별 출전: 6장
예비 카드: 4장
라운드별 전술 플랜: 최대 5개
라운드별 직접 전술 선택: 최대 5회
전술 칩: 1개
전장 규칙: 매치당 1개
```

덱 10장/출전 6장 구조는 유저에게 아래 판단을 요구한다.

- 핵심 조합 6장 선택
- 특정 조합 대응용 예비 카드 선택
- 1~5라운드별 출전 카드 변경
- 후반 라운드용 안정 플랜 또는 역전 플랜 선택
- 직전 라운드 결과와 공개된 요약 정보를 보고 다음 라운드 전술 재선택

주의:

- 라운드 중 실시간 교체는 없다.
- 매칭 성사 후 라운드별 기본 선택 타이머를 둔다. 제한 시간 안에 입력하지 않은 쪽은 저장된 기본 플랜으로 자동 진행한다.
- 모든 플랜은 덱 저장 또는 큐 등록 전에 검증한다.
- 조건이 많은 자동 플랜은 제공하지 않는다. 유저가 매 라운드 전술을 직접 조정하는 흐름을 우선한다.

### 3.2 라운드별 직접 전술 선택

라운드별 직접 전술 선택은 밴픽 없이 전략성을 늘리는 핵심 장치다. 서버가 복잡한 조건식을 계속 평가하는 구조가 아니라, 각 라운드 사이에 유저가 다음 라운드 선택을 수정하고 라운드 종료 시점에 결과를 확정한다.

선택 가능한 항목:

```text
다음 라운드 출전 6장
배치 프리셋
타겟 우선순위
전술 성향
예비 카드 투입 여부
```

진행 기준:

- 각 라운드 종료 후 짧은 선택 타이머를 제공한다.
- 선택 시간 안에 입력하지 않으면 저장된 기본 플랜 또는 직전 유효 선택으로 자동 진행한다.
- 양쪽 입력이 모두 완료되면 즉시 다음 라운드를 계산한다.
- 한쪽이 탈주/잠수하더라도 상대는 대기 피로 없이 다음 라운드를 진행할 수 있어야 한다.
- 서버는 라운드별 선택 결과만 저장하고, 복잡한 자동 조건 평가 기록은 남기지 않는다.

금지:

- 상대의 비공개 상세 배치를 본 뒤 실시간 선택
- 라운드 사이 무제한 유저 입력 대기
- 상대 카드 하나를 지정해 금지하는 밴픽 형태
- 조건이 너무 복잡해 DB 조회나 긴 계산이 필요한 규칙
- 승패 확정 후 결과를 바꾸는 후처리

### 3.3 전술 칩

전술 칩은 모든 유저가 같은 풀에서 고르는 공용 전략 옵션이다. 치카포 본편 자산, 카드 가치, 방송 데이터와 연결하지 않는다.

운영 기준:

- 랭크 시즌당 8~12개만 활성화한다.
- 덱당 1개만 장착한다.
- 모든 전술 칩은 파워 예산에 포함한다.
- 전술 칩 승률은 관리자 통계에서 별도로 추적한다.
- 문제가 생기면 다음 밸런스 패치 또는 긴급 kill switch로 비활성화한다.

예시:

- 초반 압박: 1라운드 초반 공격 속도 소폭 증가, 후반 화력 감소
- 후열 보호: 후열 피해 감소, 전열 방어 소폭 감소
- 역전 설계: 직전 라운드 패배 후 다음 라운드 시작 에너지 소폭 증가
- 스킬 순환: 스킬 비용 소폭 감소, 기본 공격력 소폭 감소
- 광역 대응: 광역 피해 감소, 단일 피해 취약
- 암살 대응: 첫 후열 피해 감소, 전체 회복량 감소

### 3.4 전장 규칙

전장 규칙은 매치마다 적용되는 가벼운 시즌 룰이다.

운영 기준:

- 시즌당 3~5개만 활성화한다.
- 한 매치에는 1개만 적용한다.
- 전장 규칙은 양쪽에 동일하게 적용된다.
- 수치 효과는 작게 유지한다.
- 관리자 통계에서 전장 규칙별 승률/픽률/매치 길이를 추적한다.

예시:

- 좁은 전선: 전열 방어력 소폭 증가, 후열 사거리 보정 없음
- 긴 호흡: 30초 이후 회복량 감소, 후반 폭주 억제
- 불안정 에너지: 첫 스킬 발동이 빨라지지만 두 번째 스킬 비용 증가
- 보호막 약화: 보호막 효율 감소, 체력 회복 효율 소폭 증가
- 저격 경계: 후열 첫 피해 감소, 암살 태그 피해 소폭 감소

## 4. 8인 아레나 컵

8인 컵은 랭크 빠른대전과 분리된 별도 모드다.

목적:

- 여러 유저가 한 이벤트 안에서 1~8위를 경쟁하는 재미 제공
- 장시간 플레이 체감 제공
- 스트리머/커뮤니티 이벤트에 적합한 콘텐츠 제공
- 랭크와 다른 메타 실험 공간 제공

기본 구조:

```text
참가자: 8명
진행 방식: 3라운드 배치 브래킷 또는 스위스형 컵
개별 경기: 5판 3선승 또는 컵 전용 축약 3승 목표
총 경기 수: 12세트
체감 시간: 12~25분
점수: 컵 포인트, 이벤트 랭킹, 시즌 컵 기록
랭크 MMR: 기본 미반영
```

권장 첫 구현은 8인 배치 브래킷이다.

```text
라운드 1: 8강 4경기
라운드 2: 승자 4강 2경기 + 패자 순위전 2경기
라운드 3: 1/2위전, 3/4위전, 5/6위전, 7/8위전
총 12경기
```

전략 요소:

- 컵 참가 전 컵 전용 덱과 플랜 제출
- 컵 참가 전 라운드별 전술 플랜 제출
- 컵 전용 전술 칩 선택 가능
- 컵 전용 전장 규칙 공개
- 빠른대전은 라운드 종료 후 다음 라운드 전술을 제한 시간 안에 수정할 수 있다. 8인 컵은 서버 부하를 낮추기 위해 완료 리플레이 기반으로 제공하며, 실시간 상주 컵 룸은 MVP에서 제공하지 않는다.

부하 제한:

- 컵은 별도 큐와 별도 워커를 사용한다.
- 기본 컵 동시 처리 수는 0~1개로 시작한다.
- 서버 부하가 높으면 컵 생성과 봇 컵을 자동 중단한다.
- 컵 전체 상세 로그를 모두 저장하지 않는다.
- 참가자 본인 경기, 결승전, 하이라이트만 상세 로그 보존 대상이다.
- 나머지 컵 경기는 요약 결과와 핵심 이벤트만 저장한다.

랭킹 정책:

- 8인 컵 결과는 기본 랭크 MMR에 반영하지 않는다.
- 첫 구현은 `cup_points`와 1~8위 최종 순위를 브래킷 JSON에 저장한다.
- `cup_rating`, `weekly_cup_rank`는 별도 스냅샷/랭킹 확장으로 분리한다.
- 정식 시즌에서 컵 MMR을 만들 경우에도 1:1 랭크 MMR과 합치지 않는다.

## 5. 관전 기능

관전은 반드시 저부하 방식으로 시작한다.

MVP 관전 범위:

- 완료된 매치 리플레이 관전
- 완료된 컵 하이라이트 관전
- 관리자/대회 운영자가 선정한 공개 리플레이
- 참가자가 공유 허용한 매치 링크

금지:

- 실시간 tick 브로드캐스트 관전
- 관전자별 실시간 방 상태 저장
- 관전자 진행 위치를 서버에 매초 저장
- 공개 리플레이 썸네일을 매치마다 자동 생성
- 스트리머가 비활성화한 카드 이미지를 관전 리플레이에 계속 노출

권장 구현:

- `arena_spectator_links`에 공개 범위와 만료 시각 저장
- 관전 조회는 match summary와 압축/요약 로그만 사용
- 관전 API는 강한 rate limit과 캐시 헤더를 둔다.
- 컵 관전은 컵 종료 후 생성된 하이라이트 묶음으로 제공한다.
- 실시간 관전이 필요해지는 경우에도 전투 결과는 이미 확정된 리플레이 스트림으로 시작한다.

## 6. 관리자 페이지

아레나에는 별도 관리자 페이지를 둔다.

권장 탭:

- 운영 현황
- 매치/큐 관리
- 8인 컵 관리
- 관전/리플레이 관리
- 카드 사용 가능 상태 관리
- 클래스/스킬/태그 통계
- 전술 칩/전장 규칙 통계
- 밸런스 위험 조합
- 어뷰징 감사
- 시즌/랭킹 스냅샷
- kill switch
- 관리자 감사 로그

### 6.1 운영 현황

표시 항목:

- 현재 빠른대전 큐 수
- 컵 큐 수
- 평균 매칭 시간
- quick join p95
- status API p95
- 세트 시뮬레이션 p95/p99
- 컵 시뮬레이션 대기 수
- 리플레이 로그 저장량
- 리플레이 pruning 결과
- 랭킹 스냅샷 갱신 시각
- 통계 스냅샷 갱신 시각
- 현재 kill switch 상태

### 6.2 밸런스 통계

관리자는 다음 통계를 볼 수 있어야 한다.

- 유저별 승패, MMR, 최근 덱 요약
- 카드별 픽률/승률/평균 라운드 기여도
- 클래스별 픽률/승률/상대 클래스별 승률
- 스킬별 픽률/승률/발동 횟수/평균 효과량
- 패시브별 픽률/승률
- 스탯 프로필별 승률
- 태그 단계별 승률
- 2태그/3태그 조합 승률
- 전술 칩별 승률
- 전장 규칙별 승률
- 라운드별 전술 변경률과 변경 후 승률
- 5판 3선승 스코어 분포: 3:0, 3:1, 3:2
- 8인 컵 등수별 조합 분포

통계 노출 원칙:

- 표본 수가 작은 항목은 숨기거나 `표본 부족`으로 표시한다.
- 승률은 픽률, 표본 수, 신뢰 구간과 함께 보여준다.
- 실시간 DB 집계 쿼리를 관리자 화면 요청마다 실행하지 않는다.
- `arena_balance_stat_snapshots` 같은 스냅샷 테이블을 조회한다.
- 상세 분석은 운영자가 수동 배치로 실행한다.

### 6.3 관리자 인게임 관리

관리자는 다음 조작을 할 수 있다.

- 시즌 카드 사용 가능 상태 재검증
- 특정 카드 아레나 사용 제한
- 특정 클래스/스킬/태그 임시 비활성화
- 특정 전술 칩 비활성화
- 특정 전장 규칙 비활성화
- 8인 컵 생성 중단
- 관전 공개 중단
- 상세 리플레이 저장 중단
- 랭킹 스냅샷 재생성
- 통계 스냅샷 재생성
- 리플레이 로그 pruning

모든 관리자 조작은 감사 로그를 남긴다.

### 6.4 어뷰징 감사

관리자 페이지에는 `어뷰징 감사` 하위 탭을 둔다.

목표:

- 같은 계정끼리 반복 매칭되는 패턴을 빠르게 확인한다.
- 한쪽이 반복적으로 일방 승리/패배하는 패턴을 확인한다.
- 지나치게 짧은 전투 재생 시간과 3:0 스윕 반복을 함께 본다.
- 의심 계정에 대해 1일, 7일, 30일, 영구 제재를 바로 실행할 수 있게 한다.
- CSV/JSON 내보내기로 외부 분석과 패치 검토가 가능해야 한다.

저부하 원칙:

- 관리자 화면 요청마다 전체 `arena_matches`를 `GROUP BY` 하지 않는다.
- 최신 랭크 경기 제한 개수만 `ORDER BY id DESC LIMIT N`으로 읽는다.
- 기본 스캔 범위는 800경기, UI 선택지는 300/800/1500경기로 제한한다.
- 동일 요청은 짧은 TTL 캐시를 사용해 반복 클릭이 DB 부하로 이어지지 않게 한다.
- 점수화와 페어 분석은 서버 메모리에서 수행한다.

초기 점수화 항목:

- 동일 상대 반복 횟수
- 상위 상대 집중도
- 일방 승패 비율
- 짧은 전투 비율
- 3:0 스윕 비율
- 평균 전투 재생 시간

운영 원칙:

- 짧은 전투 시간 하나만으로 제재하지 않는다.
- 동일 상대 반복, 일방 승패, 짧은 전투가 함께 나타날 때 우선 검토한다.
- `high` 계정은 근거 경기와 리플레이 확인 후 7일 이상 제재를 검토한다.
- `medium` 계정은 1일 제재 또는 경고 후 다음 감사에서 재발 여부를 본다.
- 제재 사유에는 감사 점수와 주요 플래그를 기록한다.

고도화 후보:

- 계정 생성일, 마지막 접속, 제재 이력 결합
- IP/디바이스 해시 기반 계정군 탐지
- 큐 진입 간격과 동시 큐 패턴 분석
- 리플레이 이벤트 다양성, 라운드 전술 변경 여부 분석
- 보상 지급 전 자동 보류 플래그 연동

```text
admin_user_id
action_type
target_type
target_id
before_json
after_json
reason
created_at
```

## 7. 통계 저장 정책

매치 종료 시 매번 무거운 통계를 갱신하지 않는다.

허용:

- match summary에 필요한 통계 원천 데이터를 작게 저장
- 카드/클래스/스킬/태그 id 목록 저장
- 스코어, 승패, match_format, mode 저장
- 배치 작업이 읽을 수 있는 compact facts 저장

금지:

- 매치 종료마다 클래스별 전체 승률 update
- 매치 종료마다 스킬 조합 랭킹 update
- 관리자 화면 요청마다 `GROUP BY` 대량 집계
- 컵 전체 경기를 상세 로그로 모두 장기 저장

권장 스냅샷:

```text
arena_balance_stat_snapshots
arena_card_stat_snapshots
arena_class_stat_snapshots
arena_skill_stat_snapshots
arena_tag_combo_stat_snapshots
arena_tactic_stat_snapshots
arena_cup_stat_snapshots
```

갱신 주기:

- 일반 시간: 30~60분
- 피크 시간: 수동 또는 지연
- 밸런스 패치 전: 운영자가 수동 생성
- 시즌 종료: 최종 고정 스냅샷 생성

## 8. 반드시 지켜야 할 결정 사항

1. 기본 랭크 매치는 5판 3선승이다.
2. 밴픽은 넣지 않는다.
3. 전략성은 사전 저장된 플랜과 공용 전략 옵션으로 만든다.
4. 8인 컵은 1:1 랭크와 분리된 별도 모드다.
5. 관전은 완료된 리플레이/하이라이트 관전으로 시작한다.
6. 실시간 상주 매치룸과 tick 브로드캐스트 관전은 금지한다.
7. 관리자 통계는 스냅샷/배치 기반으로 조회한다.
8. 관리자 화면 요청이 대량 집계 쿼리를 직접 실행하면 안 된다.
9. 컵과 관전은 서버 부하가 높으면 kill switch로 즉시 줄일 수 있어야 한다.
10. 모든 관리자 조작은 감사 로그를 남긴다.

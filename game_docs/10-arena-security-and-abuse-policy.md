# 치카포 아레나 보안 및 어뷰징 방지 정책

## 1. 목적

이 문서는 치카포 아레나의 랭크 공정성, 매칭 무결성, MMR 보호, 리플레이/덱 데이터 보호, 스트리머 설정 권한 보호, 관리자 감사 정책을 정의한다.

아레나는 경쟁 모드와 시즌 보상을 가진 서비스이므로 반드시 악용을 전제로 설계해야 한다.

주요 위협:

- 큐 저격
- 다계정 어뷰징
- 져주기
- MMR 조작
- 봇전 보상 파밍
- 덱/전투 결과 위조
- 리플레이 데이터 남용
- 스트리머 카드 설정 권한 탈취
- 관리자 기능 오남용

## 2. 보안 기본 원칙

1. 클라이언트는 전투 결과를 제출하지 않는다.
2. 전투 결과는 서버 deterministic simulation만 신뢰한다.
3. 덱, 배치, 라운드 플랜은 서버에서 검증한다.
4. MMR 변경은 match result 저장과 원자적으로 처리한다.
5. 랭킹은 DB snapshot 기반으로 제공한다.
6. 스트리머 설정은 본인 확인 후에만 가능하다.
7. 관리자 액션은 감사 로그를 남긴다.
8. 모든 보상 지급은 어뷰징 검증 후 처리한다.

## 3. 클라이언트 신뢰 경계

클라이언트가 보낼 수 있는 것:

- 덱 저장 요청
- 라운드별 전술 플랜
- 빠른대전 큐 등록
- 봇전 시작 요청
- 리플레이 조회 요청
- 스트리머 카드 설정 요청

클라이언트가 보내도 신뢰하면 안 되는 것:

- 전투 승패
- 피해량
- 스킬 발동 결과
- MMR 변화량
- 보상 수령 조건 충족 여부
- 카드 능력 정보
- 상대 매칭 결과

서버는 모든 핵심 결과를 직접 계산해야 한다.

## 4. 매칭 어뷰징

### 4.1 큐 저격

큐 저격은 특정 유저와 의도적으로 매칭되기 위해 동시에 큐를 넣는 행위다.

탐지 지표:

- 같은 두 유저의 반복 매칭 횟수
- 짧은 시간 내 반복 매칭
- 특정 시간대 반복
- MMR 차이가 큰데 반복 매칭
- 한쪽이 비정상적으로 계속 패배

대응:

- 최근 N분 내 같은 상대 재매칭 제한
- 같은 상대 연속 매칭 제한
- 대기 시간이 짧은 상황에서는 같은 상대 회피
- 상위 랭크 구간에서는 반복 매칭 허용치를 별도로 조정

권장 초기값:

```text
same_opponent_cooldown_minutes = 10
max_same_opponent_matches_per_hour = 3
```

상위 랭커처럼 인구가 적은 구간은 예외가 필요할 수 있다.

### 4.2 져주기

져주기는 한 계정이 다른 계정의 MMR을 올리기 위해 의도적으로 패배하는 행위다.

탐지 지표:

- 같은 상대에게 반복 패배
- 3:0 패배 반복
- 매우 짧은 매치 반복
- 덱이 비정상적으로 약함
- 라운드 플랜이 비어 있거나 의도적으로 불리함
- 특정 계정군 간 점수 이전 패턴

대응:

- 의심 매치 MMR 반영 보류
- 보상 지급 보류
- 관리자 검토
- 반복 시 랭크 제한

관리자 감사 화면:

- 최신 랭크 경기 제한 스캔으로 동일 상대 반복, 일방 승패, 짧은 전투, 3:0 스윕을 함께 점수화한다.
- 감사 결과는 `watch`, `low`, `medium`, `high` 위험도로 표시한다.
- 제재는 1일, 7일, 30일, 영구 중 선택하되 단일 지표만으로 실행하지 않는다.
- 감사 CSV/JSON은 의심 계정, 페어, 근거 경기 ID, 주요 플래그를 포함한다.

### 4.3 다계정 어뷰징

탐지 지표:

- 동일 IP/디바이스/세션 패턴
- 같은 상대 반복
- 생성 직후 랭크 몰아주기
- 비슷한 닉네임/행동 패턴
- 특정 계정으로 점수 집중

대응:

- 직접 차단보다 의심 점수 누적
- 보상 지급 전 검증
- 고위 랭킹 보상 수동 검토
- 계정 상호작용 제한 정책과 연동

### 4.4 이탈 및 큐 회피 악용

아레나 빠른대전은 매칭 확정 후 덱/시드가 고정되고 라운드별 기본 선택 타이머가 적용되므로, 전투 중 브라우저 종료나 네트워크 단절로 패배를 회피할 수 없어야 한다.

정책:

- 매칭 확정 이후 이탈은 매치 결과를 취소하지 않는다.
- 매칭 확정 이후 미시청, 리플레이 중 나가기, 결과 화면 미확인은 패널티 대상이 아니다.
- 큐 대기 중 취소와 TTL 만료는 본인 큐 엔트리만 정리하며 상대에게 영향을 주지 않는다.
- 반복 큐 취소, 반복 TTL 만료, 매칭 직전 회피 패턴만 어뷰징 신호로 본다.

탐지 지표:

- 짧은 시간 내 큐 취소 횟수
- 큐 등록 후 만료까지 방치하는 비율
- 특정 MMR 구간 또는 특정 시간대에서만 반복 취소
- 같은 상대 후보가 잡히는 구간에서 반복 취소

대응:

- 1단계: 10~30초 재큐 쿨다운
- 2단계: 몇 분 단위 랭크 큐 제한
- 3단계: 어뷰징 의심 플래그와 관리자 검토

주의:

- 연결 불안정 유저를 과도하게 처벌하지 않기 위해 단발성 이탈은 무시한다.
- 큐 악용 패널티는 MMR 직접 차감보다 재큐 제한을 우선한다.
- 매칭 확정 후 결과가 저장된 매치는 이탈 여부와 관계없이 정상 매치로 남긴다.
## 5. MMR 조작 방지

### 5.1 원자적 반영

랭크 match result와 rating update는 같은 트랜잭션으로 처리한다.

필수:

- match id 기준 중복 반영 방지
- winner/loser rating 동시 갱신
- 실패 시 둘 다 rollback
- 봇전은 rating update 경로에 들어가지 않음

### 5.2 비정상 매치 제외

MMR에 반영하지 않을 수 있는 매치:

- 서버 오류로 결과가 불완전한 매치
- 덱 검증 오류가 뒤늦게 발견된 매치
- 전투 로그/summary 불일치
- 어뷰징 의심으로 보류된 매치
- 시즌 종료 이후 완료된 매치

### 5.3 배치 경기 보호

배치 경기 구간은 조작에 취약하다.

권장:

- 배치 경기 수: 5~10세트
- 배치 중 같은 상대 반복 제한 강화
- 배치 중 MMR 변동폭은 크지만 랭킹 노출은 제한
- 배치 완료 전 상위 랭킹 진입 불가

## 6. 덱/카드 위조 방지

검증 항목:

- 덱 소유자 확인
- 전체 활성 카드 사용 가능 여부
- 비활성 카드 제외
- 같은 스트리머 중복 금지
- 출전 카드 수 상한
- 라운드별 보드 좌표
- 카드 능력 버전
- 스킬/태그 정의 버전

전투 시점에는 덱을 snapshot으로 복사한다. 이후 유저가 덱을 수정해도 이미 생성된 match에는 영향을 주지 않는다.

## 7. 전투 결과 위조 방지

전투 결과는 클라이언트가 제출하지 않는다.

서버 저장:

- match_seed
- round_seed
- 덱 스냅샷
- 라운드 플랜 스냅샷
- 결과 요약
- 상세 로그

검증:

- result summary와 battle log의 round result 일치
- rating delta와 match result 일치
- replay 만료 후에도 summary는 남김

## 8. 봇전 악용 방지

봇전은 MMR에 반영하지 않는다.

위험:

- 보상 파밍
- 전투 시뮬레이션 API 부하 유발
- 리플레이 저장 공간 낭비

대응:

- 봇전 rate limit
- 봇전 보상 제한
- 봇전 리플레이 짧은 보존 또는 미저장
- 같은 덱 반복 봇전 제한 가능

권장:

```text
bot_practice_limit = 10회 / 10분 / user
bot_reward_limit = 일일 첫 완료
bot_replay_retention = 0~3일
```

## 9. 리플레이 및 정보 공개

### 9.1 리플레이 접근 정책

선택 가능한 정책:

- 기본 비공개: 참가자만 조회
- 랭킹 상위권 공개
- 유저가 공유 링크 생성 시 공개
- 대회/이벤트 매치 공개

MVP 권장:

```text
기본: 참가자만 조회
공유: 공개 목록 노출은 제공하지 않으며, 참가자가 생성한 만료 토큰 링크 방식만 허용한다.
상위권 공개: 운영 안정화 후
```

### 9.2 숨겨야 할 정보

리플레이에서 숨길 수 있는 정보:

- 내부 RNG seed 원문
- 서버 내부 validation 결과
- 비공개 MMR
- 어뷰징 탐지 점수

공개 가능한 정보:

- 덱 스냅샷
- 라운드 결과
- 전투 이벤트
- 카드별 기여도

## 10. 스트리머 카드 설정 권한 보호

### 10.1 본인 확인

스트리머 카드 설정은 해당 스트리머 본인만 할 수 있다.

검증:

- 치카포 OAuth 계정
- user id와 channel id 매핑
- 토큰 유효성
- 관리자 강제 비활성 상태 여부

### 10.2 민감 액션

민감 액션:

- 카드 설정 요청
- opt-out
- opt-in
- 플레이버 텍스트 변경

권장:

- 재확인 모달
- 최근 변경 이력 표시
- 변경 후 알림
- 관리자 감사 로그

### 10.3 권한 탈취 대응

의심 상황:

- 갑작스러운 opt-out
- 반복 설정 변경
- 평소와 다른 세션/IP에서 민감 액션
- 신고된 플레이버 텍스트

대응:

- 설정 반영 지연
- 관리자 검토
- 스트리머에게 알림
- 이전 설정 복구 가능성 확보

## 11. 관리자 보안

### 11.1 관리자 액션 감사 로그

감사 로그 대상:

- 카드 비활성화/활성화
- 스트리머 설정 승인/거절
- 시즌 생성/종료
- 카드 풀 재생성
- 랭킹 스냅샷 재생성
- 리플레이 로그 강제 삭제
- 보상 지급/회수
- 문제 스킬 비활성화

로그 필드:

```text
admin_user_id
action_type
target_type
target_id
before_json
after_json
reason
created_at
```

### 11.2 관리자 기능 보호

필수:

- ADMIN 권한 확인
- CSRF 보호
- rate limit
- 중요한 액션 confirm
- destructive action reason 필수

## 12. 신고 및 제재

신고 대상:

- 부적절한 카드 플레이버 텍스트
- 닉네임/프로필 악용
- 어뷰징 의심
- 비정상 랭킹
- 리플레이 악용

제재:

- 경고
- 아레나 랭크 제한
- 시즌 보상 제외
- MMR 롤백
- 계정 제재
- 스트리머 카드 설정 일시 중지

제재는 본편 계정 제재 정책과 충돌하지 않도록 별도 reason을 기록한다.

## 13. 보상 지급 전 검증

시즌 보상 지급 전 검증:

- 최소 매치 수
- 어뷰징 의심 점수
- 같은 상대 반복 비율
- 제재 이력
- 비정상 승률
- 시즌 종료 직전 비정상 점수 상승

의심 계정은 자동 지급하지 않고 수동 검토로 보낸다.

## 14. 모니터링 지표

보안/어뷰징 대시보드:

- 같은 상대 반복 매칭 상위 계정
- 3:0 반복 패배 패턴
- 비정상 승률 계정
- 짧은 시간 MMR 급등 계정
- 봇전 요청량 상위 계정
- 리플레이 조회량 상위 계정/IP
- opt-out/opt-in 반복 계정
- 관리자 액션 로그

## 15. Rate Limit 정책

권장:

```text
quick join: 유저당 10초 1회
matchmaking-status: 30회/분/user
cancel-queue: 10회/분/user
bot-practice: 10회/10분/user
deck-save: 30회/10분/user
deck-validate: 30회/분/user
replay-read: 60회/분/user
ranking-read: 60회/분/IP
streamer-config-request: 10회/일/channel
opt-out/in: 5회/일/channel
admin-sensitive-action: 30회/10분/admin
```

## 16. 데이터 보존

보존 권장:

- match summary: 시즌 후 장기 보존 가능
- battle log: 7~14일
- 봇전 battle log: 0~3일
- abuse signal: 최소 시즌 종료 후 90일
- admin audit log: 장기 보존
- reward claim log: 장기 보존

## 17. MVP 범위

MVP 필수:

- 서버 전투 결과만 신뢰
- 덱/카드/플랜 검증
- MMR 원자 반영
- 봇전 MMR 제외
- 큐 반복 매칭 기본 제한
- rate limit
- 스트리머 opt-out 권한 검증
- 관리자 감사 로그 기본형
- 시즌 보상 지급 전 수동 검토 가능성

MVP 이후:

- 고급 어뷰징 점수
- 자동 MMR 롤백
- 리플레이 공개/공유 정책
- 고급 다계정 탐지
- 관리자 보안 대시보드 고도화

## 18. 반드시 지켜야 할 결정 사항

1. 클라이언트 전투 결과는 절대 신뢰하지 않는다.
2. MMR은 match result와 원자적으로 반영한다.
3. 봇전은 MMR과 랭킹에 반영하지 않는다.
4. 큐 저격과 같은 상대 반복 매칭을 감시한다.
5. 스트리머 카드 설정과 opt-out은 본인 확인 후에만 가능하다.
6. 관리자 민감 액션은 감사 로그를 남긴다.
7. 시즌 보상은 어뷰징 검증 후 지급한다.
8. rate limit 없이 전투 시뮬레이션 API를 열지 않는다.

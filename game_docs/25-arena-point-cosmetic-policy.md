# 치카포 아레나 포인트 코스메틱 정책

## 1. 목적

이 문서는 치카포 아레나 안에서 포인트를 사용할 수 있는 항목과 구현 범위를 정의한다.

포인트 사용처는 반드시 아레나 내부에서 구매, 확인, 장착할 수 있어야 한다. 단, 포인트 사용은 전투력, 스탯, 클래스, 스킬, 매칭, MMR, 랭킹, 보상량에 영향을 주지 않는다.

## 2. 절대 원칙

- 포인트는 전투 결과에 영향을 주지 않는다.
- 포인트는 카드 능력 재설정, 클래스 선택, 스킬 선택, 스탯 변경에 쓰지 않는다.
- 포인트는 매칭 우선권, 랭킹 보호권, 패배 무효권, 보상 증가권에 쓰지 않는다.
- 포인트 상품은 아레나 화면 안에서 명확하게 외형으로 표현한다.
- 구매/장착 UI는 강화, 등급 상승, 성능, 승률 같은 표현을 사용하지 않는다.
- 아레나 코스메틱 장착 정보는 전투 시뮬레이션 입력으로 전달하지 않는다.

## 3. MVP 구현 범위

| 항목 | 구현 위치 | 서버 영향 | P2W 위험 |
| --- | --- | --- | --- |
| 아레나 스타일 상점 | 아레나 탭 내부 | 기존 상점 조회 재사용 | 낮음 |
| 아레나 아이템 구매 | `/api/arena/cosmetics/buy` | 기존 포인트 원장/상점 구매 재사용 | 낮음 |
| 보유 수량 확인 | `/api/arena/cosmetics/inventory-counts` | 기존 보유 코스메틱 수량 조회 재사용 | 낮음 |
| 구매 제한 확인 | `/api/arena/cosmetics/purchases` | 기존 구매 횟수 조회 재사용 | 낮음 |
| 아레나 장착 상태 | `/api/arena/cosmetics/loadout` | 아레나 전용 1 row 저장 | 낮음 |
| 배틀 이모트 표시 | `/arena/realtime` WebSocket | 메모리 룸 브로드캐스트, DB 저장 없음 | 낮음 |

아레나 장착 상태는 `arena_user_cosmetic_loadouts`에 저장한다.

```text
user_id
border_item_id
name_effect_item_id
emote_slot_1_item_id
emote_slot_2_item_id
emote_slot_3_item_id
emote_slot_4_item_id
updated_at
```

## 4. 허용 상품

구현 허용:

- 프로필 프레임
- 이름 연출
- 배틀 이모트

확장 후보:

- 전투 입장 연출
- 승리 화면 명패
- 리플레이 공유 프레임
- 8인 컵 대진표 스킨
- 시즌 기념 배지

확장 후보도 전투 판단, 타겟팅, 시야, 정보량, 전투 속도에 영향을 주면 안 된다.

## 4.1 배틀 이모트 상세

배틀 이모트는 아레나에서 구매하고, 아레나 스타일 탭에서 4개 슬롯에 장착한다.

상품 데이터:

```json
{
  "type": "emote",
  "style_json": {
    "image_url": "https://...",
    "emoji": "✨",
    "class": "ae-pop",
    "css": ".ae-pop { animation: ae-pop .9s ease both; }"
  }
}
```

표시 규칙:

- 게임/리플레이 화면에서 우클릭하면 장착한 이모트 파이 메뉴를 연다.
- 파이 메뉴는 X자 분할로 상/우/하/좌 4방향을 고정 제공한다.
- `emote_slot_1_item_id`는 상, `emote_slot_2_item_id`는 우, `emote_slot_3_item_id`는 하, `emote_slot_4_item_id`는 좌 방향이다.
- 아레나 스타일 탭에는 실제 파이 메뉴 모양의 편집 미리보기를 제공해 어디에 장착되었는지 직관적으로 보여준다.
- 이모트를 선택하면 같은 매치 화면에 접속 중인 사용자에게 즉시 표시한다.
- 서버는 이미 확정된 라운드 결과와 리플레이를 바꾸지 않는다.
- 이모트는 DB, 리플레이 로그, 랭킹, 관리자 전투 통계에 저장하지 않는다.
- 이모트 전송은 사용자별 짧은 쿨다운을 적용한다.
- 소켓이 끊겨도 매치 결과, 보상, MMR, 리플레이 조회에는 영향이 없다.

관리자 업로드:

- 관리자는 아레나 관리자/상점 관리 화면에서 `emote` 타입 상품을 만들 수 있다.
- JPG, PNG, WebP, AVIF, GIF 이미지를 업로드할 수 있다.
- GIF는 움짤 보존을 위해 원본 파일을 저장한다.
- 업로드된 파일 URL은 상품 `style_json.image_url`에 연결한다.
- 업로드 파일은 코스메틱 표시용이며 전투 시뮬레이션 입력으로 전달하지 않는다.

실시간처럼 보이는 전투 경험은 클라이언트 리플레이 재생과 이모트 오버레이가 담당한다. 서버 판정은 라운드 커밋 시점에 해당 라운드만 확정하며, 이모트는 전투 판정과 분리된 외형 이벤트로만 처리한다.

## 5. 구매/장착 UX

아레나 내부에서 제공해야 하는 상태:

- 판매 중인 아레나 스타일 아이템
- 보유 수량
- 구매 횟수
- 현재 장착 여부
- 이모트 슬롯 1~4의 장착 상태
- 구매 가능/불가 사유
- 포인트 잔액
- 장착 미리보기
- 공정성 고지

상품이 없으면 목업 상품을 표시하지 않는다. 빈 상태를 표시한다.

## 6. 부하 기준

- 스타일 상점 데이터는 사용자가 아레나 스타일 탭을 열었을 때만 조회한다.
- 조회 API는 읽기 전용이며 전투/매칭 API와 분리한다.
- 구매는 기존 상점 구매 트랜잭션을 재사용한다.
- 장착은 사용자당 1 row upsert만 수행한다.
- 이모트 사용은 DB write 없이 WebSocket 메모리 룸에만 브로드캐스트한다.
- 이모트 장착 검증은 짧은 TTL 캐시를 허용한다.
- 장착 상태는 매치 생성, 전투 시뮬레이션, 랭킹 스냅샷에 포함하지 않는다.

## 7. 금지 항목

- 카드 능력 변경권
- 클래스 변경권
- 스킬 선택권
- 스탯 분배권
- 전술 칩 구매권
- 덱 저장 슬롯 유료화
- 상세 통계 유료화
- 상대 분석 유료화
- 매칭 우선권
- 랭킹 보호권
- 패배 무효권
- 보상 증가권

덱 저장 슬롯, 상세 통계, 상대 분석은 편의 기능처럼 보여도 경쟁 승률에 영향을 줄 수 있으므로 포인트 상품으로 만들지 않는다.

## 8. 출시 판정

- 아레나에서 구매가 가능하다.
- 아레나에서 보유 수량이 보인다.
- 아레나에서 장착/해제가 가능하다.
- 구매 실패 시 포인트 표시가 복구된다.
- 장착 API가 보유하지 않은 아이템을 거절한다.
- 같은 이모트를 여러 슬롯에 중복 장착하지 못한다.
- 장착하지 않은 이모트는 WebSocket 전송에서 거절된다.
- 이모트 WebSocket 이벤트가 DB write를 발생시키지 않는다.
- 장착 상태가 전투 API 입력에 포함되지 않는다.
- 빈 상품/빈 보유 상태가 목업 없이 표시된다.

## 1. 재구현 원칙

### 1.1. 기존 시스템 폐기

현재 구현된 아레나의 다음 요소는 새 규칙과 호환하지 않는다.

- 5판 3선승 세트 매치
- 2행 x 4열 보드
- 라운드별 6장 출전 플랜
- tick 기반 자동 전투
- `hp/attack/defense/speed/focus` 스탯 체계
- 액티브/패시브/궁극기 스킬 슬롯
- 전술칩, 경기장 규칙, 시너지 태그
- 기존 아레나 덱, 매치, 리플레이, 랭킹 데이터

따라서 새 아레나는 기존 아레나의 데이터와 API 계약을 마이그레이션하지 않는다. 기존 데이터는 운영 배포 전 백업 후 폐기한다.

### 1.2. 새 게임 정체성

치카포 아레나는 스트리머 카드를 사용해 6칸 필드에서 싸우는 동시 배치형 카드 오토배틀 게임이다.

플레이어는 14~20장의 덱을 구성하고, 매 턴 40초 안에 손패 카드를 배치하거나 기존 필드를 조정한다. 양쪽 플레이어가 행동을 확정하면 필드가 공개되고, 카드들이 같은 라인을 기준으로 자동 전투한다.

### 1.3. 전면 구현 범위

첫 정식 재구현 릴리스에는 다음을 모두 포함한다.

- 봇전
- 빠른대전
- 8인 대전
- 덱 생성/검증
- 멀리건
- 손패/드로우/피로
- 6칸 필드 배치
- 전술 이동
- 교체
- 전투 판정
- 키워드 판정
- 카드 제작 검증기
- 스트리머 카드 직접 설정
- 카드 버전 관리
- 리플레이 로그
- 랭킹/MMR
- 관리자 kill switch와 진단 도구

## 3. 지원 모드

### 3.1. 봇전

봇전은 알고리즘 기반 봇과 대전하는 1:1 모드다. LLM은 사용하지 않는다.

| 항목 | 규칙 |
|---|---|
| 플레이어 체력 | 30 |
| 턴 제한 시간 | 40초 |
| 승리 조건 | 빠른대전과 동일 |
| 보상/MMR | MMR 미반영, 학습/연습용 보상만 지급 가능 |
| 룰 엔진 | 빠른대전과 동일 |

#### 봇 난이도

| 난이도 | 특징 |
|---|---|
| 입문 | 무작위 배치 비중이 높고, 명백한 손해만 피한다. |
| 쉬움 | 카드 스탯과 빈 라인 위주로 배치한다. |
| 보통 | 라인별 전열/후열 구조와 직접 공격 위험을 계산한다. |
| 어려움 | 다음 턴 코스트, 교체, 전술 이동 가능성까지 고려한다. |
| 전문가 | 상대 덱 성향, 손패 가능성, 후반 피니셔 위험까지 일부 추정한다. |

#### 봇 성향

| 성향 | 설명 |
|---|---|
| 어그로형 | 빈 라인 직접 공격과 전열 돌파를 우선한다. |
| 수비형 | 전열을 채우고 체력 손실을 줄이는 선택을 선호한다. |
| 저격형 | 후열 카드와 조준 계열 키워드를 선호한다. |
| 기만형 | 약화, 침묵, 위치 교란 키워드를 선호한다. |
| 망령형 | 묘지, 전투불능, 손실 보상 계열 키워드를 선호한다. |
| 균형형 | 라인별 점수와 체력 상황을 균형 있게 본다. |

### 3.2. 빠른대전

빠른대전은 1:1 온라인 대전 모드다.

| 항목 | 규칙 |
|---|---|
| 대전 방식 | 1:1 |
| 기본 체력 | 30 |
| 턴 제한 시간 | 매 턴 40초 |
| 조기 진행 | 양쪽 모두 배치 완료 시 즉시 전투 진행 |
| 승리 조건 | 상대 체력 0 이하 또는 9턴 종료 후 체력 우위 |
| 무승부 처리 | 서든데스 |
| 매칭 방식 | MMR 기반 |
| 서버 권위 | 필수 |
| 재접속 | 제한 시간 안에 복귀 가능 |
| 시간 초과 | 현재 서버에 저장된 임시 행동으로 진행, 아무 행동도 없으면 패스 |

### 3.3. 8인 대전

8인 대전은 8명이 참가하고 매 라운드 1:1 전투를 반복하는 배틀로얄 모드다.

| 항목 | 규칙 |
|---|---|
| 참가자 수 | 8명 |
| 기본 체력 | 30 |
| 라운드 제한 | 없음 |
| 코스트 | 1라운드 1코스트에서 시작해 9코스트까지 증가, 이후 9코스트 고정 |
| 전투 방식 | 각 라운드마다 1:1 자동 전투 |
| 탈락 조건 | 체력 0 이하 |
| 승리 조건 | 마지막 생존자 |
| 랜덤 경기장 | 사용하지 않음 |
| 패배 보정 | 패배자는 다음 라운드 첫 전술 이동 비용 0 |

## 5. 필드 구조

각 플레이어는 2행 3열의 필드를 가진다.

```text
후열 좌 | 후열 중 | 후열 우
전열 좌 | 전열 중 | 전열 우
```

각 세로 줄을 하나의 라인으로 본다.

```text
좌 라인: 전열 좌 + 후열 좌
중 라인: 전열 중 + 후열 중
우 라인: 전열 우 + 후열 우
```

### 5.1. 칸 제한

- 한 칸에는 카드 1장만 존재할 수 있다.
- 기본적으로 카드는 자신의 필드에만 배치한다.
- 상대 필드에 직접 배치할 수 없다.
- 기존 카드가 있는 칸에는 교체 행동으로만 새 카드를 놓을 수 있다.
- 전술 이동은 빈 칸으로만 가능하다.

### 5.2. 라인 제한 키워드

다음 키워드는 전부 같은 라인 안에서만 작동한다.

- 도발
- 조준
- 밀치기
- 끌어오기

이 키워드들은 다른 라인의 카드나 플레이어에게 영향을 주지 않는다.

## 6. 덱과 손패

### 6.1. 덱 구성

| 항목 | 값 |
|---|---:|
| 최소 덱 크기 | 14장 |
| 최대 덱 크기 | 20장 |
| 동일 스트리머 카드 | 덱당 최대 1장 |
| 동일 카드 버전 | 덱당 최대 1장 |
| 8~9코스트 제한 | 별도 장수 제한 없음 |

덱 크기를 14장으로 줄이면 원하는 카드를 더 빨리 뽑을 수 있지만, 덱 소진에 따른 피로 피해 위험이 커진다.

### 6.2. 시작 손패와 멀리건

- 게임 시작 시 각 플레이어는 카드 5장을 드로우한다.
- 1턴 시작 시 추가 드로우는 없다.
- 2턴부터 턴 시작 시 카드 1장을 드로우한다.
- 시작 손패 5장 중 최대 3장을 선택해 교체할 수 있다.
- 멀리건으로 교체한 카드는 덱으로 돌아가고, 덱을 섞은 뒤 같은 수만큼 다시 드로우한다.
- 멀리건은 1회만 가능하다.

### 6.3. 손패 최대 크기와 초과 처리

손패 최대 크기는 8장이다.

드로우는 1장씩 순서대로 처리한다.

```text
1. 드로우를 시도한다.
2. 덱에 카드가 있으면 덱 맨 위 카드를 확인한다.
3. 손패가 8장 미만이면 손패에 넣는다.
4. 손패가 이미 8장이면 해당 드로우 카드는 손패에 들어가지 않고 묘지로 간다.
5. 손패 초과로 묘지에 간 카드는 전투불능이 아니며 전투불능 효과를 발동하지 않는다.
```

덱이 비어 있으면 손패 크기와 무관하게 피로 피해를 받는다.

## 8. 배치 단계

### 8.1. 배치

플레이어는 손패의 카드를 자신의 필드 빈 칸에 배치할 수 있다.

- 카드 코스트만큼 코스트를 소비한다.
- 한 턴에 여러 장 배치할 수 있다.
- 배치 확정 전에는 UI에서 자유롭게 위치를 수정할 수 있다.
- 서버에 제출된 최종 행동만 실제 행동으로 처리된다.

### 8.2. 전술 이동

전술 이동은 이전 턴부터 필드에 있던 내 카드 1장을 빈 칸으로 옮기는 행동이다.

| 항목 | 규칙 |
|---|---|
| 기본 비용 | 1코스트 |
| 사용 횟수 | 턴당 1회 |
| 대상 | 이전 턴부터 필드에 있던 내 카드 |
| 목적지 | 빈 칸 |
| 체력 피해 | 유지 |
| 일시 효과 | 전투 종료 시 제거되어 이동에 영향 없음 |

8인 대전에서 패배한 플레이어는 다음 배치 단계의 첫 전술 이동 비용이 0코스트가 된다. 전술 이동 횟수 제한은 그대로 턴당 1회다.

### 8.3. 교체

교체는 기존 필드 카드가 있는 칸에 새 카드를 배치하는 행동이다.

| 항목 | 규칙 |
|---|---|
| 비용 | 새 카드 코스트만큼 |
| 기존 카드 | 묘지로 이동 |
| 새 카드 | 해당 칸에 배치 |
| 전투불능 효과 | 교체로 묘지에 간 카드는 발동하지 않음 |

교체는 메리트 행동이 아니라 기존 카드를 잃고 새 카드를 넣는 전술적 손실 행동이다.

### 8.4. 행동 처리 순서

서버는 각 플레이어의 배치 단계 행동을 다음 순서로 검증하고 적용한다.

```text
1. 시작 필드 스냅샷 확정
2. 전술 이동 검증 및 적용
3. 신규 카드 배치 검증 및 적용
4. 교체 검증 및 적용
5. 최종 필드 확정
```

세부 규칙:

- 전술 이동 대상 카드는 시작 필드에 있어야 한다.
- 전술 이동 목적지는 시작 필드 기준 빈 칸이어야 한다.
- 전술 이동으로 비워진 칸에는 이번 턴 새 카드를 배치할 수 있다.
- 이번 턴 새로 배치한 카드는 같은 턴에 전술 이동할 수 없다.
- 이번 턴 새로 배치한 카드는 같은 턴에 교체 대상이 될 수 없다.
- 같은 칸에 두 개 이상의 신규 배치를 할 수 없다.

---

## 9. 전투 규칙

### 9.1. 공격 가능 범위

카드는 기본적으로 같은 라인만 공격할 수 있다.

기본 타겟 우선순위:

```text
상대 전열 카드 -> 상대 후열 카드 -> 상대 플레이어
```

같은 라인의 상대 전열 카드가 있으면 기본 공격으로 후열이나 플레이어를 공격할 수 없다.

### 9.2. 전투 순서

```text
1. 전투 시작 효과 처리
2. 전열 공격 그룹 확정
3. 전열 카드들이 동시에 기본 공격
4. 전열 피해 처리
5. 전투불능 대체 효과 처리
6. 전투불능 카드 묘지 이동 및 사망 트리거 처리
7. 후열 공격 그룹 확정
8. 후열 카드들이 동시에 기본 공격
9. 후열 피해 처리
10. 전투불능 대체 효과 처리
11. 전투불능 카드 묘지 이동 및 사망 트리거 처리
12. 전투 종료 효과 처리
13. 일시 효과 제거
```

전열 공격 단계에서 전투불능이 된 카드는 이후 행동하지 않는다. 후열 카드가 전열 공격 단계의 초과 피해나 관통 피해로 전투불능이 되면 후열 공격을 하지 못한다.

### 9.3. 동시 공격

같은 공격 단계에 속한 카드들은 동시에 공격한다.

공격 그룹이 확정되면 해당 그룹의 공격자는 같은 단계 안에서 받은 피해와 무관하게 자기 공격을 수행한다. 단, 공격 그룹 확정 전에 이미 전투불능 상태가 된 카드는 공격 그룹에 포함되지 않는다.

---

## 10. 피해 규칙

### 10.1. 기본 피해

기본 공격 피해는 카드의 공격력에 의해 결정된다.

공격력 0인 카드도 기본 공격은 수행하지만, 실제 피해가 0이면 "피해를 줬을 때" 효과는 발동하지 않는다.

### 10.2. 피해 계산 순서

카드가 피해를 줄 때는 다음 순서로 처리한다.

```text
1. 기본 피해 결정
2. 피해 증가/감소 효과 적용
3. 보호막으로 피해 흡수
4. 실제 체력 피해 확정
5. 체력 피해 감소 패시브 적용
6. 지원 패시브의 피해 분담 처리
7. 남은 체력 피해 적용
8. 전투불능 여부 확인
```

### 10.3. 보호막

- 보호막은 전투 중 피해를 대신 흡수한다.
- 보호막은 체력 회복이 아니다.
- 보호막은 전투가 끝나면 사라진다.
- 보호막은 같은 전투 안에서는 합산된다.

### 10.4. 체력 피해 유지

카드가 받은 체력 피해는 필드에 남아 있는 동안 계속 유지된다.

필드를 벗어나 묘지로 간 카드는 일반적으로 다시 사용할 수 없다. 묘지 회수 키워드로 손패에 돌아온 카드는 최대 체력 상태로 손패에 들어온다.

---

## 11. 초과 피해, 관통, 직접 공격

### 11.1. 기본 초과 피해

전열 카드가 기본 공격으로 전투불능이 되고 피해가 남으면, 같은 라인의 후열 카드에게 남은 피해의 절반을 준다. 소수점은 버린다.

이 피해는 상대 플레이어에게 전달되지 않는다.

### 11.2. 관통

관통 키워드가 있으면 초과 피해의 절반이 아니라 전부를 같은 라인의 후열 카드에게 준다.

관통 피해도 상대 플레이어에게는 전달되지 않는다.

### 11.3. 망령 패시브와 초과 피해

망령 패시브는 전열에서 전투불능이 될 때 일반 초과 피해가 후열로 넘어가는 것을 막는다. 관통 공격에는 적용되지 않는다.

### 11.4. 직접 공격

같은 라인의 상대 전열과 후열이 모두 없으면 상대 플레이어를 직접 공격한다.

| 위치 | 직접 공격 피해 |
|---|---:|
| 전열 | 공격력 |
| 후열 | 공격력 - 1, 단 0 미만 불가 |

클래스 패시브는 플레이어 직접 공격 피해를 증가시키지 않는다. 직접 공격 피해를 강화하려면 별도 키워드가 필요하다.

---

## 12. 전투불능과 묘지

### 12.1. 전투불능

전투 중 카드 체력이 0 이하가 되면 전투불능이 되어 묘지로 간다.

전투불능으로 묘지에 간 경우에만 "전투불능 시" 효과가 발동한다.

### 12.2. 단순 묘지 이동

| 상황 | 전투불능 효과 발동 |
|---|---|
| 교체로 묘지에 감 | 발동하지 않음 |
| 손패 초과로 버려짐 | 발동하지 않음 |
| 효과로 직접 묘지로 이동 | 카드 텍스트에 따름 |
| 전투 중 체력 0 이하 | 발동함 |

### 12.3. 묘지 원칙

- 묘지는 사용된 카드가 자동으로 쌓이는 영역이 아니다.
- 묘지는 전투불능 카드, 교체 카드, 손패 초과 버림 카드가 가는 손실 영역이다.
- 묘지 카드는 일반적으로 사용할 수 없다.
- 묘지 카드는 덱으로 자동으로 섞이지 않는다.

---

## 13. 드로우와 피로 피해

### 13.1. 기본 드로우

- 시작 시 카드 5장을 드로우한다.
- 1턴 시작 시 추가 드로우는 없다.
- 2턴부터 턴 시작 시 카드 1장을 드로우한다.

### 13.2. 덱 소진

덱이 빈 상태에서 드로우를 시도하면 피로 피해를 받는다.

| 피로 횟수 | 피해 |
|---:|---:|
| 1번째 | 1 |
| 2번째 | 2 |
| 3번째 | 3 |
| N번째 | N |

피로 피해는 드로우를 시도할 때마다 증가한다. 추가 드로우 키워드로 인한 드로우도 피로 피해를 발생시킨다.

---

## 14. 승리 조건과 서든데스

### 14.1. 봇전 / 빠른대전

봇전과 빠른대전은 다음 조건 중 하나가 만족되면 종료된다.

1. 한 플레이어의 체력이 0 이하가 된다.
2. 9턴 전투 종료 후 한 플레이어의 체력이 더 높다.
3. 서든데스에서 승패가 결정된다.

9턴 종료 시 양쪽 체력이 같으면 10턴부터 서든데스에 들어간다.

### 14.2. 서든데스

서든데스는 10턴부터 시작한다.

- 코스트는 9로 고정된다.
- 드로우와 피로 피해는 계속 적용된다.
- 일반 전투 규칙은 그대로 사용한다.
- 서든데스 중 플레이어가 양수의 직접 공격 피해를 받으면 패배 후보가 된다.
- 한쪽만 직접 공격 피해를 받으면 해당 플레이어가 패배한다.
- 양쪽이 같은 전투에서 직접 공격 피해를 받으면 직접 공격 피해가 더 큰 쪽이 패배한다.
- 직접 공격 피해도 같으면 전투 종료 후 체력이 낮은 쪽이 패배한다.
- 그래도 같으면 다음 서든데스 턴을 진행한다.

원혼 피해, 피로 피해, 스킬 피해는 서든데스의 "직접 공격을 맞으면 패배" 조건을 발동하지 않는다. 단, 체력을 0 이하로 만들면 일반 패배 조건은 적용된다.

## 15. 8인 대전 세부 규칙

### 15.1. 라운드 진행

- 8명이 같은 라운드 번호를 공유한다.
- 모든 생존자가 준비 완료했거나 40초가 지나면 라운드 전투로 넘어간다.
- 각 라운드에서 생존자는 1:1로 매칭된다.
- 탈락자는 이후 라운드 매칭 대상에서 제외된다.

### 15.2. 홀수 생존자 처리

생존자가 홀수인 경우, 가장 최근에 휴식하지 않은 플레이어 중 한 명이 휴식한다.

휴식 플레이어:

- 해당 라운드 전투를 하지 않는다.
- 체력 피해를 받지 않는다.
- 승리/패배 보정도 받지 않는다.
- 다음 라운드 매칭 우선순위에서 휴식 페널티를 받아 연속 휴식을 피한다.

### 15.3. 라운드 승패 판정

각 1:1 전투의 라운드 승패는 다음 순서로 판정한다.

1. 전투 중 상대 체력을 0 이하로 만들면 승리
2. 전투 후 체력이 더 높은 쪽 승리
3. 직접 공격 총 피해가 더 큰 쪽 승리
4. 상대 필드 카드 전투불능 수가 더 많은 쪽 승리
5. 무승부

### 15.4. 8인전 체력 감소

라운드 패배자는 전투 중 받은 플레이어 체력 피해와 별개로 패배 피해를 추가로 받는다.

| 라운드 | 기본 패배 피해 |
|---:|---:|
| 1~3 | 2 |
| 4~6 | 3 |
| 7~9 | 4 |
| 10+ | 5 |

연패 추가 피해:

| 연패 수 | 추가 피해 |
|---:|---:|
| 1 | 0 |
| 2 | 1 |
| 3 | 2 |
| 4+ | 3 |

10라운드 이후에는 전투 중 직접 공격 피해가 1.25배로 보정된다. 소수점은 버린다.

### 15.5. 무승부

8인전 라운드가 무승부면 양쪽 모두 패배 피해의 절반을 받는다. 소수점은 버린다.

### 15.6. 순위 산정

같은 라운드에 여러 플레이어가 탈락하면 다음 순서로 최종 순위를 정한다.

1. 탈락 처리 후 남은 체력이 높은 플레이어
2. 해당 라운드 전투 전 체력이 높은 플레이어
3. 누적 라운드 승수가 높은 플레이어
4. 누적 직접 공격 피해가 높은 플레이어
5. 서버 결정론적 tie-breaker 값

### 15.7. 상대 매칭

8인전 매칭은 다음 원칙을 따른다.

- 직전 라운드에 만난 상대와 즉시 재매칭하지 않는다.
- 가능한 한 체력이 비슷한 플레이어끼리 매칭한다.
- 휴식한 플레이어는 다음 라운드에 우선 매칭한다.
- 매칭이 불가피하면 재매칭 제한보다 생존자 전원 매칭을 우선한다.

### 15.8. 유령 필드

유령 필드는 기본적으로 사용하지 않는다. 단, 재접속 대기 중인 플레이어가 제한 시간 안에 돌아오지 않으면 해당 플레이어의 마지막 확정 필드를 자동 제출로 사용한다.

## 16. 클래스

### 16.1. 클래스 원칙

- 클래스 시너지는 없다.
- 각 카드는 정확히 하나의 클래스를 가진다.
- 클래스는 전투 성향과 패시브를 제공한다.
- 클래스 패시브는 직접 공격 피해를 증가시키지 않는다.

### 16.2. 클래스 목록

| 클래스 | 핵심 역할 |
|---|---|
| 돌격 | 첫 공격과 전열 돌파 |
| 수호 | 체력 피해 감소와 전열 보호 |
| 저격 | 후열 압박과 조준 |
| 지원 | 같은 라인 아군 보호와 피해 분담 |
| 기만 | 약화, 침묵, 위치 교란 |
| 망령 | 전투불능, 묘지, 손실 보상 |
| 기술 | 보호막, 제어 무효, 안정성 |

## 17. 키워드

### 17.1. 키워드 원칙

- 키워드는 텍스트보다 내부 enum과 파라미터로 관리한다.
- 모든 키워드는 발동 시점, 대상, 지속 시간, 비용을 가진다.
- v1.0.0에서는 전투 후 지속되는 상태이상을 만들지 않는다.

### 17.2. 주요 키워드

| 키워드 | 규칙 |
|---|---|
| 도발 | 같은 라인 적의 공격 우선순위를 자신으로 끌어온다. |
| 관통 | 전열 초과 피해 전부를 같은 라인 후열에 준다. |
| 조준 | 같은 라인의 후열 대상을 우선 공격할 수 있다. |
| 흡혈 X | 실제 카드 체력 피해를 준 뒤 자신의 체력을 X 회복한다. |
| 반격 X | 피해를 받은 뒤 같은 라인 공격자에게 X 피해를 준다. |
| 침묵 | 같은 라인 대상의 키워드 효과를 이번 전투 동안 막는다. |
| 기절 | 같은 라인 대상의 이번 공격 단계를 막는다. |
| 약화 X | 같은 라인 대상의 공격력을 이번 전투 동안 X 낮춘다. |
| 밀치기 | 같은 라인 안에서 전열 대상을 후열로 민다. 후열이 차 있으면 실패한다. |
| 끌어오기 | 같은 라인 안에서 후열 대상을 전열로 당긴다. 전열이 차 있으면 실패한다. |
| 부활 | 전투불능이 되는 대신 체력 1로 생존한다. 전투마다 1회. |
| 원한 X | 전투불능 시 같은 라인의 가장 앞 적 카드에게 X 피해를 준다. |
| 원혼 X | 전투불능 시 상대 플레이어에게 X 피해를 준다. 직접 공격이 아니다. |
| 잔재 X | 전투불능 시 같은 라인의 아군 카드 1장에게 보호막 X를 준다. |
| 묘지 회수 | 조건에 맞는 묘지 카드 1장을 최대 체력 상태로 손패에 넣는다. |

### 17.3. 키워드 발동 우선순위

같은 시점에 여러 효과가 발동하면 다음 순서로 처리한다.

```text
1. 전투불능 대체 효과: 부활
2. 피해 방지/감소 효과
3. 피해 분담 효과
4. 전투불능 확정
5. 묘지 이동
6. 전투불능 시 카드 대상 효과: 원한, 잔재
7. 전투불능 시 플레이어 대상 효과: 원혼
8. 묘지 회수, 드로우, 기타 자원 효과
```

같은 우선순위 안에서는 다음 순서로 처리한다.

```text
1. 현재 공격 단계의 공격자 쪽
2. 방어자 쪽
3. 전열 -> 후열
4. 좌 -> 중 -> 우
```

### 19.5. 스트리머 직접 설정

스트리머는 시즌 중 자신의 카드 성능을 1회 직접 업데이트할 수 있다.

- 클래스
- 코스트
- 공격력
- 체력
- 키워드
- 카드 콘셉트
- 카드 설명 문구
- 외형 리소스

검증기 버전 변경, 버그성 키워드 수정, 공식 룰 변경, 데이터 오류 수정은 스트리머 자율 업데이트 횟수로 계산하지 않는다.

## 24. 동시 제출과 재접속 정책

### 24.1. 행동 제출

클라이언트는 배치 단계 중 여러 번 임시 행동을 제출할 수 있다.

- 마지막으로 서버가 정상 수락한 행동이 현재 임시 행동이다.
- `ready: true` 제출은 해당 턴 행동 확정을 의미한다.
- 확정 후에는 같은 턴 행동을 수정할 수 없다.
- 단, 서버가 아직 `TURN_PLANNING` 상태이고 제출이 같은 `actionRevision`을 가진 중복 요청이면 idempotent 성공으로 처리한다.

### 24.2. 타임아웃

제한 시간이 끝나면 서버는 다음 순서로 행동을 확정한다.

1. `ready: true`로 확정된 행동
2. 마지막으로 검증 통과한 임시 행동
3. 아무 행동도 없으면 패스

### 24.3. 재접속

재접속한 플레이어는 현재 매치 상태, 남은 시간, 자기 손패, 자기 임시 행동, 공개 필드 상태를 다시 받는다.

상대 손패와 상대 임시 행동은 공개하지 않는다.

## 29. 상용 게임 수준 비주얼과 연출

### 29.1. 목표

치카포 아레나는 기능적으로만 동작하는 웹 게임이 아니라 상용 카드 배틀 게임처럼 보이고 느껴져야 한다.

전투 화면은 정적인 카드 배치판이 아니라, 카드가 살아 있는 것처럼 반응하고 전투 결과가 직관적으로 읽히는 실시간 연출 무대여야 한다. 화려함은 목표지만, 판정 가독성과 룰 이해를 해치면 안 된다.

### 29.2. 렌더링 원칙

전투 화면의 핵심 렌더러는 PixiJS를 적극적으로 사용한다.

PixiJS 담당 영역:

- 2x3 필드 보드
- 카드 스프라이트와 카드 상태 레이어
- 공격 궤적
- 충돌/피격 이펙트
- 보호막, 관통, 직접 공격, 묘지 이동 연출
- 파티클
- 화면 흔들림
- 타격 정지
- 슬로 모션
- 전투 카메라 줌/팬
- 전투 리플레이 타임라인

React/DOM 담당 영역:

- 내비게이션
- 버튼, 탭, 메뉴
- 덱 편성 폼
- 위키 문서
- 카드 상세 텍스트
- 접근성 텍스트
- 설정 화면

전투 중 HUD는 PixiJS와 DOM을 혼합할 수 있다. 단, 핵심 전투 피드백은 PixiJS 씬 안에서 통일감 있게 처리한다.

### 29.3. 외부 라이브러리 사용 방침

외부 라이브러리는 상용 수준의 연출 품질을 위해 적극 사용한다. 단, 룰 판정은 외부 애니메이션 라이브러리에 의존하지 않는다.

후보 라이브러리 역할:

| 라이브러리 | 역할 |
|---|---|
| PixiJS | 전투 캔버스, 2D WebGL/WebGPU 렌더링, 씬 그래프 |
| pixi-filters | 블룸, 블러, 색수차, 글로우, 디졸브 등 후처리 필터 |
| spine-pixi 계열 런타임 | 카드 등장, 클래스별 캐릭터형 연출, 스켈레탈 애니메이션 |
| GSAP | 복잡한 UI/전투 타임라인, 카메라 연출, 시퀀스 제어 |
| motion/react | DOM UI 전환, 패널 등장, 버튼/탭 상태 변화 |
| canvas-confetti | 승리/보상 등 짧은 축하 연출 |
| Howler.js 또는 동급 오디오 라이브러리 | 효과음, 타격음, 승리/패배 사운드 큐 |

구현 시점에는 각 라이브러리의 최신 호환 버전과 라이선스를 확인한다.

### 29.4. 전투 연출 레이어

PixiJS 전투 씬은 다음 레이어를 가진다.

```text
1. 배경 레이어
2. 보드/라인 레이어
3. 카드 그림자 레이어
4. 카드 스프라이트 레이어
5. 상태 아이콘/체력 레이어
6. 공격 궤적 레이어
7. 피격/폭발/파티클 레이어
8. 화면 전체 후처리 레이어
9. 결과/마무리 연출 레이어
```

레이어 순서는 고정한다. 전투 로그 재생 중에도 같은 이벤트는 항상 같은 시각적 레이어에서 재생되어야 한다.

### 29.5. 클래스별 연출 방향

| 클래스 | 연출 방향 |
|---|---|
| 돌격 | 빠른 돌진선, 충격파, 짧은 타격 정지 |
| 수호 | 육각 보호막, 둔탁한 방어음, 단단한 파편 |
| 저격 | 조준선, 렌즈 플레어, 날카로운 직선 궤적 |
| 지원 | 부드러운 광원, 리본/파동형 보호 효과 |
| 기만 | 왜곡, 잔상, 위치 흔들림, 색상 반전 |
| 망령 | 어두운 잔향, 연기, 사라짐/되돌아옴 효과 |
| 기술 | 홀로그램, 픽셀 입자, 정밀한 기계식 이펙트 |

클래스 연출은 서로 구분되어야 하지만 전체 팔레트와 형태 언어는 하나의 게임처럼 어울려야 한다.

### 29.6. 키워드별 VFX 방향

| 키워드 | VFX |
|---|---|
| 도발 | 같은 라인 안에서 시선이 끌리는 링/화살표 |
| 조준 | 같은 라인 후열을 향한 얇은 타겟 라인 |
| 관통 | 전열을 지나 후열까지 이어지는 궤적 |
| 보호막 | 카드 주변 반투명 막과 흡수 파편 |
| 침묵 | 카드 키워드 영역이 잠기는 듯한 어둡고 짧은 봉인 효과 |
| 기절 | 별/파형보다 게임 톤에 맞는 전기적 흔들림 |
| 밀치기 | 같은 라인 후열 방향으로 짧은 넉백 |
| 끌어오기 | 같은 라인 전열 방향으로 당기는 와이어/중력 효과 |
| 부활 | 묘지 이동 직전 빛 또는 그림자가 되감기는 연출 |
| 원한 | 전투불능 지점에서 같은 라인 적에게 날아가는 잔류 공격 |
| 원혼 | 카드에서 플레이어 체력 영역으로 이동하는 영혼형 피해 |

### 29.7. 애니메이션 품질 기준

전투 연출은 다음 품질 기준을 만족해야 한다.

- 카드 배치, 이동, 교체는 즉시 순간이동하지 않고 짧은 easing을 가진다.
- 공격은 준비, 발사/접근, 피격, 복귀의 4단계로 읽힌다.
- 큰 피해는 숫자 크기, 색, 카메라 반응으로 구분한다.
- 전투불능은 카드가 사라지는 이유가 명확하게 보여야 한다.
- 묘지 이동은 카드가 필드에서 손실되었다는 느낌을 준다.
- 직접 공격은 카드 간 공격과 명확히 다른 연출을 가진다.
- 8인전 라운드 결과는 개인 전투와 전체 순위 변화를 모두 보여준다.
- 반복 전투에서도 눈이 피로하지 않도록 과도한 전체 화면 플래시는 제한한다.

### 29.8. 성능 기준

목표 성능:

| 환경 | 목표 |
|---|---|
| 데스크톱 최신 브라우저 | 전투 연출 60fps |
| 일반 모바일 | 전투 연출 30fps 이상 |
| 저사양/절전 모드 | 이펙트 품질 자동 낮춤 |

성능 원칙:

- 파티클 수는 품질 프리셋별 상한을 둔다.
- 텍스처는 atlas로 묶는다.
- 큰 필터는 화면 전체가 아니라 필요한 컨테이너에만 적용한다.
- 리플레이 이벤트와 렌더링 타임라인을 분리한다.
- 전투 판정은 애니메이션 프레임에 의존하지 않는다.
- `prefers-reduced-motion` 또는 저사양 모드에서는 화면 흔들림, 플래시, 파티클 밀도를 낮춘다.

### 29.9. 아트 에셋 파이프라인

필수 에셋:

- 카드 프레임
- 카드 그림자/광원
- 클래스별 공격 이펙트
- 키워드별 파티클 텍스처
- 보호막/관통/직접 공격 전용 이펙트
- 승리/패배/서든데스 결과 연출
- 8인전 순위 변화 연출

에셋은 가능한 한 재사용 가능한 atlas와 preset으로 관리한다. 카드별 개별 특수효과를 무한정 늘리지 않고 클래스, 키워드, 희귀도 외형 효과 조합으로 다양성을 만든다.

### 29.10. 비주얼 QA

전투 화면 구현은 빌드 성공만으로 완료하지 않는다.

필수 검증:

- 데스크톱과 모바일 화면 캡처
- PixiJS 캔버스 non-blank 확인
- 전투 리플레이 1턴, 중반, 서든데스, 8인전 결과 화면 확인
- 카드/체력/피해 숫자 겹침 확인
- 이펙트가 룰 판정을 가리지 않는지 확인
- 저사양 모드 또는 reduced motion 확인
- 30초 이상 리플레이 재생 시 메모리 증가 확인

## 30. 아레나 위키

### 30.1. 목적

아레나 안에는 `위키`라는 이름의 읽기 전용 룰 문서 영역을 제공한다.

위키는 개발 문서가 아니라 플레이어가 게임을 이해하고 판단하는 데 필요한 게임 플레이 규칙을 정리하는 공간이다. 기술적 구현, API, DB, 서버 구조, 배포 계획, 내부 밸런스 계산식 같은 개발자용 정보는 위키에 노출하지 않는다.

### 30.2. 기본 원칙

- 위키는 모든 유저가 읽을 수 있다.
- 일반 유저는 위키 문서를 수정할 수 없다.
- 위키 문서는 운영자 또는 개발자가 관리한다.
- 문서 내용은 게임 플레이에 필요한 룰, 용어, 모드, 카드, 키워드 설명으로 제한한다.
- 기획 중인 규칙은 확정 규칙과 구분해서 표시한다.
- 실제 적용 중인 규칙과 다른 내용이 있으면 현재 게임에 적용 중인 규칙을 우선한다.
- 위키 문서에는 마지막 갱신일과 적용 대상 룰 버전을 표시한다.

### 30.3. 위키 문서 분류

필수 문서 분류:

| 분류 | 포함 내용 |
|---|---|
| 처음 시작하기 | 아레나의 목표, 한 판 흐름, 기본 조작 |
| 모드 | 봇전, 빠른대전, 8인 대전 설명 |
| 덱 구성 | 덱 크기, 동일 스트리머 제한, 카드 버전 |
| 손패와 드로우 | 시작 손패, 멀리건, 손패 8장 제한, 피로 피해 |
| 필드와 라인 | 2x3 필드, 전열/후열, 좌/중/우 라인 |
| 턴과 코스트 | 코스트 증가, 배치 시간, 행동 확정 |
| 배치 행동 | 배치, 전술 이동, 교체 |
| 전투 | 공격 순서, 동시 공격, 타겟 우선순위 |
| 피해 | 보호막, 체력 피해 유지, 초과 피해, 관통 |
| 직접 공격 | 전열/후열 직접 공격 피해, 서든데스 관계 |
| 묘지 | 전투불능, 교체, 손패 초과 버림, 묘지 회수 |
| 클래스 | 돌격, 수호, 저격, 지원, 기만, 망령, 기술 |
| 키워드 | 도발, 조준, 침묵, 기절, 밀치기, 끌어오기 등 |
| 8인 대전 | 매칭, 휴식, 패배 피해, 순위 산정 |
| 자주 묻는 질문 | 자주 헷갈리는 판정과 예시 |
| 용어집 | 게임 내 용어의 짧은 정의 |

### 30.4. 문서 표현 방식

위키 문서는 짧은 문단, 표, 예시 상황 중심으로 작성한다.

좋은 예:

```text
후열 카드는 같은 라인의 상대 카드가 없을 때 플레이어를 직접 공격합니다.
이때 직접 공격 피해는 공격력 -1입니다. 0보다 낮아지지는 않습니다.
```

피해야 하는 예:

```text
서버는 resolveCombat 내부에서 PlayerBattleState를 순회하며 directAttackDamage를 산출합니다.
```

### 30.5. 게임 UI와의 연결

위키는 독립 메뉴뿐 아니라 게임 화면 곳곳에서 연결된다.

- 카드 키워드 툴팁에서 해당 키워드 위키 문서로 이동
- 덱 편성 오류에서 관련 덱 구성 문서로 이동
- 손패 초과, 피로 피해, 교체 경고에서 관련 문서로 이동
- 전투 로그의 주요 판정에서 관련 룰 문서로 이동
- 8인전 순위/피해 결과에서 8인전 규칙 문서로 이동

### 30.6. 검색과 링크

- 위키는 제목, 용어, 키워드, 별칭으로 검색할 수 있어야 한다.
- 각 문서는 고유 주소를 가진다.
- 전투 로그와 카드 툴팁은 고유 주소로 연결한다.
- 문서 안의 용어는 다른 위키 문서로 링크할 수 있다.

### 30.7. 공개 상태

기획 중인 아레나 규칙도 위키에 포함할 수 있다. 단, 문서 상태를 반드시 표시한다.

| 상태 | 의미 |
|---|---|
| 적용 중 | 현재 게임에 적용된 규칙 |
| 확정 예정 | 구현 예정이며 룰 변경 가능성이 낮은 규칙 |
| 검토 중 | 밸런스나 UX 검토 중인 규칙 |
| 폐기됨 | 더 이상 사용하지 않는 규칙 |

검토 중 문서는 공식 대전에서 실제로 적용 중인 규칙으로 오해되지 않도록 상단에 안내를 표시한다.

## 31. 구현 아키텍처

### 31.1. 새 엔진 패키지

새 룰 엔진은 기존 `arenaBattleSimulator`를 수정하지 않고 새 모듈로 만든다.

권장 구조:

```text
backend/src/arena-v2/
  rules/
  engine/
  validators/
  bots/
  modes/
  persistence/
  replay/
  __tests__/
```

핵심 함수:

```ts
validateDeck(input): DeckValidationResult
createInitialBattleState(input): BattleState
applyMulligan(state, playerId, input): BattleState
validateTurnAction(state, playerId, action): ActionValidationResult
lockTurnActions(state): LockedTurn
applyTurnActions(state, lockedTurn): BattleState
resolveCombat(state): CombatResult
checkWinCondition(state): WinResult
serializeVisibleState(state, viewerId): MatchView
```

### 31.2. 순수 함수 우선

- 출력: 새 상태 객체와 이벤트 목록
- DB 조회, 저장, 락 처리는 service layer에서 수행
- 랜덤은 seed 기반 유틸만 사용

## 32. 안전한 전면 교체 계획

### 32.1. 기본 방침

기존 아레나 데이터는 최종적으로 폐기한다. 다만 배포 사고에 대비해 즉시 삭제하지 않고 백업 후 단계적으로 교체한다.

### 32.2. 단계 1: 동결

1. 기존 빠른대전/8인전 큐 진입을 막는다.
2. 진행 중인 기존 아레나 매치는 완료 또는 강제 종료한다.
3. 기존 아레나 보상/랭킹 쓰기를 중지한다.
4. 공지 문구를 노출한다.

### 32.3. 단계 2: 백업

폐기 대상 테이블과 설정을 배포 직전 백업한다.

대상 예시:

- `arena_decks`
- `arena_matches`
- `arena_match_replays`
- `arena_player_ratings`
- `arena_rank_snapshots`
- `arena_*` 설정 JSON

백업은 복구 목적이 아니라 감사와 장애 대응 목적이다. 새 아레나로 데이터 이전은 하지 않는다.

### 32.4. 단계 3: 새 스키마 생성

기존 테이블을 바로 덮어쓰지 않고 새 prefix 또는 새 version column 기준으로 생성한다.

권장 prefix:

```text
arena_v2_decks
arena_v2_card_versions
arena_v2_matches
arena_v2_match_players
arena_v2_card_instances
arena_v2_action_submissions
arena_v2_replay_events
arena_v2_ratings
arena_v2_rank_snapshots
arena_v2_battle_royales
```

### 32.5. 단계 4: 새 엔진 검증

배포 전에 다음 테스트를 통과해야 한다.

- 같은 seed와 같은 입력은 같은 결과를 만든다.
- 덱 셔플이 재현 가능하다.
- 멀리건이 재현 가능하다.
- 손패 초과 버림이 정확히 동작한다.
- 피로 피해가 누적된다.
- 전술 이동 검증이 시작 필드 기준으로 동작한다.
- 교체가 전투불능 효과를 발동하지 않는다.
- 전열/후열 동시 공격 순서가 정확하다.
- 관통/초과 피해가 같은 라인 후열까지만 전달된다.
- 도발/조준/밀치기/끌어오기가 같은 라인 안에서만 작동한다.
- 부활/원한/원혼/잔재 우선순위가 재현 가능하다.
- 서든데스 판정이 재현 가능하다.
- 8인전 홀수 생존자 휴식과 순위 산정이 재현 가능하다.

### 32.6. 단계 5: 내부 스위치오버

1. API 라우트를 새 서비스로 연결한다.
2. 프론트엔드 계약 패키지를 새 타입으로 교체한다.
3. 기존 리플레이 페이지는 새 이벤트 타입 기준으로 재작성한다.
4. 관리자 화면에서 새 kill switch, 매치 진단, 큐 진단을 제공한다.
5. 내부 계정으로 봇전, 빠른대전, 8인전 전체 플로우를 검증한다.

### 32.7. 단계 6: 기존 데이터 폐기

새 아레나가 정상 동작하고 백업이 확인되면 기존 아레나 테이블과 캐시를 제거한다.

주의:

- 제거 스크립트는 운영 DB에서 수동 확인 후 실행한다.
- 삭제 전 테이블 row count와 백업 파일 위치를 로그로 남긴다.
- 삭제 후 새 아레나 smoke test를 즉시 실행한다.

### 32.8. 롤백 방침

기존 아레나 데이터를 새 아레나로 마이그레이션하지 않으므로, 기능 롤백은 다음 둘 중 하나만 허용한다.

1. 새 아레나 오픈 전이면 기존 아레나로 되돌린다.
2. 새 아레나 오픈 후이면 아레나 기능을 점검 모드로 닫고 새 엔진을 수정한다.

새 아레나 오픈 후 기존 아레나로 유저 데이터를 되돌리는 롤백은 지원하지 않는다.

## 36. 카드 풀과 자동 생성 상세 기획

### 36.1. 목표

치카포 아레나의 카드 풀은 등록 스트리머 규모가 커져도 운영자가 개별 수작업으로 밸런싱하지 않아도 되는 구조여야 한다.

자동 생성 카드는 다음 조건을 만족해야 한다.

- 같은 스트리머는 같은 카드 능력을 가진다.
- 같은 생성 버전과 같은 스트리머 ID는 항상 같은 결과를 만든다.
- 자동 생성 카드와 스트리머 직접 설정 카드는 같은 검증기를 통과한다.
- 카드 풀 전체의 코스트, 클래스, 키워드 분포가 한쪽으로 쏠리지 않는다.
- 14~20장 덱에서 실제로 다양한 전략이 가능해야 한다.

### 36.2. 코스트 분포 목표

전체 카드 풀의 기본 목표 분포:

| 코스트 | 목표 비중 |
|---:|---:|
| 1 | 8~10% |
| 2 | 12~14% |
| 3 | 14~16% |
| 4 | 14~16% |
| 5 | 13~15% |
| 6 | 10~12% |
| 7 | 8~10% |
| 8 | 5~7% |
| 9 | 3~5% |

저코스트 카드는 초반 필드 점유와 직접 공격을 만들기 쉬우므로 공격력과 직접 공격 관련 키워드 빈도를 낮게 유지한다. 고코스트 카드는 장수 제한을 두지 않지만 초반 리스크와 피로 피해로 자연 제약한다.

### 36.3. 클래스 분포 목표

| 클래스 | 목표 비중 |
|---|---:|
| 돌격 | 13~16% |
| 수호 | 13~16% |
| 저격 | 13~16% |
| 지원 | 12~15% |
| 기만 | 12~15% |
| 망령 | 12~15% |
| 기술 | 12~15% |

지원, 기만, 망령은 과도하게 많으면 전투가 길어지거나 불쾌한 판정이 늘 수 있으므로 시뮬레이션에서 별도 관찰한다.

### 36.4. 역할 템플릿

자동 생성은 클래스만 고르는 방식이 아니라 역할 템플릿을 함께 고른다.

| 템플릿 | 설명 |
|---|---|
| 전열 공격수 | 전열에서 같은 라인을 빠르게 돌파한다. |
| 전열 방어수 | 피해를 받아내고 후열을 보호한다. |
| 후열 딜러 | 후열에서 안정적으로 피해를 누적한다. |
| 후열 지원 | 같은 라인 아군을 보호하거나 보조한다. |
| 방해형 | 침묵, 기절, 약화, 위치 교란을 사용한다. |
| 묘지형 | 전투불능, 원한, 원혼, 잔재, 묘지 회수를 활용한다. |
| 직접 압박형 | 빈 라인과 직접 공격을 노린다. |
| 안정형 | 강한 조합은 없지만 덱에 섞기 쉬운 평균형이다. |

### 36.5. 키워드 빈도 기준

키워드는 희소도와 불쾌감을 기준으로 빈도를 관리한다.

| 키워드군 | 빈도 기준 |
|---|---|
| 기본 전투 키워드 | 흔함 |
| 보호막, 피해 감소 | 보통 |
| 관통, 반격, 흡혈 | 보통 이하 |
| 조준, 침묵, 기절 | 낮음 |
| 밀치기, 끌어오기 | 낮음 |
| 부활 | 매우 낮음 |
| 원혼, 제한 없음 묘지 회수 | 매우 낮음 |

저코스트 카드에는 직접 압박, 원혼, 전투 드로우, 묘지 회수의 조합을 강하게 제한한다.

### 36.6. 자동 생성 파이프라인

```text
1. 스트리머 ID와 생성 버전으로 seed 생성
2. 코스트 후보 선택
3. 클래스 후보 선택
4. 역할 템플릿 선택
5. 공격력/체력 분배
6. 키워드 후보 선택
7. 예산 계산
8. 조합 추가 비용 계산
9. 금지/주의 조합 검사
10. 카드 풀 분포 검사
11. 실패 시 같은 콘셉트 안에서 fallback
12. 카드 버전 저장
```

fallback은 같은 스트리머와 같은 생성 버전에서 항상 같은 결과를 내야 한다.

### 36.7. 스트리머 직접 설정 UX

스트리머 직접 설정 화면은 완전 자유 편집보다 검증 가능한 선택식 편집을 우선한다.

권장 흐름:

1. 현재 자동 생성 카드 확인
2. 클래스 선택
3. 코스트 선택
4. 역할 템플릿 선택
5. 공격력/체력 조정
6. 키워드 선택
7. 예산 사용량과 위험 조합 확인
8. 저장 전 시뮬레이션 요약 확인
9. 카드 버전 생성

검증 실패 시 단순히 저장 실패만 보여주지 않고 어떤 조합이 예산을 초과했는지 설명한다.

## 37. 밸런스 시뮬레이션 기획

### 37.1. 목표

밸런스는 운영자 감각이 아니라 반복 가능한 시뮬레이션 지표로 판단한다.

시뮬레이션은 다음을 검증한다.

- 게임이 너무 빨리 끝나지 않는가
- 게임이 너무 오래 끌리지 않는가
- 특정 클래스나 키워드가 지나치게 강하지 않은가
- 직접 공격이 과도하게 자주 발생하지 않는가
- 피로 피해가 의미 있는 선택지가 되는가
- 8인전 탈락 타이밍이 적절한가

### 37.2. 주요 지표

| 지표 | 관찰 이유 |
|---|---|
| 평균 종료 턴 | 게임 길이 |
| 9턴 이전 종료율 | 초반 폭발 위험 |
| 서든데스 진입률 | 장기전/무승부 위험 |
| 직접 공격 발생률 | 라인 방어 중요도 |
| 직접 공격 평균 피해 | 체력 30 기준 압박 강도 |
| 피로 피해 발생률 | 덱 크기 선택의 의미 |
| 손패 초과 버림률 | 드로우/손패 제한 밸런스 |
| 카드 교체 빈도 | 교체가 실제 전술로 쓰이는지 |
| 전술 이동 빈도 | 위치 전략 유효성 |
| 클래스별 승률 | 클래스 밸런스 |
| 키워드별 승률 | 키워드 밸런스 |
| 코스트별 채용률 | 덱 구성 다양성 |
| 8인전 평균 탈락 라운드 | 배틀로얄 흐름 |

### 37.3. 위험 기준

| 항목 | 위험 기준 |
|---|---|
| 특정 클래스 승률 | 전체 평균 대비 +7%p 이상 |
| 특정 키워드 포함 덱 승률 | 전체 평균 대비 +8%p 이상 |
| 평균 종료 턴 | 5턴 미만 또는 11턴 초과 |
| 서든데스 진입률 | 15% 초과 |
| 1~3턴 직접 공격 누적 피해 | 평균 6 초과 |
| 8인전 3라운드 이전 탈락률 | 10% 초과 |
| 8인전 12라운드 이후 생존자 5명 이상 | 장기전 위험 |

### 37.4. 시뮬레이션 방식

- 무작위 덱
- 템플릿 덱
- 메타 후보 덱
- 봇 성향별 덱
- 극단 조합 덱
- 14장 최소 덱
- 20장 최대 덱
- 고코스트 과다 덱
- 저코스트 직접 압박 덱

각 시뮬레이션 배치는 seed를 저장해 재현 가능해야 한다.

### 37.5. 조정 방식

자동 너프/버프는 하지 않는다.

조정은 다음 방식으로만 한다.

1. 검증기 버전 업데이트
2. 키워드 비용 조정
3. 조합 추가 비용 조정
4. 특정 키워드 임시 비활성화
5. 카드 버전 강제 갱신
6. 다음 시즌 카드 생성 버전 변경

이미 시작된 전투에는 밸런스 변경을 적용하지 않는다.

## 38. UX 플로우 및 화면 기획

### 38.1. 첫 진입

첫 진입 화면은 플레이 가능한 상태로 안내해야 한다.

필수 요소:

- 현재 시즌 상태
- 내 아레나 프로필
- 추천 시작 행동
- 봇전 시작
- 덱 만들기
- 위키 바로가기
- 튜토리얼 진행 상태

처음 온 유저에게는 빠른대전보다 튜토리얼과 봇전을 우선 노출한다.

### 38.2. 덱 빌더

덱 빌더 필수 기능:

- 14~20장 덱 구성
- 동일 스트리머 1장 제한 표시
- 코스트 분포 표시
- 클래스 분포 표시
- 키워드 검색
- 카드 버전 표시
- 불법 카드 경고
- 추천 보완 카드
- 저장 전 검증

덱이 저장 가능해지는 조건을 명확하게 보여준다.

### 38.3. 멀리건 화면

멀리건 화면은 대전 시작 전 가장 중요한 첫 판단이다.

필수 표시:

- 시작 손패 5장
- 교체 가능 수 0~3장
- 각 카드 코스트와 역할
- 덱 남은 장수
- 초반 코스트 곡선 요약
- 확정 버튼
- 제한 시간

상대 손패는 공개하지 않는다.

### 38.4. 배치 화면

배치 화면은 플레이어가 매 턴 가장 오래 보는 핵심 화면이다.

필수 구성:

- 내 필드 6칸
- 상대 공개 필드 6칸
- 내 손패 최대 8장
- 현재 코스트
- 남은 시간
- 전술 이동 가능 여부
- 교체 모드
- 묘지 보기
- 덱 남은 장수
- 피로 예정 피해
- 배치 완료 버튼

행동을 하면 즉시 서버 검증 전 로컬 미리보기를 보여주되, 서버가 거절하면 이유와 함께 되돌린다.

### 38.5. 전투 재생

전투 재생은 빠르게 이해되어야 한다.

- 전투 시작 전 양쪽 최종 배치를 1초 내외로 보여준다.
- 전열 공격과 후열 공격을 시각적으로 구분한다.
- 직접 공격은 플레이어 체력 UI까지 연결되는 궤적으로 보여준다.
- 전투불능 카드는 묘지로 이동하는 연출을 가진다.
- 로그는 전체 덤프가 아니라 핵심 사건 위주로 접는다.

### 38.6. 결과 화면

1:1 결과 화면:

- 승패
- 남은 체력
- 종료 턴
- 결정적 피해
- MVP 카드
- MMR 변화
- 다시 플레이
- 덱 수정
- 리플레이 보기

8인전 결과 화면:

- 최종 순위
- 라운드별 상대
- 받은 패배 피해
- 직접 공격 피해
- 탈락 라운드
- 보상

### 38.7. 위키 연결 UX

유저가 실수했을 때 바로 관련 위키로 갈 수 있어야 한다.

예:

- "동일 스트리머 카드는 1장만 넣을 수 있습니다." -> 덱 구성 문서
- "손패가 가득 차서 카드가 묘지로 갔습니다." -> 손패와 드로우 문서
- "조준은 같은 라인에서만 작동합니다." -> 키워드 문서

## 39. 비주얼 아트 디렉션

### 39.1. 핵심 톤

치카포 아레나는 귀여운 스트리머 카드 수집 감성과 상용 카드 배틀 게임의 타격감을 동시에 가져야 한다.

목표 톤:

- 귀엽지만 유치하지 않음
- 화려하지만 판정을 가리지 않음
- 카드 수집의 만족감
- 전투 게임의 속도감
- 모바일에서도 읽히는 명확한 UI

### 39.2. 색과 분위기

기본 UI는 밝고 선명한 톤을 유지한다. 전투 VFX는 클래스별 색을 갖지만, 전체 게임 팔레트에서 벗어나지 않는다.

권장 팔레트 방향:

- 기본 배경: 밝은 중립색
- 주요 포인트: 치카포 브랜드 계열의 선명한 포인트 컬러
- 위험/피해: 붉은색 계열
- 보호/회복: 청록/녹색 계열
- 망령/기만: 보라/남색 계열을 제한적으로 사용
- 기술: 청색/시안 계열의 홀로그램 느낌

보라/남색이 전체 화면을 지배하지 않도록 주의한다.

### 39.3. 카드 디자인

카드는 작은 크기에서도 다음 정보가 읽혀야 한다.

- 코스트
- 공격력
- 체력
- 클래스
- 현재 남은 체력
- 누적 피해
- 주요 키워드

카드 프레임은 희귀도와 코스메틱 표현에 사용할 수 있지만 전투 성능을 암시하면 안 된다.

### 39.4. 전투 화면 구도

전투 화면은 중앙에 2x3 양쪽 필드를 명확하게 배치한다.

구도 원칙:

- 내 필드는 하단, 상대 필드는 상단
- 좌/중/우 라인이 직관적으로 이어져야 함
- 직접 공격 궤적이 플레이어 체력 UI와 연결되어야 함
- 손패는 내 필드 아래에 배치
- 모바일에서는 손패와 필드를 겹치지 않게 분리

### 39.5. 모션 언어

모션은 다음 규칙을 따른다.

- 일반 배치: 부드럽고 짧은 이동
- 공격: 빠르고 날카로운 easing
- 방어: 묵직하고 반발력 있는 easing
- 묘지 이동: 아래로 가라앉거나 카드가 흐려지는 느낌
- 승리: 밝고 확장되는 연출
- 패배: 과하지 않은 어두운 수축 연출

## 40. 보상, 랭킹, 시즌 기획

### 40.1. 전체 원칙

아레나 시즌은 운영자가 관리자 탭에서 열고 닫고 설정한다. 시즌 보상은 빠른대전 MMR 기준 등급으로 나누어 시즌 종료 시 차등 지급한다.

핵심 원칙:

- 시즌 경쟁 보상의 기준은 빠른대전 MMR 등급이다.
- 8인전은 별도 시즌 포인트와 업적 보상을 제공하지만, 핵심 등급 보상 기준은 흔들지 않는다.
- 봇전은 학습 보상만 제공하고 시즌 경쟁 보상에는 반영하지 않는다.
- 보상은 전투 성능에 영향을 주면 안 된다.
- 시즌 종료 후 정산이 끝나기 전까지 보상은 `pending` 상태로 둔다.

### 40.2. 관리자 시즌 설정

운영자는 관리자 탭에서 다음 항목을 설정할 수 있다.

| 항목 | 설명 |
|---|---|
| 시즌 ID | 내부 식별자 |
| 시즌 이름 | 유저에게 표시되는 이름 |
| 시즌 상태 | 초안, 예약, 진행 중, 잠금, 정산 중, 종료 |
| 시작 시각 | 시즌 자동 오픈 시각 |
| 종료 시각 | 시즌 자동 종료 시각 |
| 룰 버전 | 전투 규칙 버전 |
| 검증기 버전 | 카드 제작/검증 기준 버전 |
| 카드 생성 버전 | 자동 생성 카드 버전 |
| 보상 정책 | 등급별 보상 묶음 |
| 빠른대전 활성화 | MMR 반영 대전 허용 여부 |
| 봇전 활성화 | 봇전 허용 여부 |
| 8인전 활성화 | 8인전 허용 여부 |
| 스트리머 카드 수정 | 시즌 중 카드 직접 설정 허용 여부 |
| 리플레이 보존 기간 | 고정 7일 |

### 40.3. 시즌 상태

```text
초안 -> 예약 -> 진행 중 -> 잠금 -> 정산 중 -> 종료
```

| 상태 | 동작 |
|---|---|
| 초안 | 운영자만 설정 가능. 유저에게 노출하지 않는다. |
| 예약 | 유저에게 예정 시즌으로 노출할 수 있다. 매칭은 불가하다. |
| 진행 중 | 봇전, 빠른대전, 8인전이 설정에 따라 열린다. |
| 잠금 | 새 매칭은 막고 진행 중인 경기만 마무리한다. |
| 정산 중 | 랭킹 확정, 어뷰징 보류, 보상 계산을 수행한다. |
| 종료 | 보상 지급 완료. 시즌 기록은 읽기 전용으로 남는다. |

시즌 상태 전환은 감사 로그를 남긴다.

### 40.4. 시즌과 카드 버전의 관계

시즌이 `진행 중`이 되면 다음 값을 고정한다.

- 룰 버전
- 검증기 버전
- 자동 생성 카드 버전
- 공식 모드 허용 카드 버전
- 등급 보상 정책

시즌 중 카드 성능 변경은 최소화한다. 검증기 위반, 버그, 금지 키워드 같은 강제 사유가 있으면 다음 공식 경기부터 최신 합법 버전을 적용한다.

### 40.5. 빠른대전 MMR

빠른대전은 MMR 기반 랭킹을 사용한다.

필수 요소:

- 현재 MMR
- 현재 등급
- 시즌 최고 MMR
- 시즌 최고 등급
- 승/패/무
- 최근 경기
- 순위 스냅샷

무승부는 MMR 변동을 없게 한다. 단, 어뷰징 방지를 위해 무승부 경기 수는 기록한다.

### 40.6. MMR 등급

시즌 보상은 `시즌 최고 등급` 기준으로 지급한다. 시즌 최고 등급은 해당 시즌 중 달성한 가장 높은 MMR 등급이다.

| 등급 | MMR 범위 |
|---|---:|
| 브론즈 | 0~999 |
| 실버 | 1000~1199 |
| 골드 | 1200~1399 |
| 플래티넘 | 1400~1599 |
| 다이아 | 1600~1799 |
| 마스터 | 1800~1999 |
| 그랜드마스터 | 2000+ |

신규 유저 기본 MMR은 1000이다.

배치 경기:

- 시즌 첫 5판은 배치 경기로 표시한다.
- 배치 중에도 MMR은 변동한다.
- 배치 중 등급 보상 기준은 확정하지 않고, 5판 완료 후 등급을 표시한다.
- 시즌 종료 시 배치 5판을 완료하지 않은 유저는 브론즈 참여 보상만 받을 수 있다.

### 40.7. MMR 변화 방향

정확한 공식은 구현 시 검증하되 다음 원칙을 따른다.

- 상대 MMR이 높을수록 승리 보상이 크다.
- 상대 MMR이 낮을수록 패배 손실이 크다.
- 연승 보너스는 플래티넘 이하에서만 적용할 수 있다.
- 다이아 이상에서는 연승 보너스를 사용하지 않는다.
- 장기 미접속으로 MMR을 깎지 않는다.
- 어뷰징 의심 경기는 MMR 반영을 보류할 수 있다.

### 40.8. 시즌 종료 보상

시즌 종료 보상은 등급별로 차등 지급한다.

보상은 성능과 무관한 코스메틱과 명예 요소로 제한한다.

| 등급 | 보상 방향 |
|---|---|
| 브론즈 | 참여 칭호, 소량 포인트, 기본 프로필 장식 |
| 실버 | 브론즈 보상 + 시즌 카드 프레임 하위 |
| 골드 | 실버 보상 + 이름 효과 하위 |
| 플래티넘 | 골드 보상 + 전투 이모트 |
| 다이아 | 플래티넘 보상 + 승리 연출 하위 |
| 마스터 | 다이아 보상 + 시즌 한정 프로필 장식 상위 |
| 그랜드마스터 | 마스터 보상 + 최상위 시즌 칭호와 특별 승리 연출 |

보상 수량과 아이템 ID는 시즌별 보상 정책에서 운영자가 설정한다.

### 40.9. 보상 지급 절차

```text
1. 시즌 잠금
2. 진행 중 경기 마무리
3. 정산 중 상태 진입
4. 랭킹 스냅샷 생성
5. 어뷰징 의심 계정 보류
6. 시즌 최고 등급 기준 보상 계산
7. 보상 미리보기 생성
8. 운영자 확인
9. 보상 지급
10. 시즌 종료 상태 전환
```

보상 지급은 idempotent 해야 한다. 같은 시즌 보상을 두 번 지급하지 않도록 `seasonId + playerId` 기준으로 중복을 막는다.

### 40.10. 보상 보류

다음 계정은 보상 지급을 보류할 수 있다.

- 담합 의심
- MMR 조작 의심
- 반복 탈주
- 제재 중인 계정
- 비정상 경기 패턴

보류된 보상은 관리자 검토 후 지급, 축소 지급, 취소 중 하나로 처리한다.

### 40.11. 8인전 보상

8인전은 최종 순위 기반 보상을 사용하되, 빠른대전 MMR 등급 보상과 분리한다.

| 순위 | 보상 방향 |
|---:|---|
| 1위 | 가장 높은 8인전 시즌 포인트와 연출 보상 기회 |
| 2~4위 | 승리권 보상 |
| 5~8위 | 참여/학습 보상 |

8인전 시즌 포인트는 별도 랭킹이나 업적에 사용할 수 있지만, 빠른대전 MMR 등급을 올리지 않는다.

### 40.12. 봇전 보상

봇전은 학습용 모드이므로 반복 파밍 효율을 낮게 유지한다.

- 최초 클리어 보상 가능
- 난이도별 업적 가능
- 일일 소량 보상 가능
- MMR 반영 없음
- 시즌 등급 보상 없음

### 40.13. 보상 원칙

전투 성능에 영향을 주는 보상은 지급하지 않는다.

허용 보상:

- 프로필 장식
- 카드 프레임
- 이름 효과
- 전투 이모트
- 등장 연출
- 승리 연출
- 칭호
- 위키/도감용 수집 기록

금지 보상:

- 카드 능력 강화
- 추가 예산
- 유료 전용 키워드
- 덱 슬롯 전투 보너스
- 매칭 우대

### 40.14. 시즌 종료 후 노출

시즌 종료 후 유저에게 다음을 보여준다.

- 내 최종 MMR
- 내 시즌 최고 등급
- 내 최종 순위
- 지급 예정 보상
- 지급 완료 보상
- 보류 여부
- 다음 시즌 변경점 위키 링크

## 41. 튜토리얼과 온보딩

### 41.1. 목표

아레나는 룰이 많은 게임이므로 첫 경험에서 모든 규칙을 설명하면 안 된다. 튜토리얼은 플레이 중 필요한 순간에 하나씩 가르친다.

### 41.2. 튜토리얼 단계

| 단계 | 내용 |
|---|---|
| 1 | 6칸 필드와 라인 이해 |
| 2 | 손패에서 카드 배치 |
| 3 | 전열/후열 공격 순서 |
| 4 | 직접 공격 |
| 5 | 전술 이동 |
| 6 | 교체와 묘지 |
| 7 | 손패 8장 제한과 피로 피해 |
| 8 | 키워드 기본 |
| 9 | 빠른대전 준비 |
| 10 | 8인전 기본 흐름 |

### 41.3. 첫 플레이 권장 흐름

처음 온 유저에게는 다음 순서를 권장한다.

```text
튜토리얼 봇전 -> 추천 덱 생성 -> 일반 봇전 -> 덱 수정 -> 빠른대전
```

빠른대전을 바로 막지는 않지만, 튜토리얼 미완료 유저에게는 봇전을 강하게 추천한다.

### 41.4. 추천 덱

추천 덱은 유저가 보유한 카드 기준으로 자동 생성한다.

추천 덱 조건:

- 14장 이상
- 동일 스트리머 1장 제한 준수
- 1~3코스트 카드 최소 5장
- 7~9코스트 카드 과다 방지
- 클래스가 최소 4종 이상 섞이도록 권장

### 41.5. 도움말 방식

- 첫 실수는 경고보다 설명을 우선한다.
- 같은 실수를 반복하면 짧은 경고로 줄인다.
- 모든 도움말은 관련 위키 문서로 연결된다.
- 튜토리얼은 다시 볼 수 있어야 한다.

## 42. 운영과 어뷰징 정책

### 42.1. 시간 끌기

빠른대전에서 반복적으로 턴 시간을 모두 소모하는 유저는 어뷰징 점수를 받는다.

처리:

- 단발성 시간 초과는 패스 처리
- 반복 시간 초과는 경고
- 과도한 반복은 빠른대전 큐 제한

### 42.2. 탈주

빠른대전:

- 제한 시간 안에 복귀하면 진행 가능
- 장기 이탈은 자동 패스
- 반복 이탈은 패배 처리 또는 큐 제한 가능

8인전:

- 이탈자는 자동 패스
- 일정 라운드 이상 미복귀 시 탈락 처리
- 보상은 축소 가능

### 42.3. 담합

8인전은 담합 위험이 크다.

감지 지표:

- 같은 유저들끼리 반복 매칭
- 특정 상대에게 비정상적으로 약한 행동
- 비정상적인 패스 반복
- 시즌 포인트 교환 패턴

담합 의심 시 보상 지급을 보류할 수 있다.

### 42.4. 부계정과 MMR 조작

감지 지표:

- 같은 기기/네트워크 기반 반복 매칭
- 짧은 시간 내 특정 계정에 반복 패배
- 비정상적인 서렌더 또는 패스
- 랭킹권 계정과 신규 계정의 반복 매칭

처리:

- MMR 반영 보류
- 보상 보류
- 큐 제한
- 관리자 검토

### 42.5. 스트리머 카드 악용

스트리머 직접 설정에서 다음을 제한한다.

- 혐오/비방 문구
- 사칭
- 성인/폭력 이미지
- 룰을 오해하게 하는 카드 설명
- 외부 링크 유도
- 전투 성능이 있는 것처럼 보이는 코스메틱 설명

문제가 있는 카드는 즉시 비활성화할 수 있다.

### 42.6. 운영 로그

다음 이벤트는 감사 로그를 남긴다.

- 카드 비활성화
- 키워드 비활성화
- 카드 버전 강제 업데이트
- 보상 보류
- MMR 조정
- 큐 제한
- 시즌 종료 보상 지급
- 위키 문서 상태 변경

## 43. 시스템 연동 흐름

### 43.1. 시즌 오픈 전 흐름

```text
관리자 시즌 생성
-> 룰 버전 선택
-> 검증기 버전 선택
-> 카드 생성 버전 선택
-> 보상 정책 선택
-> 위키 변경점 준비
-> 시즌 예약
-> 시즌 오픈
```

시즌이 오픈되면 해당 시즌의 룰, 검증기, 카드 생성 버전, 보상 정책은 공식 모드 기준으로 고정된다.

### 43.2. 카드와 덱 흐름

```text
스트리머 카드 정의
-> 검증기 통과
-> 카드 버전 생성
-> 유저 덱 편성
-> 동일 스트리머 1장 제한 검증
-> 시즌 공식 모드 사용 가능
```

카드 버전이 검증기 위반 상태가 되면 덱은 공식 모드 진입 전에 최신 합법 버전으로 강제 전환되거나 사용 불가 상태가 된다.

### 43.3. 매치와 리플레이 흐름

```text
매치 생성
-> 덱/카드 버전 스냅샷
-> 멀리건
-> 턴 행동 제출
-> 서버 전투 판정
-> 리플레이 이벤트 저장
-> 매치 요약 저장
-> 7일 후 상세 리플레이 정리
```

리플레이가 삭제되어도 시즌 정산에 필요한 매치 요약과 MMR 변화 기록은 유지된다.

### 43.4. 랭킹과 보상 흐름

```text
빠른대전 완료
-> MMR 반영
-> 현재 등급 갱신
-> 시즌 최고 등급 갱신
-> 시즌 잠금
-> 랭킹 스냅샷 생성
-> 어뷰징 보류 계정 제외
-> 시즌 최고 등급 기준 보상 계산
-> 운영자 확인
-> 보상 지급
```

시즌 보상은 최종 MMR이 아니라 시즌 최고 등급 기준이다. 시즌 최고 등급은 빠른대전 MMR로만 결정한다.

### 43.5. 8인전과 보상 흐름

```text
8인전 참가
-> 라운드별 1:1 전투
-> 최종 순위 결정
-> 8인전 시즌 포인트 지급
-> 업적/참여 보상 반영
```

8인전 시즌 포인트는 빠른대전 MMR 등급 보상을 대체하지 않는다. 담합 위험이 있으므로 핵심 시즌 등급 보상은 빠른대전 MMR 기준으로 유지한다.

### 43.6. 위키와 라이브 운영 흐름

```text
룰/카드/시즌 변경 예정
-> 위키 문서 작성
-> 문서 상태: 검토 중 또는 확정 예정
-> 시즌 오픈 시 적용 중으로 전환
-> 변경 이력 유지
```

유저가 덱 오류, 전투 판정, 키워드 효과를 이해해야 할 때는 관련 위키 문서로 연결한다.

### 43.7. 운영 안전 흐름

```text
이상 징후 감지
-> 관리자 진단
-> 필요 시 kill switch
-> MMR/보상 보류
-> 감사 로그 기록
-> 조사 후 해제 또는 제재
```

운영 조치는 시즌 정산, 보상 지급, 카드 사용 가능 여부에 영향을 줄 수 있으므로 모두 감사 로그를 남긴다.

## 44. 최종 요약

```text
치카포 아레나는 기존 아레나 시스템을 폐기하고 새로 구현한다.

핵심 게임:
6칸 동시 배치형 스트리머 카드 오토배틀

모드:
봇전 / 빠른대전 / 8인 대전

체력:
모든 모드 기본 30

덱:
14~20장

손패:
시작 5장
최대 8장
초과 드로우는 묘지로 버림

턴:
40초
2턴부터 1장 드로우
코스트 1~9

필드:
전열 좌/중/우 + 후열 좌/중/우

행동:
배치 / 전술 이동 / 교체

전투:
전열 동시 공격 후 후열 동시 공격

라인 제한:
기본 공격, 도발, 조준, 밀치기, 끌어오기는 같은 라인 안에서만 작동

비주얼:
PixiJS 기반 상용 게임 수준 전투 화면
외부 VFX/애니메이션 라이브러리를 적극 사용
클래스/키워드별로 통일된 화려한 연출 제공

직접 공격:
전열 공격력만큼
후열 공격력 -1

승리:
체력 0 이하
9턴 종료 후 체력 우위
동률이면 10턴부터 서든데스

구현:
기존 아레나 데이터/API/렌더러/엔진 폐기
새 arena_v2 스키마와 순수 룰 엔진으로 전면 재구현
백업 후 스위치오버하고 기존 데이터는 폐기

시즌:
운영자가 관리자 탭에서 생성/예약/오픈/잠금/정산/종료
시즌별 룰 버전, 검증기 버전, 카드 생성 버전, 보상 정책 고정

랭킹/보상:
빠른대전 MMR 기준 등급 사용
시즌 최고 등급 기준으로 시즌 종료 보상 차등 지급
8인전 포인트는 별도 운영하고 핵심 등급 보상과 분리

리플레이:
상세 리플레이 보존 기간 7일
정산에 필요한 매치 요약과 MMR 기록은 유지

위키:
아레나 안에 읽기 전용 위키 제공
게임 플레이에 필요한 룰 문서만 정리
기술적 구현 문서는 위키에 노출하지 않음

추가 운영 기획:
카드 풀 자동 생성
밸런스 시뮬레이션
UX 플로우
비주얼 아트 디렉션
보상/랭킹/시즌
튜토리얼
어뷰징 대응
시스템 연동 흐름
```

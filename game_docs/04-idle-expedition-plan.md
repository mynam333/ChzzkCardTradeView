# 방치형 원정 게임 기획

## 1. 목표

방치형 원정은 `치카포 프론티어`의 1차 메인 콘텐츠다.

기본은 방치형 RPG지만, 클리커류 방치 게임의 장점을 차용한다. 유저가 접속하지 않아도 원정은 진행된다. 다만 접속해서 상황을 보고 개입하면 더 빠르게 돌파하고, 더 좋은 보상을 얻고, 어디에서 막혔는지 이해할 수 있어야 한다.

핵심 목표:

- 오프라인 상태에서도 원정이 진행된다.
- 접속 중에는 탭/응원/스킬 개입/돌발 선택으로 더 큰 이득을 얻는다.
- 진행 상황을 실시간처럼 볼 수 있다.
- 어느 구간, 어떤 적, 어떤 조건에서 막히는지 알 수 있다.
- 서버는 유저별 실시간 tick을 돌리지 않는다.
- 실시간 화면은 클라이언트 예측과 서버 체크포인트를 결합한다.

## 2. 기본 플레이 흐름

1. 유저가 원정 화면에 진입한다.
2. 지역과 난도를 선택한다.
3. 원정 시간을 선택한다.
4. 보유 카드 4장으로 파티를 편성한다.
5. 서버가 파티 스냅샷, seed, 진행 경로를 저장한다.
6. 유저가 접속 중이면 진행 상황 화면에서 파티가 이동/전투/이벤트를 수행하는 모습을 본다.
7. 유저는 응원 클릭, 집중 지원, 돌발 선택, 수동 스킬 트리거로 진행을 도울 수 있다.
8. 접속을 종료해도 원정은 오프라인 기준으로 계속 진행된다.
9. 완료 시 결과를 수령하고 보상을 받는다.
10. 결과 화면에서 어느 단계에서 시간을 많이 썼는지, 실패 요인이 무엇이었는지 확인한다.

## 3. 게임 감각

이 게임은 완전 자동 방치형과 클리커형 활동 보너스 사이에 위치한다.

유저 경험:

- “내 파티가 지금 어디쯤 가고 있는지 보인다.”
- “접속해서 응원하면 막힌 구간을 밀 수 있다.”
- “무조건 클릭 노동을 해야 하는 게임은 아니다.”
- “방치해도 보상은 받지만, 신경 쓰면 효율이 오른다.”
- “실패했을 때 왜 실패했는지 알 수 있다.”

금지 방향:

- 계속 클릭하지 않으면 손해가 너무 큰 구조
- 접속 유지가 사실상 필수인 구조
- 클라이언트 클릭 수를 그대로 신뢰하는 구조
- 실시간 서버 전투를 유저마다 계속 돌리는 구조

## 4. 원정 시간과 활동 보너스

1차 추천 시간:

- 15분: 짧은 접속 루프
- 1시간: 일반 회전 루프
- 4시간: 반나절 루프
- 8시간: 취침/업무 루프

| 시간 | 목적 | 방치 보상 | 접속 개입 이득 | 역할 기여 방향 |
| --- | --- | --- | --- | --- |
| 15분 | 짧은 루프 | 낮은 재료, 빠른 시즌 점수 | 진행 가속, 대성공 확률 상승 | 모든 역할 기여, 전투/속도 축 체감 큼 |
| 1시간 | 기본 원정 | 표준 재료 | 돌발 선택, 보상 슬롯 강화 | 전투/생존/탐사 균형 확인 |
| 4시간 | 장기 원정 | 희귀 재료 기회 | 막힘 구간 구조, 안정도 회복 | 생존/상태/탐사 축 체감 큼 |
| 8시간 | 긴 방치 | 안정 보상, 큰 실패 리스크 | 초반 세팅/중간 구조 신호 대응 | 모든 축이 누적 검정됨 |

접속 개입 이득은 원정 시간이 짧을수록 체감이 크고, 긴 원정에서는 실패 완화와 희귀 이벤트 대응 중심으로 둔다.

## 5. 파티 크기

1차 파티 크기는 4장을 권장한다.

이유:

- 모바일 UI에서 보기 좋다.
- 역할 조합이 생긴다.
- 5장보다 밸런스 계산이 쉽다.
- 3장보다 카드 수집 이유가 강하다.

확장:

- 일부 고난도 지역은 5장 파티 허용
- 일부 빠른 원정은 3장 파티 제한 가능
- 오토리그는 6~8장으로 별도 확장 가능

## 6. 진행 구조

원정은 하나의 타이머가 아니라 여러 `단계`로 구성된다.

예:

1. 출발
2. 일반 전투
3. 탐사 이벤트
4. 정예 전투
5. 휴식/회복
6. 보상 이벤트
7. 보스 또는 최종 장애물
8. 귀환

각 단계는 다음 정보를 가진다.

- `stage_index`
- `stage_type`: travel/combat/elite/event/rest/boss/return
- `expected_duration_ms`
- `required_scores`
- `score_axis_weights`
- `risk_tags`
- `reward_chance`
- `failure_reason_candidates`

서버는 원정 시작 시 seed 기반으로 단계 목록을 생성한다. 클라이언트는 이 단계 목록을 받아 진행 상황을 시각화한다.

## 7. 실시간 진행 보기

### 7.1 화면 구성

진행 화면은 “전투가 실시간 서버에서 돌아가는 화면”이 아니라 “서버가 만든 경로를 클라이언트가 재생하고, 주기적으로 서버 체크포인트와 맞추는 화면”이다.

표시 요소:

- 현재 지역과 원정 시간
- 진행률 바
- 현재 단계
- 남은 예상 시간
- 파티 카드 4장
- 각 카드의 현재 상태
- 발동 중인 패시브
- 누적 보상 후보
- 위험 신호
- 막힘 원인 표시

### 7.2 카드 상태

각 카드는 아래 상태를 가진다.

- 체력 안정
- 보호막
- 피로도
- 버프
- 디버프
- 기여도
- 다음 행동 예상

이 상태는 실시간 서버 상태가 아니라 스냅샷과 seed로 계산된 예측 상태다. 서버 체크포인트에서 검증 가능한 값만 최종 반영한다.

### 7.3 진행 단계 표시

단계 예시:

- `1/8 출발 준비`
- `2/8 폐방송국 복도 전투`
- `3/8 장비 고장 이벤트`
- `4/8 정예 오류체 교전`
- `5/8 야영 회복`
- `6/8 숨은 보급품 발견`
- `7/8 잔류 신호 보스`
- `8/8 귀환`

유저는 어느 단계에서 시간이 오래 걸리는지, 어떤 피해가 누적되는지 볼 수 있다.

## 8. 막힘 진단 시스템

실패하거나 진행이 느려질 때 유저가 이유를 알아야 한다.

### 8.1 막힘 유형

- `화력 부족`: 전투 점수가 부족해 전투 시간이 길어짐
- `생존 부족`: 체력/방어/회복이 낮아 사고 피해가 큼
- `정화 부족`: 상태이상 또는 디버프에 오래 묶임
- `탐사 부족`: 이벤트 보상 획득 실패
- `속도 부족`: 이동/행동 속도가 낮아 원정 시간이 길어짐
- `기여 축 불균형`: 전투/생존/상태/탐사/변수 중 특정 축이 부족함
- `성장 축 과밀`: 고성 카드 또는 같은 효과 축이 몰려 점감 발생
- `패시브 충돌`: 선택한 패시브가 지역과 맞지 않음

### 8.2 진단 표시

진행 중:

- `정예 전투에서 화력이 부족합니다`
- `정화 역할이 없어 중독 시간이 길어졌습니다`
- `탐사 기여가 낮아 숨은 보급품을 놓쳤습니다`
- `지원 카드가 없어 장기 원정 피로도가 빠르게 쌓입니다`

결과 후:

- 가장 오래 걸린 단계
- 가장 큰 피해를 받은 단계
- 발동하지 못한 패시브
- 추천 보완 역할
- 추천 자동 편성 버튼

### 8.3 개선 제안

결과 화면은 단순 실패가 아니라 다음 행동을 제안한다.

예:

- `선봉 또는 지원 클래스를 1장 추가하면 안정 점수가 크게 오릅니다.`
- `이번 단계는 상태 대응/전략 판정 비중이 높았습니다.`
- `정화 패시브가 있으면 3단계 상태이상 지연을 줄일 수 있습니다.`
- `15분 원정은 속공 카드가 많을수록 효율이 좋습니다.`

## 9. 접속 중 활동 시스템

접속 중 유저는 원정을 도울 수 있다.

중요 원칙:

- 활동은 보너스다.
- 방치 보상을 무효화하지 않는다.
- 클릭 수를 그대로 보상으로 환산하지 않는다.
- 하루/원정별 활동 상한을 둔다.

### 9.1 응원 탭

가장 기본적인 클리커형 행동이다.

- 화면의 `응원` 버튼을 누르면 응원 게이지가 오른다.
- 게이지가 차면 `집중 지원`을 1회 발동할 수 있다.
- 빠른 연타보다 일정한 참여를 권장한다.
- 초당 인정 횟수와 원정당 총 인정량 상한을 둔다.

효과 후보:

- 현재 단계 진행 속도 증가
- 다음 전투 첫 행동 게이지 증가
- 파티 보호막 소량 부여
- 대성공 확률 소폭 증가

### 9.2 집중 지원

응원 게이지를 소모하는 수동 개입이다.

지원 타입:

- `공격 지원`: 현재 전투 단계 진행량 증가
- `방어 지원`: 다음 피해 일부 감소
- `회복 지원`: 파티 피로도/체력 일부 회복
- `탐사 지원`: 이벤트 판정 보정
- `정화 지원`: 상태이상 지속시간 감소

지원 타입은 파티에 없는 역할을 임시로 보완하는 느낌을 준다. 단, 부족한 역할을 완전히 대체하면 안 된다.

### 9.3 돌발 선택

원정 중 특정 단계에서 선택지가 뜬다.

예:

- `낡은 장비를 수리한다`: 방어/공명 필요, 성공 시 안정 보상
- `숨은 신호를 추적한다`: 기교/탐사 필요, 성공 시 희귀 재료 기회
- `정면 돌파한다`: 공격/체력 필요, 성공 시 시간 단축
- `우회한다`: 속도/전략 필요, 실패 리스크 감소

접속 중이면 유저가 직접 선택한다. 오프라인이면 파티 성향에 따라 자동 선택한다.

### 9.4 수동 스킬 트리거

일부 클래스는 접속 중 수동 트리거 보너스를 받을 수 있다.

예:

- 철벽 진행자: 위험 단계에서 보호막 강화
- 단일 저격수: 정예/보스 단계에서 집중 사격
- 힐링 매니저: 파티 체력이 낮을 때 회복 증폭
- 지도 제작자: 이동 단계에서 우회 경로 선택

수동 트리거는 클래스의 기본 성능을 대체하지 않고, 타이밍 보너스로만 둔다.

## 10. 활동 자원

클리커형 개입을 무한정 허용하면 접속 강제가 된다. 따라서 활동 자원을 둔다.

### 10.1 응원 에너지

- 접속 중 천천히 회복
- 탭으로 채우되 초당 인정 상한 적용
- 원정마다 최대 사용량 제한
- 하루 전체 사용량 제한 가능

### 10.2 집중 토큰

- 응원 게이지가 꽉 차면 생성
- 원정당 3~5개까지 사용
- 원정 시간에 따라 최대치 다름

권장:

- 15분 원정: 2개
- 1시간 원정: 3개
- 4시간 원정: 4개
- 8시간 원정: 5개

### 10.3 구조 신호

막힘 상태가 일정 시간 지속되면 사용할 수 있는 구제 자원이다.

- 하루 제한
- 실패 직전 원정에 사용 가능
- 보상 증가가 아니라 실패 완화 중심

## 11. 접속 보너스 설계

접속 보너스는 크게 4종이다.

### 11.1 속도 보너스

원정 단계를 빠르게 넘긴다.

- 짧은 원정에서 체감이 크다.
- 총 시간 단축 상한은 10~15%를 넘기지 않는다.
- `빠른 루트`, `지도 제작자`와 합산 상한을 공유한다.

### 11.2 안정 보너스

피해, 피로, 상태이상 시간을 줄인다.

- 긴 원정에서 유리하다.
- 실패를 성공으로 바꾸기보다는 실패를 부분 성공으로 완화하는 역할이 좋다.

### 11.3 보상 보너스

대성공 확률, 이벤트 보상 판정, 시즌 점수를 소폭 올린다.

- 직접 재료 보상 증가는 상한을 둔다.
- 보상형 패시브와 합산 상한을 공유한다.

### 11.4 정보 보너스

접속 중 유저는 더 많은 정보를 본다.

- 다음 위험 단계 예고
- 추천 개입 타입
- 현재 막힘 원인
- 보상 이벤트 힌트

정보 보너스는 경제를 망치지 않으면서 접속 가치를 높일 수 있다.

## 12. 원정 지역

### 12.1 폐방송국

- 콘셉트: 오래된 방송 장비와 오류가 남은 안정형 지역
- 판정 비중: 생존 유지 높음, 전투/상태/탐사도 함께 필요
- 위험: 장기 전투, 누적 피해
- 주요 보상: 기본 재료, 안정 성장 재료
- 특수 이벤트: 장비 고장, 구조 요청, 잔류 신호

접속 개입:

- 장비 고장 단계에서 `방어 지원` 또는 `정화 지원` 유리
- 정예 전투에서 `회복 지원` 가치 높음
- 막힘 진단은 생존/정화 부족 중심

### 12.2 알고리즘 숲

- 콘셉트: 추천 알고리즘이 뒤엉킨 미로형 지역
- 판정 비중: 상태 대응과 변수/고점 높음, 생존/탐사도 함께 필요
- 위험: 무작위 상태이상, 경로 변경
- 주요 보상: 전략 재료, 시즌 조사 점수
- 특수 이벤트: 추천 경로, 숨은 루트, 알고리즘 왜곡

접속 개입:

- 돌발 선택 비중 높음
- `탐사 지원`, `정화 지원` 유리
- 막힘 진단은 역할 불일치/정화 부족 중심

### 12.3 신호 폭풍항

- 콘셉트: 방송 신호와 항로가 파도처럼 요동치는 항구
- 판정 비중: 전투 돌파와 속도 높음, 생존/탐사도 함께 필요
- 위험: 짧고 강한 전투, 보상 변동
- 주요 보상: 공격 재료, 거래형 재료
- 특수 이벤트: 급등 파도, 급락 소용돌이, 상인 조우

접속 개입:

- `공격 지원`으로 정예 전투를 빠르게 넘기는 재미
- 빠른 탭 보너스 체감이 가장 큼
- 막힘 진단은 화력/속도 부족 중심

### 12.4 팬덤 광장

- 콘셉트: 응원과 이벤트가 열리는 커뮤니티형 지역
- 판정 비중: 탐사/보상과 지원 높음, 전투/전략도 함께 필요
- 위험: 전투보다 선택 이벤트 중심
- 주요 보상: 시즌 점수, 꾸미기 재료, 칭호 재료
- 특수 이벤트: 응원전, 부스 지원, 팬미팅 준비

접속 개입:

- 응원 탭 효율이 다른 지역보다 좋음
- 돌발 선택 성공 시 시즌 점수 증가
- 막힘 진단은 탐사/공명 부족 중심

### 12.5 심야 송출탑

- 콘셉트: 밤마다 강해지는 고난도 탑
- 판정 비중: 모든 축이 높은 종합 고난도
- 위험: 강한 보스 이벤트, 상태이상, 실패 리스크
- 주요 보상: 희귀 재료, 고급 성장 재료
- 특수 이벤트: 심야 패턴, 송출 왜곡, 보스 난입

접속 개입:

- 위험 단계 예고가 중요
- `정화 지원`, `방어 지원`, `공격 지원` 타이밍 선택
- 막힘 진단은 생존/정화/화력 복합

## 13. 결과 계산 구조

결과는 크게 5개 점수로 계산한다.

### 13.1 전투 점수

전투 성공 가능성을 나타낸다.

영향 요소:

- 공격, 방어, 체력
- 전투 돌파/생존 유지 관련 역할군
- 지역 적합도
- 별 등급
- 클래스/스탯/별 등급 보정
- 전투형 패시브
- 접속 중 공격 지원

### 13.2 안정 점수

실패율과 사고 이벤트 피해를 줄인다.

영향 요소:

- 체력, 방어, 공명
- 생존 유지 관련 역할군
- 회복/보호/정화 패시브
- 장시간 원정 보정
- 접속 중 방어/회복/정화 지원

### 13.3 탐사 점수

보상 슬롯, 특수 이벤트, 시즌 조사 점수에 영향을 준다.

영향 요소:

- 속도, 기교, 공명
- 탐사/전략 관련 역할군
- 보상/시간/시즌 패시브
- 지역별 특화 클래스
- 접속 중 탐사 지원

### 13.4 변수 점수

무작위 고점과 저점을 만든다.

영향 요소:

- 기교
- 술식/변수 패시브
- 위험형 패시브
- 지역 이벤트 seed
- 돌발 선택 결과

### 13.5 참여 점수

접속 중 활동을 반영한다.

포함:

- 인정된 응원 탭
- 집중 지원 사용
- 돌발 선택 참여
- 수동 스킬 트리거
- 위험 단계 대응

참여 점수는 대성공 확률, 진행 속도, 일부 이벤트 판정에만 영향을 준다. 기본 보상 자체를 과하게 늘리면 접속 강제가 된다.

## 14. 성공률 설계

원정은 4단계 결과로 나눈다.

- 대성공: 기본 보상 + 추가 슬롯 + 시즌 점수 보너스
- 성공: 기본 보상
- 부분 성공: 기본 보상 일부
- 실패: 낮은 보상 또는 안전 귀환 효과만 적용

권장 초기 확률:

- 적정 파티 방치 성공률: 70~85%
- 모든 판정 축이 고르게 충족될 때 방치 성공률: 80~92%
- 접속 개입을 적절히 했을 때: 대성공 확률 +5~15%
- 부적합 파티: 45~65%
- 고난도 지역: 35~75%

실패가 너무 많으면 방치형 피로감이 커진다. 실패해도 일부 보상은 주는 편이 좋다.

## 15. 보상 설계

### 15.1 보상 종류

- 기본 재료
- 역할군 재료
- 지역 재료
- 시즌 조사 점수
- 장비 파편
- 꾸미기 재료
- 낮은 확률의 희귀 재료

### 15.2 접속 활동 보상

접속 활동은 별도 “참여 보상”을 조금 준다.

예:

- 응원 참여 보상: 낮은 양의 프론티어 토큰
- 돌발 선택 성공 보상: 시즌 조사 점수
- 막힘 단계 구조 성공: 실패 보상 보존
- 수동 스킬 적중: 대성공 확률 증가

주의:

- 접속 활동만으로 반복 파밍 가능한 포인트 지급 금지
- 프론티어 전용 재화도 일일 상한 필요
- 클릭 수와 보상량 직접 비례 금지

### 15.3 포인트 보상

포인트는 기존 경제와 연결되어 있어 조심해야 한다.

권장:

- 기본 원정 보상으로 대량 포인트 금지
- 이벤트/업적/시즌 정산으로 제한적 지급
- 포인트 대신 프론티어 전용 재화 사용

### 15.4 보상형 패시브 상한

보상형 패시브는 아래 상한을 둔다.

- 추가 보상 슬롯: 파티당 최대 1개
- 시간 단축: 총합 최대 10~15%
- 희귀 재료 확률 증가: 곱연산 금지, 합연산 상한
- 실패 보상 보존: 최대 50% 이하
- 접속 보너스와 보상형 패시브는 같은 상한을 공유

## 16. 서버 정산 방식

### 16.1 원정 시작

서버 저장값:

- `expedition_id`
- `user_id`
- `region_id`
- `duration_minutes`
- `started_at`
- `finishes_at`
- `party_snapshot_json`
- `route_snapshot_json`
- `seed`
- `activity_summary_json`
- `checkpoint_json`
- `status`: started

`party_snapshot_json`에는 시작 당시 카드의 클래스, 스탯, 패시브, 별 등급을 복사한다. 시세는 프론티어 계산에 포함하지 않는다.

`route_snapshot_json`에는 단계 목록과 각 단계의 기본 요구치를 저장한다.

### 16.2 진행 중 조회

서버는 매초 계산하지 않는다.

진행 화면 조회 시:

- 현재 서버 시간 기준 예상 단계 계산
- 최근 activity summary 반영
- checkpoint 반환
- 클라이언트는 checkpoint 사이를 애니메이션으로 재생

권장 API:

- `GET /api/frontier/expeditions/:id/progress`

응답:

- 현재 단계
- 진행률
- 예상 남은 시간
- 위험 신호
- 발동 가능한 개입
- 최근 로그
- 서버 체크포인트 버전

### 16.3 활동 입력

클라이언트는 클릭 하나하나를 매번 서버에 보내지 않는다.

권장:

- 3~5초 단위로 활동 묶음 전송
- 서버는 인정 가능한 상한만 반영
- 비정상 속도/패턴은 무시
- 결과 계산에는 서버가 인정한 activity summary만 사용

권장 API:

- `POST /api/frontier/expeditions/:id/activity`

payload:

- `tap_count`
- `support_type`
- `manual_trigger`
- `event_choice`
- `client_elapsed_ms`

서버 반영:

- 초당 인정 탭 수 제한
- 원정당 최대 참여 점수 제한
- 지원 토큰 보유량 확인
- 이벤트 선택 유효성 확인

### 16.4 오프라인 진행

유저가 접속하지 않으면 서버는 결과 수령 시 한 번에 계산한다.

계산 방식:

- 시작 시각과 종료 시각
- route snapshot
- party snapshot
- seed
- 저장된 activity summary

접속 중 화면에서 본 진행과 최종 결과가 크게 어긋나면 안 된다. 클라이언트 예측 공식은 서버 공식의 표시용 근사치로 둔다.

### 16.5 결과 수령

`finishes_at` 이후 유저가 결과 수령 API를 호출한다.

서버는:

1. 원정 소유권 확인
2. 상태 확인
3. seed, snapshot, activity summary로 결과 계산
4. 보상 지급
5. 상태 completed로 변경
6. 결과 로그 저장

결과 수령은 멱등 처리해야 한다. 같은 원정에서 보상이 2회 지급되면 안 된다.

## 17. 진행 로그

진행 로그는 유저가 상황을 이해하게 만드는 핵심 UI다.

로그 예시:

- `00:12 철벽 진행자가 장비 폭주 피해를 막았습니다.`
- `00:18 정화 역할이 없어 중독 시간이 8초 늘어났습니다.`
- `00:24 응원 지원으로 정예 전투 진행도가 6% 증가했습니다.`
- `00:31 보물 탐색가가 숨은 보급품을 발견했습니다.`
- `00:45 화력이 부족해 정예 오류체 전투가 지연되고 있습니다.`

로그는 모든 내부 계산을 노출하지 않는다. 유저가 다음 행동을 이해할 만큼만 보여준다.

## 18. 원정 취소

원정 취소는 단순하게 시작한다.

권장:

- 시작 후 1분 이내 무료 취소
- 이후 취소 시 보상 없음
- 이미 완료 가능한 원정은 취소 불가

취소 보상을 넣으면 어뷰징 경로가 늘어난다.

## 19. 자동 편성

유저 편의를 위해 자동 편성을 제공한다.

모드:

- 안정형: 선봉/지원 우선
- 빠른 원정형: 속공/타격 우선
- 보상형: 탐사/전략 우선
- 보스형: 단일 딜/표식/지원 우선
- 균형형: 역할군 다양성 우선
- 접속 플레이형: 속공/수동 트리거/탐사 이벤트 대응 우선
- 완전 방치형: 안정/회복/실패 완화 우선

자동 편성은 최적해가 아니라 입문용이어야 한다. 고급 유저가 직접 조합할 여지는 남긴다.

## 20. 원정 결과 화면

결과 화면에 보여줄 것:

- 파티 카드 4장
- 성공/대성공/부분 성공/실패
- 획득 보상
- 클래스별 기여
- 접속 활동 기여
- 발동한 패시브
- 지역 이벤트
- 가장 오래 걸린 단계
- 가장 위험했던 단계
- 막힘 원인
- 다음 추천 원정

기여 표시는 딜량만 보여주면 안 된다.

기여 항목:

- 피해
- 보호
- 회복
- 방해
- 탐사
- 보상 발견
- 시간 단축
- 응원/지원 기여
- 실패 완화

## 21. 1차 출시 지역 난도

초기 난도:

- 폐방송국: 쉬움
- 팬덤 광장: 쉬움
- 신호 폭풍항: 보통
- 알고리즘 숲: 보통
- 심야 송출탑: 어려움

각 지역은 쉬움/보통/어려움 난도를 나중에 확장한다.

## 22. 1차 출시 권장 범위

포함:

- 원정 단계 시각화
- 진행률/현재 단계/위험 신호
- 응원 탭
- 집중 지원 5종
- 돌발 선택 일부
- 막힘 진단
- 결과 로그
- 접속 활동 상한
- 서버 체크포인트 API

나중으로 미룰 것:

- 복잡한 수동 스킬 애니메이션
- 모든 클래스별 고유 수동 트리거
- 실시간 멀티 협동
- PvP 실시간 전투
- 무한 클릭 성장

## 23. 확장 후보

- 원정 중 희귀 보스 난입
- 친구 카드 지원 요청
- 특정 단계에서 미니게임식 짧은 판정
- 시즌별 접속 이벤트
- 지역별 일일 변동 버프

- 파티 리더 수동 스킬
- 방치 중 위험 알림 푸시

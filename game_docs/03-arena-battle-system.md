# 치카포 아레나 전투 시스템 상세 기획서

## 1. 목적

이 문서는 치카포 아레나의 전투 규칙을 구현 가능한 수준으로 정의한다. 전투 시스템은 카드 생성, 클래스/스킬, 밸런스 검증, 리플레이, MMR 산정, 서버 부하 정책의 기준이 된다.

치카포 아레나는 실시간 조작 게임이 아니다. 유저는 전투 전에 덱과 라운드별 전술 플랜을 결정하고, 서버는 5판 3선승 세트 매치를 deterministic simulation으로 계산한다. 클라이언트는 서버가 저장한 세트 전투 로그를 리플레이로 재생한다.

핵심 원칙:

- 전투는 서버에서만 판정한다.
- 클라이언트는 전투 결과를 계산하지 않는다.
- 같은 입력과 같은 seed는 항상 같은 결과를 만든다.
- 세트 매치는 7~12분 체감 플레이 시간을 목표로 하되, 서버 계산은 짧고 예측 가능한 CPU/메모리 비용 안에서 끝나야 한다.
- 치카포 시세, 팔로워, 방송 중 여부, 채팅량, 포인트, 카드 보유량은 전투력에 영향을 주지 않는다.

## 2. 전투 장르 정의

치카포 아레나의 전투는 카드형 자동 전투다.

유저가 하는 일:

- 전체 활성 카드 확인
- 덱 구성
- 카드 배치
- 시너지와 카운터 고려
- 빠른대전 또는 봇 연습전 시작
- 전투 리플레이 확인

서버가 하는 일:

- 덱 유효성 검증
- 비활성 카드 사용 차단
- 전투 seed 생성
- 자동 전투 시뮬레이션
- 결과와 전투 로그 저장
- MMR 변화 계산

클라이언트가 하는 일:

- 전투 전 덱/배치 UI 제공
- 매칭 상태 표시
- 전투 로그 기반 리플레이 재생
- 결과, 보상, 랭킹 변화 표시

## 3. 전투 단위

### 3.1 매치

매치는 두 플레이어 또는 플레이어와 봇 사이의 5판 3선승 세트다. 한 매치는 최대 5개 라운드로 구성되며, 먼저 3개 라운드를 승리한 쪽이 매치에서 승리한다.

매치 유형:

- `RANKED`: MMR이 반영되는 빠른대전
- `CASUAL`: MMR이 반영되지 않는 일반전
- `BOT_PRACTICE`: AI 봇 연습전
- `CUSTOM`: 커스텀 룸 또는 이벤트전

### 3.2 라운드

라운드는 실제 자동 전투가 벌어지는 최소 단위다.

MVP부터 빠른대전은 5판 3선승을 기본으로 한다. 라운드 사이에는 제한 시간 안에서 전술을 직접 수정할 수 있고, 입력하지 않으면 저장된 기본 플랜 또는 직전 유효 선택으로 자동 진행한다. 서버는 매칭 성사 시 덱/전장/시드만 고정하고, 각 라운드 커밋 시점마다 필요한 라운드만 순서대로 시뮬레이션한다.

라운드 결과:

- `WIN`
- `LOSS`
- `DRAW`

무승부 라운드는 어느 쪽도 라운드 승점을 얻지 않는다. 3라운드 종료 후에도 양쪽 라운드 승수가 같으면 세트 타이브레이커 규칙으로 매치 승자를 결정한다.

### 3.3 전투 시간

각 라운드는 시뮬레이션 시간 기준으로 최대 45초를 권장한다. 세트 전체는 최대 5라운드이지만, 실제 서버 계산은 tick을 빠르게 순회하므로 짧고 예측 가능한 시간 안에 끝나야 한다.

권장값:

```text
ROUND_TIME_LIMIT_MS = 45_000
TICK_MS = 250
MAX_ROUND_TICKS = 180
MAX_ROUNDS_PER_MATCH = 5
ROUNDS_TO_WIN = 3
TARGET_USER_FACING_MATCH_TIME = 7~12분
```

서버는 라운드별 최대 tick 수를 넘기면 즉시 해당 라운드를 종료하고 판정 규칙에 따라 라운드 승패 또는 무승부를 결정한다. 한쪽이 3라운드를 먼저 이기면 남은 라운드는 계산하지 않는다.

### 3.4 세트 매치 체감 시간

유저가 체감하는 한 게임의 목표 시간은 7~12분이다.

권장 리플레이 템포:

- 3:0 종료: 약 6~8분
- 3:1 종료: 약 8~10분
- 3:2 종료: 약 10~12분
- 라운드 사이 결과 연출: 8~12초
- 기본 재생 속도: 1.25x 또는 1.5x
- 결과만 보기 제공

서버는 세트 전체를 미리 계산하지 않는다. 매치 생성 시 덱 스냅샷, 전장, 시드만 고정하고, 각 라운드 시작 전 유저가 선택한 전술을 받아 해당 라운드만 확정한다. 클라이언트는 확정된 라운드 리플레이를 순서대로 재생해 실시간 전투처럼 체감시키되, 서버가 장시간 매치룸을 붙잡고 있지 않는 구조를 유지한다.

### 3.5 라운드별 전술 플랜

5판 3선승의 전략성을 위해 덱은 최대 5개의 전술 플랜을 가진다.

전술 플랜 구성:

```text
round_no
formation
tactic_style
focus_rule
reserved_cards
```

권장:

- 1라운드: 기본 플랜
- 2라운드: 상대 전열 대응 또는 안정 플랜
- 3라운드: 중반 대응 플랜
- 4라운드: 역전 또는 굳히기 플랜
- 5라운드: 최종 승부수 플랜

MVP에서는 라운드 사이에 제한 시간 안에서만 직접 수정할 수 있다. 입력하지 않은 유저는 저장된 기본 플랜이나 직전 유효 선택으로 자동 진행한다. 이 방식은 5판 3선승의 깊이를 주면서도 서버가 상주 매치 상태를 오래 유지하지 않게 해준다.

### 3.6 라운드별 직접 전술 선택

라운드별 직접 전술 선택은 5판 3선승의 핵심 전략 장치다. 밴픽과 복잡한 자동 조건식은 사용하지 않는다.

선택 참고 정보:

- 직전 라운드 승패
- 현재 세트 스코어
- 공개된 라운드 요약
- 적용 전장 규칙
- 자신의 예비 카드와 전술 칩

선택 결과:

- 다음 라운드 출전 6장 선택
- 배치 선택
- 타겟 우선순위 선택
- 전술 성향 선택

금지:

- 라운드 사이 무제한 입력 대기
- 상대 카드를 금지하거나 제거하는 밴픽
- 상대 비공개 세부 정보를 보고 후처리 선택
- 조건 판정에 DB 추가 조회가 필요한 자동 플랜 구조

### 3.7 전술 칩과 전장 규칙

전술 칩은 덱당 1개 장착하는 공용 전략 옵션이다. 전장 규칙은 매치마다 양쪽에 동일하게 적용되는 가벼운 시즌 룰이다.

원칙:

- 치카포 본편 자산과 연결하지 않는다.
- 모든 전술 칩과 전장 규칙은 파워 예산과 밸런스 검증 대상이다.
- 시즌 로테이션 카드 풀은 사용하지 않는다.
- 문제가 생기면 관리자 kill switch로 비활성화할 수 있어야 한다.
## 4. 보드 구조

### 4.1 기본 보드

MVP 기본 보드는 2행 x 4열, 총 8칸을 권장한다.

```text
후열: [0,0] [0,1] [0,2] [0,3]
전열: [1,0] [1,1] [1,2] [1,3]
```

각 플레이어는 자기 진영의 8칸에 카드를 배치한다.

전투 시뮬레이션에서는 두 진영을 마주보게 배치한다.

```text
Player A 후열  A0 A1 A2 A3
Player A 전열  A4 A5 A6 A7

Player B 전열  B4 B5 B6 B7
Player B 후열  B0 B1 B2 B3
```

### 4.2 좌표

서버 내부 좌표는 플레이어 기준 좌표와 전장 기준 좌표를 분리한다.

플레이어 기준:

```text
row: 0 = 후열, 1 = 전열
col: 0~3
```

전장 기준:

```text
x: 0~3
y: 0~3
```

전장 기준 변환은 리플레이와 타겟팅 계산에서만 사용한다. 저장되는 덱 배치는 플레이어 기준 좌표를 사용한다.

### 4.3 배치 제한

MVP 권장:

- 덱 최대 8장
- 출전 카드 최대 6장
- 라운드별 전술 플랜 최대 5개
- 각 라운드 플랜은 같은 덱 10장 안에서 출전 6장과 배치를 선택
- 빈 칸 허용
- 같은 스트리머 카드 중복 편성 금지
- 같은 클래스 중복은 허용하되 시너지 효율 제한 가능
- 비활성화 카드 편성 금지

출전 카드 수를 6장으로 제한하는 이유:

- 전투 로그 크기 감소
- 시뮬레이션 비용 감소
- 모바일 리플레이 시인성 확보
- 덱 빌딩 판단 부담 완화

출전 수는 6장을 유지한다. 5판 3선승 구조에서는 출전 수를 늘리면 라운드 계산량과 로그 크기가 커지므로, 전략성은 출전 수 증가가 아니라 예비 카드, 라운드별 직접 선택, 전술 칩, 전장 규칙으로 만든다.

## 5. 카드 전투 스탯

### 5.1 기본 스탯

각 카드는 다음 전투 스탯을 가진다.

```text
hp
attack
defense
attack_speed
range
crit_chance
crit_damage
energy_gain
skill_cost
status_resist
```

스탯 설명:

- `hp`: 최대 체력
- `attack`: 기본 공격력
- `defense`: 피해 감소에 사용되는 방어력
- `attack_speed`: 초당 공격 횟수 기준값
- `range`: 공격 가능 거리
- `crit_chance`: 치명타 확률
- `crit_damage`: 치명타 피해 배율
- `energy_gain`: 공격/피격/시간 경과로 얻는 에너지 보정
- `skill_cost`: 액티브 스킬 발동에 필요한 에너지
- `status_resist`: 상태이상 저항 확률

### 5.2 스탯 범위

MVP에서는 스탯 범위를 좁게 유지한다.

권장 기준:

```text
hp: 700~1800
attack: 60~180
defense: 0~80
attack_speed: 0.6~1.6
range: 1~4
crit_chance: 0~0.25
crit_damage: 1.5~2.0
energy_gain: 0.8~1.3
skill_cost: 80~140
status_resist: 0~0.35
```

스탯은 카드별 자유 입력이 아니라 스탯 프로필과 파워 예산으로 산출한다.

### 5.3 전투 중 파생값

전투 중 상태:

```text
current_hp
current_energy
shield
alive
position
attack_cooldown_ms
statuses
summons_owned
damage_dealt
damage_taken
healing_done
```

이 값은 전투 로그와 결과 요약에 사용된다.

## 6. 전투 시작 절차

서버는 세트 매치 시작 시 다음 순서로 처리한다.

1. 매치 유형 확인
2. 시즌 상태 확인
3. 양쪽 덱 스냅샷 로드
4. 카드 출전 가능 여부 검증
5. 라운드별 전술 플랜 검증
6. 카드 능력 버전 고정
7. 세트 seed 생성
8. 1라운드 상태 초기화
9. 라운드별 시너지 적용
10. 라운드 시작 효과 처리
11. tick 시뮬레이션 시작
12. 라운드 종료 후 세트 승수 확인
13. 필요하면 다음 라운드 시뮬레이션
14. 세트 결과 저장

### 6.1 덱 스냅샷

전투 중에는 원본 카드 데이터를 다시 조회하지 않는다. 전투 시작 전에 필요한 모든 데이터를 덱 스냅샷에 고정한다.

덱 스냅샷 포함 데이터:

```text
channel_id
display_name
image_url
role_id
class_id
stat_profile_id
base_stats
active_skill
passive_skill
synergy_tags
position
round_plans
card_version
cosmetic_refs
```

전투 스냅샷에 치카포 시세, 팔로워, 방송 중 여부, 채팅량, 포인트, 카드 보유량을 포함하지 않는다.

### 6.2 전투 seed

세트 seed와 라운드 seed는 재현성을 위해 서버에서 생성한다.

권장:

```text
match_seed = hash(season_id + match_id + player_a_deck_hash + player_b_deck_hash)
round_seed = hash(match_seed + ":round:" + round_no)
```

랜덤 판정이 필요한 모든 작업은 라운드 seed에서 파생된 deterministic random generator를 사용한다.

랜덤 사용처:

- 치명타 판정
- 확률형 상태이상 판정
- 동일 우선순위 대상 중 타겟 결정
- 확률형 패시브 발동

라운드별 seed를 분리하면 1라운드가 2라운드 결과에 랜덤 순서로 영향을 주지 않는다. 따라서 특정 라운드만 재시뮬레이션하거나 디버깅하기 쉽다.

### 6.3 라운드별 전술 플랜 검증

전술 플랜은 큐 등록 또는 덱 저장 시점에 미리 검증한다. 매칭 성사 후에는 다시 긴 검증을 수행하지 않고, 저장된 검증 결과와 카드 버전만 확인한다.

검증 항목:

- 플랜 수 1~3개
- 각 플랜의 배치 좌표 유효성
- 출전 카드 수 상한
- 같은 스트리머 중복 없음
- 덱에 없는 카드 사용 없음
- 비활성 카드 없음
- 전체 활성 카드 목록 밖 카드 없음

플랜이 1개만 있으면 모든 라운드에 같은 플랜을 사용한다. 플랜이 2개면 3라운드는 2라운드 플랜을 재사용한다.

## 7. Tick 시스템

### 7.1 Tick 간격

서버 시뮬레이션은 고정 tick을 사용한다.

```text
TICK_MS = 250
```

고정 tick을 쓰는 이유:

- 결과 재현성 확보
- 전투 로그 압축 용이
- 무한 루프 방지
- CPU 비용 예측 가능

### 7.2 Tick 처리 순서

각 tick은 다음 순서로 처리한다.

1. 시간 경과 효과 처리
2. 상태이상 지속시간 감소
3. 사망 예정 카드 정리
4. 에너지 자연 회복 처리
5. 공격 쿨다운 감소
6. 행동 가능한 카드 목록 생성
7. 행동 순서 정렬
8. 카드별 행동 처리
9. 사망 처리
10. 승패 조건 확인
11. 로그 이벤트 flush

### 7.3 행동 순서

같은 tick에 여러 카드가 행동 가능하면 다음 기준으로 정렬한다.

1. 공격 쿨다운이 더 많이 초과된 카드
2. 공격 속도가 높은 카드
3. 전열 카드
4. 낮은 column
5. deterministic random tie-breaker

행동 순서가 매번 흔들리지 않도록 tie-breaker도 seed 기반으로 처리한다.

## 8. 기본 공격

### 8.1 공격 주기

기본 공격 쿨다운:

```text
attack_interval_ms = 1000 / attack_speed
```

공격 후 `attack_cooldown_ms`에 `attack_interval_ms`를 더한다.

### 8.2 공격 가능 조건

카드는 다음 조건을 만족해야 기본 공격을 한다.

- 생존 상태
- 기절, 빙결, 침묵 중 행동 불가 계열이 아님
- 공격 쿨다운이 0 이하
- 사거리 안에 유효한 적이 있음

침묵은 액티브 스킬만 막고 기본 공격은 허용한다. 기절과 빙결은 기본 공격도 막는다.

### 8.3 타겟팅 기본 규칙

기본 공격 타겟 우선순위:

1. 사거리 안의 적
2. 전열 우선
3. 현재 공격자와 같은 column에 가까운 적
4. 체력이 낮은 적
5. deterministic random tie-breaker

도발 상태의 적이 있으면 사거리 조건을 만족하는 도발 대상이 우선된다.

### 8.4 사거리

거리 계산은 Manhattan distance를 기본으로 한다.

```text
distance = abs(attacker.x - target.x) + abs(attacker.y - target.y)
```

사거리 1은 인접 공격, 사거리 4는 대부분의 후열 공격을 허용한다.

## 9. 피해 공식

### 9.1 기본 피해

기본 피해:

```text
raw_damage = attack * skill_or_attack_multiplier
```

방어 적용:

```text
damage_after_defense = raw_damage * (100 / (100 + defense))
```

최종 피해:

```text
final_damage = max(1, round(damage_after_defense * damage_modifiers))
```

이 공식은 방어력이 높을수록 효율이 점진적으로 낮아져 과도한 무적화를 막는다.

### 9.2 치명타

치명타 판정:

```text
if random() < crit_chance:
  damage *= crit_damage
```

치명타는 방어 적용 후 최종 피해 계산 전에 적용한다.

치명타 관련 제한:

- `crit_chance` 상한: 50%
- `crit_damage` 상한: 250%
- 특정 스킬이 이 상한을 넘기면 밸런스 검증 실패

### 9.3 피해 타입

MVP에서는 피해 타입을 3종으로 제한한다.

- 물리: defense 적용
- 마법: magic_resist를 추가 도입하기 전까지 defense 50%만 적용
- 고정: 방어 무시, 대신 계수가 낮아야 함

MVP에서 별도 `magic_resist` 스탯은 만들지 않는다. 스탯 복잡도를 줄이기 위해 마법 피해는 방어력 일부만 적용한다.

권장:

```text
physical_damage_defense = defense
magic_damage_defense = defense * 0.5
true_damage_defense = 0
```

## 10. 보호막, 회복, 흡혈

### 10.1 보호막

보호막은 체력보다 먼저 피해를 흡수한다.

제한:

- 카드별 보호막 총량 상한: 최대 체력의 60%
- 단일 보호막 지속시간 상한: 10초
- 보호막 중첩은 허용하지만 총량 상한을 넘을 수 없음

### 10.2 회복

회복은 최대 체력을 넘길 수 없다.

제한:

- 단일 tick 회복량 상한: 최대 체력의 25%
- 초당 총 회복량 상한: 최대 체력의 40%
- 회복 감소 디버프 적용 가능

### 10.3 흡혈

흡혈은 실제로 준 피해를 기준으로 한다.

```text
heal = actual_damage_dealt * lifesteal_ratio
```

제한:

- 흡혈 비율 상한: 30%
- 광역 피해 흡혈은 효율 50% 적용

## 11. 에너지와 액티브 스킬

### 11.1 에너지 획득

카드는 다음 방법으로 에너지를 얻는다.

- 기본 공격 성공
- 피해를 받음
- 시간 경과
- 특정 패시브 발동

권장 기본값:

```text
energy_on_attack = 12 * energy_gain
energy_on_damaged = min(15, damage_taken / max_hp * 40) * energy_gain
energy_per_second = 3 * energy_gain
```

에너지 최대값:

```text
MAX_ENERGY = 200
```

### 11.2 액티브 스킬 발동 조건

액티브 스킬은 다음 조건을 만족하면 발동한다.

- 생존 상태
- 침묵, 기절, 빙결 상태가 아님
- 현재 에너지가 `skill_cost` 이상
- 유효한 타겟이 있음
- 스킬별 내부 쿨다운이 끝남

스킬 발동 시:

```text
current_energy -= skill_cost
```

### 11.3 스킬 우선순위

카드가 기본 공격과 액티브 스킬을 모두 사용할 수 있으면 액티브 스킬을 우선한다.

예외:

- 스킬 타겟이 없으면 기본 공격 시도
- 침묵 상태면 기본 공격 시도

## 12. 패시브 스킬

패시브는 발동 조건을 명확히 가져야 한다.

허용 발동 시점:

- 전투 시작
- 기본 공격 전
- 기본 공격 후
- 피해를 받기 전
- 피해를 받은 후
- 체력 임계값 도달
- 아군 사망
- 적 사망
- 일정 시간마다
- 액티브 스킬 사용 후

패시브 제한:

- 같은 패시브가 한 tick에 무한 반복 발동하면 안 됨
- 카드별 패시브 발동 횟수 상한을 둘 수 있음
- 전투 전체 발동 횟수 상한을 메타데이터로 관리
- 무한 루프 가능 패시브는 밸런스 검증 단계에서 차단

## 13. 상태이상

### 13.1 기본 상태이상

MVP 상태이상:

```text
STUN: 기절. 기본 공격과 스킬 불가
SILENCE: 침묵. 액티브 스킬 불가
ROOT: 속박. 위치 이동 불가
TAUNT: 도발. 특정 대상을 우선 공격
BURN: 화상. 시간 피해
POISON: 중독. 시간 피해, 회복 감소 가능
WEAKEN: 약화. 공격력 감소
VULNERABLE: 취약. 받는 피해 증가
HASTE: 가속. 공격 속도 증가
SLOW: 둔화. 공격 속도 감소
SHIELD_BLOCK: 보호막 획득
```

### 13.2 상태이상 저항

상태이상 적용 시 다음 판정을 한다.

```text
apply_chance = base_apply_chance * (1 - status_resist)
```

기절, 침묵 같은 강한 상태이상은 기본 확률과 지속시간을 낮게 잡아야 한다.

권장 상한:

- 기절 지속시간: 2초
- 침묵 지속시간: 3초
- 도발 지속시간: 4초
- 화상/중독 지속시간: 8초

### 13.3 상태이상 중첩

상태이상별 중첩 정책을 명확히 둔다.

- 기절: 중첩 불가, 더 긴 지속시간으로 갱신
- 침묵: 중첩 불가, 더 긴 지속시간으로 갱신
- 도발: 중첩 불가, 최신 도발로 갱신
- 화상: 최대 3중첩
- 중독: 최대 5중첩
- 약화: 최대 3중첩
- 취약: 최대 3중첩
- 가속/둔화: 같은 계열은 가장 강한 효과만 적용

## 14. 이동과 위치 변경

MVP에서 카드는 자유 이동하지 않는다.

허용되는 위치 변경:

- 특정 스킬의 끌어오기
- 특정 스킬의 밀쳐내기
- 위치 교환
- 후열 타격을 위한 일시적 연출 이동. 판정 위치는 변하지 않음

위치 변경 제한:

- 한 카드가 1초 안에 2회 이상 강제 이동되지 않도록 제한
- 보드 밖 이동 불가
- 이미 점유된 칸으로 이동 시 가장 가까운 빈 칸으로 보정
- 빈 칸이 없으면 이동 실패

## 15. 소환수

소환수는 확장성을 위해 규칙만 정의하고, MVP에서는 제한적으로 사용한다.

제한:

- 플레이어당 소환수 최대 2체
- 소환수는 시너지 태그를 제공하지 않음
- 소환수는 액티브 스킬을 갖지 않음
- 소환수는 리플레이 로그에 단순 유닛으로 기록
- 소환수가 전투를 과도하게 길게 만들면 자동 소멸 시간 부여

권장 소환수 지속시간:

```text
SUMMON_DURATION_MS = 15_000
```

## 16. 시너지

시너지는 같은 태그를 가진 카드 수에 따라 발동한다.

예시:

```text
태그 2개: 1단계 효과
태그 4개: 2단계 효과
태그 6개: 3단계 효과
```

MVP에서는 출전 카드 6장을 전제로 하므로 2/4/6 구조가 적합하다. 저장 덱은 최대 10장이며, 예비 카드 4장은 라운드별 직접 선택에서 출전 여부가 결정된다.

시너지 제한:

- 시너지는 전투 시작 시 계산한다.
- 전투 중 소환수는 시너지 수에 포함하지 않는다.
- 비활성 카드나 유효하지 않은 카드는 시너지 계산에서 제외한다.
- 시너지 효과도 파워 예산과 밸런스 검증 대상이다.

## 17. 승패 판정

### 17.1 라운드 기본 승패

한쪽 플레이어의 모든 출전 카드가 사망하면 패배한다.

### 17.2 라운드 동시 전멸

같은 tick에서 양쪽이 모두 전멸하면 다음 순서로 판정한다.

1. 생존 카드 수가 많은 쪽
2. 남은 총 체력 비율이 높았던 쪽. 전멸 전 마지막 tick 기준
3. 누적 피해량이 높은 쪽
4. 무승부

### 17.3 라운드 시간 초과

최대 전투 시간이 끝나면 다음 순서로 판정한다.

1. 생존 카드 수가 많은 쪽
2. 남은 총 체력 비율이 높은 쪽
3. 누적 피해량이 높은 쪽
4. 무승부

랭크전에서 무승부가 발생하면 MMR 변화는 0 또는 매우 작은 값으로 처리한다.

### 17.4 세트 승패

라운드 승수 기준:

```text
3라운드 선승 = 매치 승리
최대 5라운드
```

세트 판정:

1. 한쪽이 3승을 달성하면 즉시 매치 종료
2. 5라운드 종료 시 승수가 높은 쪽 승리
3. 5라운드 종료 시 승수가 같으면 세트 타이브레이커 적용

세트 타이브레이커:

1. 전체 라운드 합산 생존 카드 수
2. 전체 라운드 합산 남은 체력 비율
3. 전체 라운드 합산 누적 피해량
4. 전체 라운드 합산 라운드 시간. 더 빠르게 우세를 만든 쪽
5. 무승부

랭크전에서 세트 무승부가 발생하면 MMR 변화는 0으로 처리한다. 세트 무승부 비율은 2% 이하를 목표로 한다.

## 18. 전투 로그

### 18.1 로그 목적

전투 로그는 클라이언트 리플레이, 결과 검증, 디버깅, 밸런스 분석에 사용된다.

로그는 사람이 읽기 쉬운 전체 상태 덤프가 아니라, 리플레이에 필요한 이벤트 목록이어야 한다.

### 18.2 로그 구조

권장 최상위 구조:

```json
{
  "version": 1,
  "match_seed": "string",
  "tick_ms": 250,
  "rounds": [
    {
      "round_no": 1,
      "round_seed": "string",
      "duration_ms": 42500,
      "initial_state": {},
      "events": [],
      "result": {}
    }
  ],
  "result": {}
}
```

### 18.3 이벤트 공통 필드

```json
{
  "t": 1250,
  "type": "DAMAGE",
  "actor": "A:card-1",
  "targets": ["B:card-3"]
}
```

필드:

- `t`: 전투 시작 후 ms
- `type`: 이벤트 타입
- `actor`: 행동 주체
- `targets`: 대상 목록

### 18.4 이벤트 타입

MVP 이벤트 타입:

```text
BATTLE_START
SYNERGY_APPLIED
STATUS_APPLIED
STATUS_EXPIRED
BASIC_ATTACK
SKILL_CAST
DAMAGE
HEAL
SHIELD_GAIN
SHIELD_BREAK
ENERGY_GAIN
UNIT_MOVE
SUMMON
DEATH
BATTLE_END
```

### 18.5 로그 크기 제한

전투 로그는 DB 부하를 막기 위해 크기 제한을 둔다.

권장:

```text
MAX_BATTLE_EVENTS = 800
MAX_BATTLE_LOG_BYTES = 128KB
```

이벤트가 상한을 넘으면 리플레이 품질을 낮추더라도 요약 이벤트로 압축한다.

압축 예시:

- 연속 DOT 피해 합산
- 반복 에너지 획득 이벤트 생략
- 상태 유지 이벤트 생략
- 작은 피해 이벤트를 tick 단위로 묶음

## 20. 서버 부하 제한

전투 엔진은 다음 제한을 반드시 지킨다.

```text
MAX_UNITS_PER_PLAYER = 8
MAX_ACTIVE_UNITS_PER_PLAYER = 6
MAX_SUMMONS_PER_PLAYER = 2
MAX_ROUNDS_PER_MATCH = 5
ROUNDS_TO_WIN = 3
MAX_ROUND_TICKS = 180
MAX_MATCH_TICKS = 900
MAX_EVENTS_PER_ROUND = 800
MAX_EVENTS_PER_MATCH = 2400
MAX_STATUS_PER_UNIT = 12
MAX_PASSIVE_TRIGGERS_PER_TICK = 20
MAX_PASSIVE_TRIGGERS_PER_ROUND = 300
```

전투 계산은 긴 DB 트랜잭션 안에서 수행하지 않는다.

권장 처리:

1. 덱과 카드 스냅샷 조회
2. DB 연결을 잡지 않은 상태에서 전투 계산
3. 결과 저장 시 짧은 트랜잭션 사용
4. MMR 업데이트와 매치 결과 저장만 원자 처리

## 21. 치팅 방지

서버 검증:

- 덱에 존재하지 않는 카드 사용 차단
- 전체 활성 카드 목록 밖 카드 사용 차단
- 비활성 카드 사용 차단
- 같은 스트리머 중복 사용 차단
- 배치 좌표 위조 차단
- 카드 능력 버전 위조 차단
- 클라이언트가 제출한 전투 결과 무시

클라이언트는 전투 결과를 제출하지 않는다. 클라이언트가 제출하는 것은 매칭 요청, 덱 선택, 배치뿐이다.

## 22. 봇전 처리

봇전도 같은 전투 엔진을 사용한다.

차이:

- MMR 변화 없음
- 랭킹 반영 없음
- 봇 덱은 사전 생성 템플릿
- 봇전 상세 로그는 저장하지 않거나 짧게 보존
- 봇전 결과는 유저 학습용으로만 제공

봇도 동일한 파워 예산 규칙을 따라야 한다. 봇이 부정확한 예외 규칙을 많이 가지면 밸런스 테스트에 도움이 되지 않는다.

## 23. 리플레이 UX 기준

리플레이는 세트 전투 로그를 기반으로 재생한다.

필수 표시:

- 양쪽 덱
- 카드 위치
- 체력바
- 에너지바
- 상태이상 아이콘
- 기본 공격 연출
- 스킬 컷인
- 피해/회복 숫자
- 사망 처리
- 라운드 스코어
- 라운드 사이 전환 연출
- 승패 결과

리플레이 속도:

- 1x
- 1.5x
- 2x
- 결과만 보기

한 게임은 7~12분 체감을 목표로 한다. 다만 모바일에서는 전체 리플레이가 길게 느껴질 수 있으므로 다음 UX를 제공한다.

- 라운드별 건너뛰기
- 전체 결과만 보기
- 1.5x 기본 재생 옵션
- 마지막 라운드만 보기
- MVP 카드 하이라이트 먼저 보기

세트 리플레이 권장 체감:

- 3:0 종료: 6~8분
- 3:1 종료: 8~10분
- 3:2 종료: 10~12분
- 봇 연습전: 2분 내 빠른 재생 옵션 제공

## 24. 밸런스 테스트 기준

전투 시스템 구현 후 다음 자동 테스트가 필요하다.

기능 테스트:

- 같은 seed와 같은 덱은 같은 결과를 만든다.
- 같은 match seed와 같은 라운드 플랜은 같은 세트 결과를 만든다.
- 같은 tick에서 행동 순서가 재현된다.
- 상태이상 지속시간이 정확히 감소한다.
- 보호막과 회복 상한이 지켜진다.
- 전투 시간 초과 판정이 동작한다.
- 2승 달성 시 3라운드를 계산하지 않는다.
- 세트 타이브레이커가 재현 가능하게 동작한다.
- 로그 이벤트 수 상한이 지켜진다.

부하 테스트:

- 최악 조합 6 vs 6, 3라운드 세트가 제한 시간 안에 계산된다.
- 1,000회 연속 세트 시뮬레이션에서 메모리가 지속 증가하지 않는다.
- 세트 로그 평균 크기가 목표 범위 안에 있다.
- 봇전 대량 요청이 DB 풀을 고갈시키지 않는다.

밸런스 시뮬레이션:

- 기본 봇 덱들 간 승률
- 각 역할군 평균 승률
- 각 클래스 평균 승률
- 각 시너지 단계별 승률
- 무승부 비율
- 평균 라운드 시간
- 평균 세트 라운드 수
- 평균 세트 리플레이 시간

## 25. MVP 결정값

MVP 초기값은 다음을 기준으로 한다.

```text
덱 최대 크기: 10
출전 카드 수: 6
보드: 2행 x 4열
매치 방식: 5판 3선승
라운드 제한 시간: 60초
tick: 250ms
라운드 최대 tick: 180
세트 최대 라운드: 5
세트 승리 조건: 3라운드 선승
유저 체감 게임 시간: 7~12분
플레이어당 소환수: 최대 2
카드당 상태이상: 최대 12
라운드 로그 이벤트: 최대 800
세트 로그 이벤트: 최대 1800
상세 세트 로그 크기: 최대 256KB
상세 리플레이 보존: 7일 이하부터 시작, 안정화 후 7~14일
```

이 값들은 서버 부하, 리플레이 품질, 밸런스 결과를 보고 조정한다.

## 26. 반드시 지켜야 할 결정 사항

1. 전투 결과는 서버만 계산한다.
2. 클라이언트는 전투 결과를 제출하지 않는다.
3. 전투는 deterministic seed 기반으로 재현 가능해야 한다.
4. 빠른대전은 MVP부터 5판 3선승 세트 매치를 기본으로 한다.
5. 라운드 사이 실시간 입력을 요구하지 않고, 사전 저장된 라운드별 전술 플랜을 사용한다.
6. 전투 계산은 긴 DB 트랜잭션 안에서 수행하지 않는다.
7. 전투 로그에는 크기와 보존 기간 제한을 둔다.
8. 실시간 상주 매치룸 구조를 사용하지 않는다.
9. 치카포 시세, 팔로워, 방송 중 여부, 채팅량, 포인트, 카드 보유량은 전투력에 쓰지 않는다.
10. 전투 시스템은 6GB RAM과 4GB swap 환경에서 MySQL과 백엔드가 함께 동작할 수 있도록 제한값을 가진다.

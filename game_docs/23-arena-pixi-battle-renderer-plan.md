# 치카포 아레나 PixiJS 전투 렌더러 기획

## 목적

아레나 전투 화면의 직관성, 타격감, 마법/투사체/폭발 VFX 완성도를 상용 카드 배틀 게임에 가까운 수준으로 끌어올린다. 백엔드 전투 판정은 서버 권위를 유지하고, 리플레이 이벤트는 서버 계산 상태를 더 정확히 전달하는 v2 포맷을 사용한다. PixiJS는 전투 보드의 카드 배치, 체력바, 초상화, 행동 HUD, 타격 모션, 투사체, 충격 VFX를 직접 렌더링하는 프론트엔드 전투 렌더러로 사용한다.

## 선택 기준

PixiJS를 선택한다.

- 현재 아레나는 서버가 라운드 결과와 이벤트를 확정하고 프론트가 이를 시간순 재생하는 구조다.
- Phaser는 씬, 물리, 충돌, 게임 루프를 포함하는 완성형 게임 프레임워크라 현재 구조에는 과하다.
- PixiJS는 WebGL 기반 2D 렌더러로, 카드 스프라이트, 텍스트, 체력바, 투사체, 충격파, 파티클, 화면 글로우를 한 좌표계에서 직접 제어하기 좋다.
- Phaser처럼 독립 게임 루프와 물리 시스템을 강제하지 않아 서버 확정 이벤트를 그대로 순차 재생하는 현재 구조와 잘 맞는다.
- React는 라운드 상태, 전술 입력, API 통신, 페이지 레이아웃만 담당하고, 전투 보드 시각화는 PixiJS가 담당한다.
- 실패하거나 지원되지 않는 환경에서는 Pixi 초기화 실패 안내와 기존 라운드 상태 UI가 유지되어 페이지가 깨지지 않는다.

## 구현 범위

### 1단계: Pixi 전투 보드

- 전투 스테이지 내부에 `ArenaPixiBattleRenderer`를 추가한다.
- 카드, 카드 이미지, 클래스/스킬/스탯 표시, 체력바, 피해/회복 배지, 플레이어 초상화, 중앙 행동 HUD는 PixiJS가 직접 렌더링한다.
- React DOM 전투 카드 보드는 전투 화면에서 사용하지 않는다. React는 매치 상태와 라운드 이벤트만 전달한다.
- Pixi 캔버스 크기를 기준으로 상단 상대 진영, 중앙 행동 HUD, 하단 내 진영 좌표를 자동 계산한다.
- 캔버스 위 텍스트 요소에 해당하는 영역은 React 커스텀 툴팁을 띄워 클래스, 스킬, 스탯 설명을 제공한다.

### 2단계: 이벤트 타입별 VFX 프리셋

- `attack`: 카드 표면 충돌점에 짧은 슬래시, 충격파, 파편.
- `skill`: 공격자에서 대상까지 마법 화살 투사체, 대상 지점 폭발.
- `ultimate`: 큰 광역 링, 중심 플래시, 화면 흔들림, 다중 파편.
- `heal`: 대상 위로 상승하는 녹색 입자와 회복 링.
- `guard`: 대상 주변 방패 돔과 푸른 파동.
- `control`: 보라색 룬, 왜곡 링, 짧은 속박선.
- `retire`: 어두운 파편과 소멸 링.

### 3단계: 상태 정확성

- HP 0 카드는 Pixi 보드에서 즉시 전투불능 상태로 표시하고 이후 공격자 후보에서 제외한다.
- 이미 전투불능인 카드가 공격자로 들어오면 Pixi 렌더러는 해당 턴의 이동/공격 모션을 생략한다.
- 프론트는 `DEATH` 이벤트를 사망 판정의 권위로 삼는다. 피해 누적 추정만으로 카드를 전투불능 처리하지 않는다.
- HP 중계는 `DAMAGE`만 피해로 차감하고 `HEAL`은 회복으로 더하며, `SHIELD_GAIN`은 HP 피해로 처리하지 않는다.
- 라운드 결과의 남은 유닛 수는 카드별 사망 식별자가 아니므로 특정 카드를 임의로 전투불능 처리하는 데 사용하지 않는다.
- 신규 리플레이는 라운드별 `unit_states`를 포함한다. 여기에는 서버가 전술, 전장, 칩 보정을 적용한 유닛별 `max_hp`, `start_hp`, `final_hp`, `alive`가 들어간다.
- 프론트 HP 바의 최대 HP는 `unit_states.max_hp`를 우선 사용한다. `unit_states`가 없는 과거 리플레이는 기존 카드 스탯 기반 추정과 `DEATH` 이벤트 fallback을 사용한다.
- `unit_states`는 라운드당 최대 12개 이하의 작은 스냅샷이며, 이벤트 수 제한으로 리플레이 이벤트가 잘려도 보존되어야 한다.
- 신규 리플레이는 `replay_version: 2`를 포함한다.
- `DAMAGE`, `HEAL`, `SHIELD_GAIN`, `DEATH` 이벤트는 가능한 경우 `hp_before`, `hp_after`, `shield_before`, `shield_after`, `alive_after`를 포함한다.
- 프론트 HP 중계는 이벤트에 `hp_after`가 있으면 누적 추정보다 이 값을 우선 사용한다. 이로써 서버 계산과 화면 재생의 체력 표시 불일치를 줄인다.
- 이벤트 저장 상한을 넘으면 라운드에 `replay_truncated`, `original_event_count`, `timeline_summary.omitted_event_count`를 남긴다. 관전/디버그는 이 메타데이터를 통해 생략 여부를 인지할 수 있어야 한다.
- 결과/라운드 승자/전투 로그는 전투 연출 종료 전까지 노출하지 않는다.

### 4단계: 성능 원칙

- Pixi 애플리케이션은 전투 스테이지당 1개만 생성한다.
- Pixi 장면 컨테이너와 액션 컨테이너를 분리하고, 턴 변경 시 필요한 컨테이너만 clear/destroy한다.
- 텍스처는 Pixi Assets 캐시를 활용하고, 그래픽 객체는 짧은 수명 후 즉시 destroy한다.
- 이벤트가 없거나 전투 중이 아니면 ticker 작업을 하지 않는다.
- 저사양 기기에서는 저해상도 렌더링, 낮은 입자 수, 낮은 antialias 설정을 사용한다.
- `prefers-reduced-motion` 환경에서는 Pixi VFX를 생략하거나 최소화하되 전투 정보는 계속 표시한다.
- `/arena/settings`는 일반 내비게이션에 노출하지 않는 숨겨진 설정 페이지로 둔다. 이곳에서 VFX 품질과 관전 기본 속도를 localStorage에 저장한다.
- `/arena/settings`의 디버그 export는 사용자가 직접 요청할 때만 매치 요약, 리플레이, 룰 카탈로그, 로컬 렌더 설정을 JSON으로 묶는다. 상시 폴링, 서버 저장, DB 쓰기는 하지 않는다.
- 추가 서버 요청, DB 쓰기, 백엔드 계산은 금지한다.

## 좌표 모델

1. Pixi 캔버스의 실제 렌더링 크기를 기준 좌표계로 삼는다.
2. 상단 상대 초상화, 상대 후열/전열, 중앙 HUD, 내 전열/후열, 하단 내 초상화의 세로 영역을 자동 계산한다.
3. 각 진영은 3열 x 2행으로 배치하며, 상대는 위쪽이 후열·아래쪽이 전열, 나는 위쪽이 전열·아래쪽이 후열이다.
4. 카드 크기와 간격은 캔버스 폭/높이에 따라 자동 clamp되어 모바일과 데스크톱에서 같은 전투 구조를 유지한다.
5. 공격자와 대상의 카드 중심점, 카드 반지름, 이동 벡터를 계산해 실제 대상 카드 표면을 때리는 모션을 만든다.

## UX 원칙

- 사용자는 한 턴에 한 행동만 명확히 인식해야 한다.
- 공격자, 대상, 피해량, 사망 여부가 같은 프레임 안에서 연결되어 보여야 한다.
- 이펙트는 화려하되 카드 정보와 체력바를 가리면 안 된다.
- 궁극기만 화면 전체 플래시/흔들림을 허용한다.
- 일반 공격은 짧고 강해야 하며 라운드 진행 속도를 늦추지 않는다.
- Pixi 캔버스에서 보이는 정보는 DOM 전투 카드와 동일한 의미를 가져야 하며, 유저가 어떤 카드가 공격했고 어떤 카드가 피해를 받았는지 즉시 이해할 수 있어야 한다.

## 완료 기준

- 기본 공격, 스킬, 회복, 보호, 제어, 궁극기, 전투불능 이벤트가 서로 다른 VFX 언어를 가진다.
- HP 0 카드가 이후 턴에서 공격하거나 맞는 것처럼 보이지 않는다.
- 전투 중 스코어/결과/로그가 선노출되지 않는다.
- 전투 보드의 카드, 체력, 초상화, 행동 안내, 툴팁이 PixiJS 기반 렌더러에서 표시된다.
- 전투 좌표는 DOM 카드 측정이 아니라 캔버스 크기와 슬롯 정보로 자동 계산된다.
- `next build`가 통과한다.
- Pixi 초기화 실패 시 기존 전투 화면이 깨지지 않는다.

## 상용 보강 기준

- 전장에는 상대/내 진영 매트, 전열/후열 라벨, 중앙 분리선, 부드러운 광원 레이어를 둔다.
- 행동 중인 카드와 대상 카드는 같은 액션 컬러로 링, 연결선, HUD 강조를 공유해 한눈에 흐름이 읽혀야 한다.
- 카드에는 그림자, 전열 리본, 클래스/스킬/스탯 툴팁 영역, 체력바, 전투불능 오버레이를 일관되게 표시한다.
- 일반 공격은 카드가 실제 대상 방향으로 돌진하고 대상이 짧게 흔들리는 타격 모션을 가진다.
- 일반 공격은 예비 후퇴, 빠른 돌진, 접촉 순간의 짧은 히트스톱, 대상 카드 흔들림, 카드 스쿼시, 속도 잔상, 미세 화면 흔들림을 함께 사용해 타격감을 만든다.
- 공격 카드는 대상 카드 중심을 단순히 덮는 것이 아니라 대상 카드 표면 근처까지 이동하고, 충격 이펙트는 대상 표면 접촉점에 발생해야 한다.
- 스킬/제어는 투사체와 궤적을 사용하고, 회복/보호는 상승 입자와 방어 링으로 구분한다.
- 이펙트 애니메이션 중 매 프레임 컨테이너를 파괴/재생성하지 않고 그래픽 객체를 재사용해 저사양 기기 부담을 낮춘다.
- 이미지 텍스처는 Pixi Assets 캐시와 렌더러 내부 캐시를 함께 사용해 같은 카드 이미지를 반복 로드하지 않는다.
- 툴팁은 캔버스 실제 크기 기준으로 위치를 보정해 모바일과 좁은 패널에서도 잘리지 않아야 한다.

# 치카포 아레나 사이트 디자인 시스템

## 1. 목적

이 문서는 치카포 아레나의 사이트 디자인, 레이아웃, 색감, 컴포넌트, 애니메이션, 반응형 기준을 정의한다.

치카포 아레나는 기존 치카포의 자매 사이트다. 따라서 전체 레이아웃 틀은 치카포와 동일해야 한다. 다만 색감, 게임 화면 연출, 카드 배틀러 특유의 장식은 아레나 전용으로 분리한다.

핵심 목표:

- 치카포와 같은 서비스 계열로 즉시 인식되어야 한다.
- 기존 치카포의 동글동글하고 귀여운 인상을 유지해야 한다.
- 아레나는 더 게임답고, 더 반짝이고, 더 전투적인 카드 배틀러처럼 보여야 한다.
- 레이아웃 골격은 치카포와 동일하지만, 아레나는 치카포의 한 탭이 아니라 별도 자매 사이트 레이아웃으로 동작한다.
- PC 사이드바와 모바일 하단 도크는 기존 치카포와 완전히 동일한 형태와 동작을 유지한다.

## 2. 절대 유지해야 할 치카포 공통 레이아웃

아레나는 `/arena` 전용 `ArenaLayout`을 사용한다. `ArenaLayout`은 기존 치카포 `MainLayout`의 형태와 동작을 계승하되, 메뉴 구조는 아레나 전용으로 분리한다.

유지 항목:

- PC: 좌측 고정 사이드바
- 모바일: 상단 바 + 루프형 하단 도크
- 메인 콘텐츠 최대 폭
- 사이드바 폭
- 사이드바 둥근 오른쪽 모서리
- 모바일 하단 도크의 슬라이드/드래그 동작
- 모바일 하단 도크의 가운데 아이콘 확대
- 모바일 하단 도크의 곡선 배치
- 테마 토글 위치
- 로그인/사용자 정보 영역의 위치
- 알림/포인트 표시 위치
- 치카포와 아레나를 오가는 자매 사이트 이동 메뉴
- 아레나 내부 탭은 URL이 있는 하위 페이지로 동작해야 한다.

변경 가능 항목:

- 색상 토큰
- 그라데이션 방향과 색 조합
- 카드/패널 내부 장식
- 전투 화면 전용 이펙트
- 아레나 전용 아이콘
- 카드 희귀도/클래스별 강조 색
- 배경 패턴의 밀도

변경 금지 항목:

- PC 사이드바를 상단 내비게이션으로 변경
- 모바일 하단 도크를 일반 탭바로 변경
- 모바일 하단 도크의 루프 슬라이드 구조 제거
- 사이드바의 둥근 외형 제거
- 레이아웃을 랜딩 페이지형 히어로 중심으로 변경
- 치카포 본편과 완전히 다른 정보 구조로 변경
- 아레나를 치카포 본편의 일반 탭처럼 표시
- 아레나 주요 화면을 클라이언트 state만으로 전환하는 싱글 페이지 탭 구조로 고정

## 3. 기준 구현 요소

기존 치카포에서 계승해야 할 구조:

```text
PC sidebar:
- w-72
- sticky top-0
- h-screen
- rounded-r-[2rem]
- cute-surface
- nav button rounded-2xl

Mobile top bar:
- sticky top-0
- mx-3 mt-3
- rounded-3xl
- cute-surface

Mobile bottom dock:
- fixed bottom-2
- data-easter-nav="mobile-dock"
- looped nav items
- dockSlotWidth = 72
- center icon larger than side icons
- horizontal drag/swipe
- snap transition around 200~240ms
```

아레나 구현자는 위 구조를 새로 해석하지 않는다. 전용 `ArenaLayout`을 사용하되 치카포 레이아웃과 동일한 DOM/CSS 구조로 확장한다. 아레나 내부 메뉴는 URL이 있는 하위 페이지로 구성하고, 치카포 본편과의 왕래는 사이드바/모바일 도크의 `치카포` 또는 `아레나로 이동` 메뉴로 처리한다.

아레나 기본 라우트:

```text
/arena           플레이
/arena/inventory 보관함
/arena/ranking   MMR 랭킹
/arena/style     스타일 상점
/arena/admin     아레나 관리자
```

라우팅 원칙:

- 사이드바와 모바일 도크 클릭은 브라우저 URL을 변경해야 한다.
- 뒤로가기/앞으로가기는 사용자가 이동한 아레나 페이지 순서를 그대로 따라야 한다.
- 필터, 검색어, 선택 탭, 페이지 번호처럼 공유 가능한 상태는 가능한 한 query parameter로 둔다.
- 모달, 선택 카드, 리플레이 ID처럼 직접 열 수 있어야 하는 상세 상태는 query parameter 또는 하위 상세 route로 확장한다.
- 새 아레나 주요 기능을 추가할 때 클라이언트 state 전환만으로 끝내지 않는다.

## 4. 디자인 키워드

아레나의 시각 키워드:

- 동글동글
- 반짝임
- 카드 게임
- 귀여운 경쟁
- 가벼운 축제감
- 전략 게임의 명료함
- 팬덤 친화적
- 읽기 쉬운 전투 정보

피해야 할 인상:

- 어두운 하드코어 판타지
- 메탈/밀리터리 UI
- 과도한 RPG 장비창 느낌
- 카지노/도박장 느낌
- 복잡한 실시간 e스포츠 관전 HUD
- 랜딩 페이지처럼 과장된 마케팅 화면

## 5. 색상 방향

치카포 본편은 블루/스카이/민트 기반의 밝고 귀여운 색감이다. 아레나는 같은 레이아웃 감각을 유지하되, 색상은 붉은 파스텔 계열로 분리해 자매 사이트처럼 보이게 한다.

### 5.1 아레나 기본 팔레트

```text
arena-primary: coral pink / warm rose
arena-secondary: blush red
arena-accent: pale coral
arena-magic: soft rose pink
arena-warning: muted red
arena-danger: candy red
arena-surface: warm white with pink tint
arena-dark-surface: deep wine brown with rose tint
```

권장 HEX:

```text
Light:
primary: #ee6776
secondary: #ffe8e8
accent: #ffdada
magic: #fda4af
warning: #ef4444
danger: #fb7185
surface: #fffaf9
background: #fff4f3

Dark:
primary: #ff9aa6
secondary: #3a1e22
accent: #4a2429
magic: #fda4af
warning: #f87171
danger: #fda4af
surface: #2a171a
background: #1f1114
```

### 5.2 색상 사용 비율

```text
배경/표면: 60%
카드/패널 보조색: 20%
주요 액션 색: 10%
희귀도/스킬/상태 이펙트: 10%
```

주의:

- 한 화면이 단일 분홍색만으로 보이지 않도록 blush red, rose, coral, pale red를 밝기 차이로 나눈다.
- 노란 기운이 강한 amber/orange 계열은 피하고, 보조색도 붉은 파스텔 안에서만 사용한다.
- 버튼과 주요 CTA는 화면마다 색을 바꾸지 않는다.
- 위험/삭제/비활성화는 rose/red 계열로 일관되게 표시한다.

## 6. 그라데이션 원칙

아레나는 그라데이션을 적극 사용한다. 단, 서로 따로 노는 장식이 아니라 카드, 표면, 버튼, 리플레이 이펙트가 같은 색 계열로 이어져야 한다.

권장 그라데이션:

```text
Primary CTA:
linear-gradient(135deg, #ff6b9e 0%, #a78bfa 52%, #62c7ff 100%)

Arena surface:
linear-gradient(180deg, rgba(255,255,255,.94), rgba(255,244,251,.86))

Battle board:
linear-gradient(135deg, rgba(98,199,255,.16), rgba(167,139,250,.14), rgba(53,230,198,.12))

Victory:
linear-gradient(135deg, #facc15 0%, #ff8fbd 48%, #62c7ff 100%)

Defeat:
linear-gradient(135deg, #64748b 0%, #a78bfa 48%, #fb7185 100%)
```

사용 규칙:

- 큰 배경은 부드러운 저채도 그라데이션을 사용한다.
- 버튼/승리/희귀도는 고채도 그라데이션을 사용한다.
- 카드 표면에는 광택 스윕과 얇은 경계 그라데이션을 사용한다.
- 독립적인 장식 오브나 의미 없는 블러 덩어리를 남발하지 않는다.
- 장식은 카드, 보드, 리본, 상태 배지, 구분선 같은 UI 요소에 붙인다.

## 7. 타이포그래피

기존 치카포 폰트 계열을 유지한다.

계승:

- UI 본문: 기존 `font-ui`
- 제목: 기존 `font-display`
- 히어로/강조: 기존 `font-hero`
- 숫자/MMR/랭킹: 기존 `font-number`

규칙:

- 카드명은 굵고 짧게 표시한다.
- 스킬 설명은 2~3줄 안에 읽히게 한다.
- 랭킹/전투 숫자는 tabular number를 사용한다.
- 모바일 버튼 텍스트는 2줄 이상 늘어지지 않게 한다.
- 영문/숫자/한글이 섞여도 줄 높이가 흔들리지 않게 한다.

## 8. 공통 컴포넌트 스타일

### 8.1 Surface

기본 표면은 기존 `cute-surface` 느낌을 유지한다.

아레나 변형:

```text
border-radius: 1.5rem ~ 2rem
border: soft pink/cyan mix
background: warm white + subtle gradient
shadow: soft colored shadow
```

사용:

- 사이드바
- 모바일 상단 바
- 필터 패널
- 덱 편성 패널
- 결과 요약 패널

주의:

- 카드 안에 또 카드형 섹션을 과도하게 중첩하지 않는다.
- 반복 아이템, 모달, 도구 패널에는 카드 스타일을 써도 된다.
- 페이지 섹션 전체를 둥근 카드로만 쌓지 않는다.

### 8.2 Button

버튼은 치카포처럼 둥글고 명확해야 한다.

종류:

```text
Primary: 빠른대전, 봇전 시작, 덱 저장
Secondary: 필터, 정렬, 상세 보기
Danger: 비활성화, 덱 삭제
Ghost: 닫기, 뒤로, 보조 액션
Icon: 필터 열기, 정렬, 확대, 리플레이 제어
```

규칙:

- 아이콘이 있는 명령은 lucide 아이콘을 우선 사용한다.
- 텍스트만 있는 버튼은 명확한 행동에만 사용한다.
- hover 시 1~2px 위로 뜨는 느낌을 유지한다.
- primary 버튼에는 짧은 sheen animation을 허용한다.
- disabled 상태는 채도와 그림자를 낮춘다.

### 8.3 Pill/Badge

사용:

- 클래스
- 역할군
- 시너지 태그
- 상태이상
- MMR 티어
- 카드 비활성화 상태
- 시즌 표시

스타일:

```text
rounded-full
small border
soft background
bold 10~12px text
```

상태 색:

```text
buff: light rose
debuff: rose
control: soft pink
shield: pale red
heal: blush coral
damage: coral
rank: rose/red gradient
disabled: gray
```

## 9. 카드 UI 디자인

아레나의 핵심 시각 자산은 카드다.

### 9.1 카드 비율

권장:

```text
card aspect ratio: 3 / 4
deck mini card: 2.5 / 3.5
replay unit card: square or 4 / 5
```

카드 구성:

```text
상단: 역할군/클래스 배지
중앙: 스트리머 이미지
하단: 카드명
하단 보조: 스킬/태그 요약
모서리: 등급/시즌/상태 아이콘
```

### 9.2 카드 장식

카드 장식은 기존 치카포 카드 테두리, 이름 효과, 커스텀 이미지를 최대한 활용한다.

아레나 추가 장식:

- 클래스별 얇은 링
- 스킬 발동 시 카드 광택
- 승리 MVP 카드 확대 컷인
- 태그 시너지 활성 시 카드 테두리 펄스
- 비활성화 카드의 부드러운 grayscale + 대체 배지

금지:

- 스트리머 이미지를 과하게 가리는 이펙트
- 카드명보다 효과가 더 눈에 띄는 장식
- 전투력/시세를 암시하는 고가 카드 연출
- 유료 코스메틱처럼 보이는 전투 능력 강조

## 10. 주요 화면 디자인

### 10.1 아레나 홈

목표:

- 바로 빠른대전/봇전을 시작할 수 있어야 한다.
- 현재 시즌, MMR, 최근 덱, 이벤트 상태를 한 화면에서 본다.
- 우측 보조 컬럼이 안내 문구로 길게 늘어지지 않아야 한다.

구성:

```text
상단: 시즌 상태 + 내 티어
중앙 좌측: 빠른대전 CTA
중앙 우측: AI 연습게임 CTA
하단: 최근 매치 / 추천 덱 / 시즌 알림
도움말: 아레나 플레이 도움말 모달
```

비주얼:

- CTA는 큰 둥근 패널이지만 랜딩 히어로처럼 과장하지 않는다.
- 빠른대전은 rose-red 그라데이션.
- 봇전은 blush-coral 그라데이션.
- 시즌 배너는 얇은 리본 형태.
- 아레나의 재미, 플레이 방식, 기록 기준처럼 읽기 전용 안내는 본문 우측 컬럼에 상시 노출하지 않고 도움말 모달로 분리한다.
- 카드 풀은 좁은 우측 패널과 나란히 두지 않고 넓은 본문 폭을 우선 사용한다.
- 시즌 상태와 내 아레나는 카드 풀 아래의 작업 패널로 묶어, 화면 폭이 넓을 때만 2열로 배치한다.

### 10.2 덱 빌더

목표:

- 6장 출전 카드와 1~5라운드 전술 플랜을 쉽게 편성한다.

구성:

```text
좌측/상단: 카드 필터
중앙: 덱 슬롯 6개
우측/하단: 카드 목록
하단/탭: 라운드 1, 2, 3, 4, 5 전술 플랜
```

디자인:

- 덱 슬롯은 고정 크기.
- 빈 슬롯은 점선 테두리와 부드러운 pulse.
- 카드 드래그/선택 시 그림자와 살짝 떠오르는 효과.
- 라운드 탭은 segmented control.
- 전술 옵션은 아이콘 + 짧은 텍스트.

모바일:

- 카드 목록은 bottom sheet 또는 drawer.
- 덱 슬롯은 2열 또는 3열 그리드.
- 라운드 전술은 탭으로 접는다.

### 10.3 카드 도감

목표:

- 3천 장 규모에서도 탐색이 어렵지 않아야 한다.
- 치카포 본편 보관함과 아레나 보관함은 역할을 분리한다.

구성:

```text
검색
역할군 필터
클래스 필터
태그 필터
시즌 풀 여부
비활성화 제외 토글
카드 그리드
```

디자인:

- 카드 그리드는 조밀하지만 답답하지 않게.
- 필터는 둥근 chip 형태.
- 클래스 색은 배지로만 사용하고 전체 카드를 한 색으로 덮지 않는다.
- 카드 hover/focus 시 이미지 확대 2~4% 이내.

### 10.3.1 아레나 보관함

목표:

- 유저가 보유한 치카포 카드 중 아레나에 사용할 수 있는 카드만 아레나 규칙으로 확인한다.
- 치카포 본편 보관함으로 빠지지 않고 `/arena/inventory` 전용 페이지에서 처리한다.
- 카드의 클래스, 역할군, 스탯, 스킬, 보유 수량, 최고 별을 한눈에 확인할 수 있어야 한다.

구성:

```text
상단: 아레나 보관함 제목 / 새로고침 / 첫 덱 만들기
요약: 아레나 카드 수 / 저장 덱 / 최고 별 / 보유 수량
본문: 보유 카드 그리드
보조: 덱 준비 상태 / 클래스 분포
```

디자인:

- 보유 카드 그리드는 카드형 리스트보다 아레나 전용 카드 프리뷰에 가깝게 보인다.
- 각 카드에는 아레나 클래스, 역할군, 5개 스탯, 주요 스킬을 표시한다.
- 보관함 준비도와 최소 덱 필요 수량을 보여주되, 전투력이나 카드 가격처럼 보이는 표현은 사용하지 않는다.
- 데이터가 없을 때는 목업을 보여주지 않고 비어 있음을 명확히 말한다.

### 10.4 매칭 화면

목표:

- 서버가 실시간 방을 유지하지 않아도 유저는 대전 중이라는 감각을 받아야 한다.

구성:

```text
내 덱 요약
큐 상태
예상 대기
취소 버튼
작은 카드 셔플 애니메이션
```

디자인:

- 카드들이 부드럽게 섞이는 loop animation.
- 진행 상태는 원형 spinner보다 카드 슬롯이 채워지는 형태를 우선.
- 너무 긴 애니메이션은 피하고 2~4초 loop로 유지.

### 10.5 리플레이 화면

목표:

- 5판 3선승 세트를 7~12분 체감으로 보여준다.
- 전투 정보는 읽기 쉽고, 연출은 카드 중심이어야 한다.

구성:

```text
상단: 세트 스코어 / 라운드 / 속도
중앙: 2행 x 4열 보드
좌우: 플레이어 덱 요약
하단: 이벤트 로그 / 스킬 타임라인
```

디자인:

- 보드는 유리판 같은 soft gradient surface.
- 유닛은 카드 썸네일 형태.
- 스킬 발동은 카드 확대 + 짧은 광택 + 상태 아이콘.
- 피해/회복 숫자는 작고 선명하게.
- 상태이상은 색상과 아이콘으로 구분.
- 3:0/3:1/3:2 결과는 승리 리본으로 표시.

성능 기준:

- 파티클 수 제한.
- 모바일에서 blur와 box-shadow 과다 사용 금지.
- `prefers-reduced-motion`에서 카드 흔들림/광택/파티클을 줄인다.
- 리플레이가 없어도 결과 요약 화면은 완성도 있게 보여야 한다.

### 10.6 결과 화면과 종료 모달

전투 종료 직후에는 별도 페이지 구역보다 결과 모달을 우선 표시한다. 페이지 내 결과 요약은 모달을 닫은 뒤에도 확인 가능한 보조 정보로 둔다.

모달 구성:

```text
승패
세트 스코어
전투 턴/이벤트 수
로그 진단 상태
MVP 카드
관전 링크 복사 / 다시 플레이 / 덱 수정
```

디자인:

- 승리: rose-red 그라데이션 리본.
- 패배: 차분한 muted rose.
- MVP 카드는 크게 보여주되 스트리머 이미지가 잘 보이게 한다.
- MMR 변화는 숫자 강조, 과한 폭죽 금지.
- 모달 배경은 반투명 rose 계열 dim과 blur를 사용하되, 본문 카드 정보와 CTA가 가장 먼저 읽혀야 한다.
- 모달은 닫을 수 있어야 하며, 닫은 뒤에도 페이지의 라운드 기록과 전투 로그를 확인할 수 있어야 한다.

### 10.7 랭킹 화면

목표:

- 정보 밀도가 높지만 귀엽고 가볍게 보여야 한다.
- 아레나 플레이 화면의 보조 패널이 아니라 `MMR 랭킹` 전용 탭/페이지로 제공한다.
- 내 순위, 시즌 상위권, 티어 분포, MMR 구간, 승률 상위를 한 화면에서 스캔할 수 있어야 한다.

구성:

```text
상단: MMR 랭킹 제목 / 내 전적 명함 / 새로고침
요약: 내 순위 / 내 MMR / 랭킹 표본 / 평균 MMR
본문: 시즌 MMR 순위 테이블
우측/하단: 상위권 포디움 / 티어 분포 / MMR 구간 / 승률 상위
```

디자인:

- 1~3위는 메달 배지.
- 테이블 행은 rounded row이며 hover 시 살짝 떠오르는 느낌을 준다.
- 모바일은 카드형 list로 순위, 유저, MMR, 티어, 전적이 한 덩어리로 읽혀야 한다.
- 랭킹 조회가 스냅샷 기반임을 작은 timestamp로 표시.
- 랭킹 행은 공개 전적 명함을 여는 진입점으로 사용할 수 있다.
- 랭킹 페이지의 보조 정보는 우측 컬럼이 너무 길어지지 않도록 데스크톱에서는 우측 요약, 모바일에서는 본문 아래 카드로 쌓는다.
- 분포 그래프는 현재 조회된 제한 목록 기준임을 전제로 하며, 추가 API 호출이나 실시간 전체 집계를 요구하지 않는다.

### 10.7.1 전적 명함 모달

목표:

- 유저의 MMR, 티어, 랭킹, 승패, 최근 랭크전을 한 장의 게임 카드처럼 보여준다.
- 프로필 모달은 경쟁심을 자극하되 전투력 구매나 자산 우위를 암시하지 않는다.
- 랭킹 화면에서 다른 유저를 눌렀을 때 즉시 확인 가능한 가벼운 공개 정보여야 한다.

구성:

```text
상단: ARENA LICENSE / 닫기
중앙: 유저 ID, 티어, 랭킹, MMR
하단: 승/패/무, 승률 바, 최근 랭크전 5개
```

디자인:

- 배경은 blush red, rose, pale coral이 섞인 아레나 전용 그라데이션을 사용한다.
- 모달 외곽은 둥근 큰 카드 형태이며, 얇은 광택선과 부드러운 colored shadow를 적용한다.
- 숫자는 tabular number로 정렬하고, 승률 바는 0~100% 범위를 고정해 레이아웃이 흔들리지 않게 한다.
- 최근 전적이 없으면 목업 없이 비어 있음을 표시한다.
- 닫기 버튼은 우상단 원형 아이콘 버튼으로 제공하고 키보드 포커스가 보여야 한다.

부하/개인정보 기준:

- 모달은 `GET /api/arena/profile/{user_id}` 1회 호출로 완성한다.
- 최근 매치는 최대 5개만 보여준다.
- 포인트, 보유 카드 수, 치카포 본편 자산, 방송 상태, 비공개 덱 원본은 보여주지 않는다.
- 새로고침 또는 랭킹 재조회 없이 같은 유저를 반복 클릭해도 UX가 깨지지 않아야 한다.

### 10.8 스트리머 카드 설정 화면

목표:

- 스트리머가 자신의 카드 콘셉트를 쉽게 이해하고 선택한다.
- 비활성화 권리를 명확하게 제공한다.

구성:

```text
내 카드 미리보기
현재 자동 생성 능력
프리셋 선택
플레이버 텍스트
아레나 사용 여부
반영 시점 안내
```

디자인:

- 프리셋은 카드 3~5개 후보처럼 보여준다.
- 위험한 설정이나 반영 대기 상태는 muted red/rose 배지.
- 비활성화 버튼은 숨기지 않는다.
- 비활성화 안내는 협박처럼 보이지 않고 담백하게 설명한다.

### 10.9 스타일 상점

목표:

- 상점, 파이 메뉴 편집, 장착 상태가 한 화면에서 서로 밀리지 않게 보여야 한다.
- 사용 안내는 도움말 모달로 분리하고, 본문에는 구매/장착에 필요한 상태만 남긴다.

구성:

```text
상단: 스타일 상점 제목 / 보유 포인트 / 스타일 도움말 / 새로고침
본문: 상품 필터 / 상품 그리드 / 파이 메뉴 편집
하단: 스타일 미리보기 / 장착 상태
도움말: 스타일 사용 도움말 모달
```

디자인:

- 상점 상품 그리드는 전체 폭을 사용한다.
- 스타일 미리보기와 장착 상태는 우측 긴 컬럼이 아니라 하단 2열 요약 영역으로 배치한다.
- 장착 상태는 프레임, 이름 연출, 이모트 슬롯을 한눈에 보이게 하되 긴 설명 문구를 반복하지 않는다.
- 파이 메뉴 편집은 상점 본문 안에 유지해 구매 후 바로 배치할 수 있게 한다.
- 비P2W 안내는 상단 짧은 문장과 도움말 모달에만 둔다.

## 11. 애니메이션 원칙

아레나는 애니메이션을 다양하게 사용하되, 모두 카드 게임 경험과 연결되어야 한다.

허용 애니메이션:

- 카드 hover float
- CTA sheen
- 카드 광택 sweep
- 태그 활성 pulse
- 매칭 카드 shuffle
- 리플레이 스킬 flash
- 승리 리본 pop
- 하단 도크 slide/snap
- 사이드바 nav hover wiggle

금지 또는 제한:

- 의미 없는 배경 오브 이동
- 계속 회전하는 대형 장식
- 텍스트 가독성을 떨어뜨리는 번쩍임
- 모바일에서 무거운 blur 중첩
- 모든 카드가 동시에 흔들리는 효과
- MMR 변화에 과한 폭죽/파티클

속도 기준:

```text
micro hover: 120~180ms
button sheen: 600~800ms
dock snap: 200~240ms
card skill flash: 280~420ms
matchmaking loop: 2~4s
victory pop: 500~700ms
```

접근성:

- `prefers-reduced-motion: reduce`를 지원한다.
- reduce 환경에서는 loop animation, sheen, shake, particle을 끈다.
- hover만으로 중요한 정보를 제공하지 않는다.

- 전투 상태 아이콘은 색상만으로 구분하지 않는다.

## 13.1 카피라이팅 기준

아레나 화면의 문구는 소개 카피와 기능 문구를 분리한다.

소개 카피:

- 히어로 본문, OG description, 소개/매력 섹션에만 사용한다.
- 구현된 기능 목록을 나열하지 않고 유저가 경험적으로 느낄 매력을 말한다.
- 좋은 예: 좋아하는 스트리머 카드를 팀의 핵심 역할로 세우는 즐거움.
- 좋은 예: 한 라운드를 내줘도 다음 플랜으로 뒤집을 수 있는 긴장감.
- 금지: 서버 방식, DB 부하, 내부 캐시, 구현 여부를 소개 카피처럼 노출.

기능 문구:

- 버튼, 탭, 상태 배지, 카드 라벨, 관리자 항목, 빈 상태에는 기능을 직관적으로 쓴다.
- 좋은 예: 덱 편성, 5판 3선승, 카드 데이터 확인, 빠른대전 상태, 다시 불러오기.
- 좋은 예: 매치 방식, 예상 플레이 시간, 주요 전략 요소.
- 금지: 버튼이나 상태 라벨에 감성 표현만 사용해 동작을 추측하게 만드는 것.
- 데이터가 없을 때는 목업 없이 비어 있음을 명확히 말한다.

## 17. 최종 결정 사항

1. 치카포 아레나는 치카포와 같은 레이아웃 골격을 사용한다.
2. PC 사이드바의 둥근 형태와 위치는 기존 치카포와 동일해야 한다.
3. 모바일 하단바는 기존 치카포의 루프형 슬라이드 도크와 동일해야 한다.
4. 색감은 아레나 전용으로 blush red, rose, coral, pale red를 섞고 노란 기운은 최소화한다.
5. 전체 인상은 동글동글하고 귀여워야 한다.
6. 그라데이션과 애니메이션은 카드 게임의 행동과 연결되어야 한다.
7. 리플레이와 전투 화면은 화려하되 모바일 성능과 가독성을 우선한다.
8. 장식은 전투력이나 유료 우위를 암시하면 안 된다.
9. 관전은 완료 리플레이/하이라이트 기반으로 제한 제공한다. 실시간 관전 HUD와 대형 생중계 연출은 MVP 이후에 검토한다.
10. 구현 전 PC/모바일 스크린샷으로 사이드바와 하단 도크 동일성을 확인한다.

## 18. 확장 화면 디자인

### 18.1 5판 3선승 덱 빌더

- 10장 덱과 6장 출전 구성이 한눈에 보여야 한다.
- 1~5라운드 탭은 모바일에서 가로 스크롤 또는 segmented control로 제공한다.
- 라운드별 전술 선택은 복잡한 문장보다 아이콘, 짧은 선택명, 결과 배치 미리보기로 표현한다.
- 밴픽 UI는 만들지 않는다.
- 시즌 로테이션 카드 풀처럼 보이는 잠금/순환 안내를 만들지 않는다.

### 18.1.1 실제 게임 페이지 전투 화면

- 실제 게임 페이지는 상단 매치 HUD, 중앙 Pixi 전장, 우측 라운드/전술 패널, 하단 리플레이/로그 영역으로 구분한다.
- 상단 HUD는 현재 라운드, 5판 3선승 목표, 스코어, 상태, 다음 행동을 작은 메트릭 카드로 보여준다.
- 전장 화면은 붉은 파스텔 톤을 유지하되 카드 정보가 장식에 묻히지 않도록 배경 광원과 VFX 투명도를 제한한다.
- 행동 중 카드와 대상 카드는 같은 액션 컬러로 링, 연결선, 배지를 공유한다.
- 피해/회복/보호 숫자는 카드 위에 떠오르되 카드 클리핑 영역 밖에서도 보이도록 Pixi 액션 레이어에 표시한다.
- 결과 모달은 승패, 스코어, MVP, 결정적 라운드, 관전 링크/다시 플레이/덱 수정 CTA를 포함한다.

### 18.2 8인 컵

- 브래킷은 8강, 순위 결정전, 최종 1~8위를 명확하게 보여준다.
- 컵 진행은 실시간 방이 아니라 계산 완료 후 결과/하이라이트 공개처럼 표현한다.
- 내 경기와 결승/하이라이트를 빠르게 전환할 수 있어야 한다.

### 18.3 관전

- 관전 화면은 리플레이 플레이어에 가깝게 설계한다.
- 결과 스포일러 숨김, 라운드 점프, 하이라이트만 보기, 배속 제어를 제공한다.
- 실시간 채팅/관전자 목록/복잡한 중계 HUD는 넣지 않는다.

### 18.4 관리자 페이지

- 기존 치카포 관리자 레이아웃을 따른다.
- 운영 현황, 컵, 관전, 통계, kill switch, 감사 로그 탭을 둔다.
- 통계 카드에는 표본 수, 승률, 픽률, 스냅샷 시각을 반드시 표시한다.
- 위험 조합은 빨간색만 남발하지 않고 심각도, 표본 수, 권장 조치를 함께 보여준다.

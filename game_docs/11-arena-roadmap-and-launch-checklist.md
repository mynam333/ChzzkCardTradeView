# 치카포 아레나 개발 로드맵 및 출시 체크리스트

## 1. 목적

이 문서는 치카포 아레나를 기획서에서 실제 서비스로 구현하기 위한 개발 순서, 마일스톤, 출시 조건, QA 체크리스트를 정의한다.

치카포 아레나는 큰 규모의 자매 서비스이므로 한 번에 모든 기능을 구현하지 않는다. 반드시 전투 엔진, 카드 생성, 봇전, 리플레이, 저부하 검증을 먼저 완료한 뒤 빠른대전과 랭크 시즌으로 확장한다.

## 2. 개발 원칙

1. 서버 부하가 낮은 기능부터 검증한다.
2. 봇전으로 전투 엔진과 리플레이를 먼저 검증한다.
3. 빠른대전은 전투 엔진이 안정된 뒤 붙인다.
4. 랭킹은 실시간 계산이 아니라 스냅샷 기반으로 만든다.
5. 유료화는 MVP 이후로 미룬다.
6. 전투력 관련 과금 요소는 만들지 않는다.
7. 스트리머 opt-out은 초기부터 반드시 포함한다.

## 3. 마일스톤 개요

```text
M0: 기획 확정
M1: 데이터 정의와 카드 생성
M2: 전투 엔진
M3: 봇 연습전
M4: 덱 편성/리플레이 UX
M5: 빠른대전/MMR
M6: 랭킹/시즌
M7: 스트리머 설정/관리자
M8: 밸런스 시뮬레이션/QA
M9: 클로즈 베타
M10: 공개 베타
M11: 정식 시즌
```

## 4. M0: 기획 확정

완료 조건:

- `01~11` 기획 문서 확정
- 5판 3선승 유지 여부 확정
- MVP 기능 범위 확정
- 제외 기능 확정
- P2W 금지 원칙 확정

산출물:

- 최종 GDD
- MVP scope
- DB migration 초안
- API 목록
- 위험 요소 목록

## 5. M1: 데이터 정의와 카드 생성

목표:

- 클래스/스킬/태그 정적 데이터 작성
- 3,000장 카드 자동 생성 가능
- opt-out 상태 반영

작업:

- TypeScript definition 작성
- class/skill/tag JSON 또는 TS 상수 작성
- deterministic RNG 구현
- power score 계산
- forbidden combo 검사
- fallback preset 구현
- arena_cards 저장
- generation report 생성

완료 조건:

- 같은 `channel_id`와 version은 항상 같은 결과
- 3,000장 batch 생성 성공
- power score 95~105 범위
- fallback 비율 허용 범위
- opt-out 카드 제외

## 6. M2: 전투 엔진

목표:

- 5판 3선승 세트 전투를 서버에서 deterministic simulation으로 계산

작업:

- 보드/좌표 구현
- tick loop 구현
- 기본 공격
- 타겟팅
- 피해 공식
- 에너지
- 액티브 스킬
- 패시브 스킬
- 상태이상
- 보호막/회복
- 승패/타이브레이커
- 전투 로그 생성

완료 조건:

- 같은 seed와 같은 입력은 같은 결과
- 2승 달성 시 이후 라운드 계산 안 함
- 최대 tick 제한 동작
- 로그 이벤트 제한 동작
- 전투 계산 중 DB 접근 없음

## 7. M3: 봇 연습전

목표:

- 매칭 큐 없이 전투 엔진과 리플레이를 검증

작업:

- 봇 덱 템플릿
- 난이도별 봇
- 단판 봇전
- 5판 3선승 봇전
- match summary 저장
- optional battle log 저장
- rate limit

완료 조건:

- 봇전은 MMR 미반영
- 봇전 반복 요청 rate limit
- 리플레이 조회 가능
- 결과 화면 표시 가능

## 8. M4: 덱 편성/리플레이 UX

목표:

- 유저가 덱과 라운드별 플랜을 만들고 세트 리플레이를 볼 수 있음

작업:

- 카드 도감
- 덱 편성
- 라운드별 플랜 UI
- 덱 검증
- 리플레이 보드
- 라운드 전환
- 결과 화면
- 결과만 보기

완료 조건:

- 신규 유저가 추천 덱으로 봇전 시작 가능
- 고급 유저가 3개 라운드 플랜 설정 가능
- 모바일에서 보드와 카드 상태가 읽힘
- 리플레이 건너뛰기 가능

## 9. M5: 빠른대전/MMR

목표:

- 유저끼리 빠른대전 가능
- MMR이 match 단위로 반영

작업:

- arena_match_queue
- quick join API
- status API
- cancel API
- MMR service
- match 저장
- rating atomic update
- 매칭 확정 후 이탈 복구
- 반복 매칭 제한
- 큐 만료 배치

완료 조건:

- 큐 등록/취소 정상
- 매칭 동시성 문제 없음
- 상대 이탈 후에도 결과/리플레이 조회 가능
- 재접속 시 matched match id 복구
- MMR 중복 반영 없음
- 봇전과 랭크 경로 분리
- 6GB RAM 환경에서 부하 허용

## 10. M6: 랭킹/시즌

목표:

- 시즌 구조와 아레나 전용 랭킹 제공

작업:

- arena_seasons
- season card pool
- player ratings
- rank snapshots
- ranking API
- season reset
- season reward preview

완료 조건:

- 랭킹은 snapshot 기반
- 실시간 전체 재계산 없음
- 시즌 soft reset 가능
- 내 rating 조회 가능

## 11. M7: 스트리머 설정/관리자

목표:

- 스트리머가 카드 사용 여부와 콘셉트 설정 요청 가능
- 관리자가 카드 풀과 위험 요소 관리 가능

작업:

- 스트리머 본인 확인
- 내 아레나 카드 페이지
- config preview
- config request
- opt-out/opt-in
- 관리자 카드 목록
- 요청 승인/거절
- 강제 비활성화
- 감사 로그

완료 조건:

- opt-out 즉시 카드 풀에서 제외
- 기존 덱의 비활성 카드 감지
- 관리자 액션 로그 기록
- 설정 요청은 검증 결과 포함

## 12. M8: 밸런스 시뮬레이션/QA

목표:

- 출시 전 안정성 검증

작업:

- Smoke Simulation
- Balance Simulation
- Stress Simulation
- 위험 조합 테스트
- 로그 크기 측정
- 서버 계산 시간 측정
- 클래스/태그 승률 리포트

완료 조건:

- 크래시 없음
- 무한 루프 없음
- 로그 제한 초과율 낮음
- 세트 무승부 2% 이하
- 클래스 승률 위험 구간 없음
- p95 simulation time 목표 충족

## 13. M9: 클로즈 베타

대상:

- 내부 테스터
- 신뢰 가능한 소수 유저
- 일부 스트리머

목표:

- UX 이해도 확인
- 전투 리플레이 품질 확인
- 덱 편성 난이도 확인
- 서버 부하 측정

운영:

- 보상 없음 또는 테스트 배지
- 랭킹 초기화 예정 고지
- 버그 리포트 수집
- opt-out 플로우 검증

## 14. M10: 공개 베타

목표:

- 실제 유저 규모에서 빠른대전 검증
- MMR/랭킹 안정성 확인
- 밸런스 데이터 수집

조건:

- 전투 엔진 안정
- 리플레이 로그 보존 정책 작동
- 큐 만료 배치 작동
- 랭킹 스냅샷 작동
- 관리자 비활성화 가능

주의:

- 시즌 보상은 제한적
- 유료화 없음
- 랭킹은 베타 표기

- p95 API 성능 목표 충족
- 밸런스 긴급 위험 없음
- 보안/어뷰징 기본 대시보드 준비
- 시즌 보상 정책 확정
- 스트리머 opt-out 안내 완료

정식 시즌 포함:

- 랭크 빠른대전
- 봇 연습전
- 시즌 랭킹

- 카드 도감
- 덱 편성
- 리플레이
- 스트리머 카드 설정

## 16. QA 체크리스트

### 16.1 전투

- 같은 seed 재현
- 3:0 종료 시 4~5라운드 미계산
- 3:2 정상 종료
- 3무승부 타이브레이커
- 상태이상 지속시간
- 보호막 상한
- 회복 상한
- 소환수 상한
- 로그 이벤트 상한

### 16.2 덱

- 중복 카드 차단
- 비활성 카드 차단
- 시즌 풀 밖 카드 차단
- 라운드 플랜 복사
- 공통 플랜 적용
- 저장/수정/삭제

### 16.3 매칭

- 큐 등록
- 큐 취소
- 큐 만료
- 동시 매칭
- 같은 상대 반복 제한
- MMR 범위 확장

### 16.4 MMR/랭킹

- 승리 반영
- 패배 반영
- 무승부 반영
- 봇전 미반영
- 중복 반영 방지
- snapshot 생성

### 16.5 스트리머

- 본인 카드 조회
- config preview
- config request
- opt-out
- opt-in
- 관리자 disabled 상태

### 16.6 보안

- 다른 유저 덱 접근 차단
- 다른 유저 match 접근 차단

- rate limit
- CSRF 보호

## 17. 성능 체크리스트

필수 측정:

- 봇전 p95
- 빠른대전 quick join p95
- 세트 시뮬레이션 p95/p99
- replay 조회 p95
- ranking 조회 p95
- DB slow query
- memory usage
- battle log 평균 크기
- queue row 정리 속도

목표:

```text
set simulation p95 <= 300ms
set simulation p99 <= 700ms
status API p95 <= 100ms
ranking API p95 <= 150ms
average battle log <= 128KB
p95 battle log <= 256KB
```

## 18. 출시 전 필수 문서

추가로 준비해야 할 운영 문서:

- 패치노트 템플릿
- 시즌 공지 템플릿
- 스트리머 opt-out 안내문
- 베타 참여 안내
- 개인정보/리플레이 공개 정책
- 보상 지급 공지
- 장애 대응 Runbook

## 19. 반드시 지켜야 할 결정 사항

1. 봇전으로 전투 엔진을 먼저 검증한 뒤 빠른대전을 붙인다.
2. 유료화는 MVP와 공개 베타 이후로 미룬다.
3. 스트리머 opt-out은 초기 출시 범위에 포함한다.
4. 랭킹은 snapshot 기반으로만 출시한다.
5. 전투 로그 보존/삭제 배치를 출시 전에 구현한다.
6. 6GB RAM + MySQL 동시 운영 환경에서 성능 측정을 통과해야 한다.
7. 정식 시즌 전에 공개 베타를 거친다.

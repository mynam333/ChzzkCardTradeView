# 이미지 기반 신규 미니게임 기획서

작성일: 2026-09-10 · 분석 기준: Git `fd0db0a` · 대상: 아레나를 제외한 현재 미니게임 5종

**신규안은 사진 도미노, 사진 길 잇기, 사진 저울, 공통 사진 한 장 찾기 등 4종이다.** 모두 프로젝트가 사용하는 이미지를 재활용하고, 스트리머 이름이나 시세를 몰라도 화면 안의 정보만으로 풀도록 설계했다. 성공 보상은 기존과 같은 **1,000 P**, 보너스는 **+200 P**다.

새로운 플레이 경험을 우선하면 **사진 도미노**, 쉬운 진입과 구현 부담을 우선하면 **공통 사진 한 장 찾기**가 첫 개발 후보다. **사진 길 잇기**는 공간 판단을, **사진 저울**은 화면에 제시된 규칙을 이용한 추론을 추가한다. 4종을 동시에 출시하기보다 한 종씩 연습 모드에서 검증하는 편이 적절하다.

기본 가중 평가: **공통 사진 81점 · 도미노 75점 · 저울 74점 · 길 잇기 72점**. 항목별 점수와 감점 이유는 7절에 제시했다.

이 문서는 실제 코드 분석과 설계 평가다. 운영 DB의 이미지 분포·이용 통계, 실제 기기에서의 플레이 결과는 확인하지 않았다. 아래 시간은 제안 제한시간이고, 재미·직관성 점수는 동일 기준으로 비교한 예측이다. ‘모든 사람에게 불쾌함이 없다’거나 ‘세계 최초’라는 의미로 해석하지 않는다. **요구사항을 충족하도록 정한 설계와, 출시 전에 확인해야 할 조건을 함께 제시한다.**

## 1. 먼저 확인한 현재 5종

### 1.1 실제 규칙과 보상

서버에 등록된 게임은 `quiz`, `puzzle`, `match`, `value_duel`, `crop_detective`다. 과거 기획서의 ‘현재 3종’, ‘퀴즈 4지선다’ 설명은 현재 상태와 다르므로 분석 기준으로 사용하지 않았다. [종류·시간 상수][S1]

| 현재 게임 | 실제 플레이 | 플레이 제한시간 | 성공과 보너스 |
|---|---|---|---|
| 송출 오류난 스트리머 맞추기 | 흐린 카드 이미지를 보고 **이름 2개** 중 선택, 총 5문제 | 문제당 10초, 답안 시간 합계 50초 | 3~4정답 1,000 P / 5정답 1,200 P |
| 3×4 회전 퍼즐 | 12조각의 위치를 드래그로 교환하고 탭으로 90도 회전 | 최대 120초 | 완성 1,000 P / 30초 이내 완성 1,200 P |
| 스트리머 짝맞추기 | 프로필 6종을 두 장씩 배치. 전체 2초 공개 후 12장의 짝 찾기 | 공개 이후 30초 | 6쌍 완성 1,000 P / 10초 이내 완성 1,200 P |
| 시세 듀얼 | 두 카드 중 `base_value`가 더 높은 쪽 선택, 총 5문제. 동가면 양쪽 정답 | 문제당 10초, 답안 시간 합계 50초 | 3~4정답 1,000 P / 5정답 1,200 P |
| 카드 확대 탐정 | 확대·회전한 작은 부분 이미지를 보고 전체 카드 4개 중 출처 선택 | 문제당 10초, 답안 시간 합계 50초 | 3~4정답 1,000 P / 5정답 1,200 P |

퍼즐 힌트는 1회 사용 가능하며, 조각 번호를 2초 보여주고 제한시간을 10초 차감한다. 짝맞추기는 정답쌍 처리에 0.5초, 오답쌍을 다시 닫는 데 0.8초의 지연이 있다. 따라서 표시 시간 외에도 조작과 연출이 체감 난도에 영향을 준다. [퍼즐 UI][S2] · [짝맞추기 입력][S3]

50초는 라운드형 게임의 **답안 시간 합계**다. 카운트다운·결과 확인·통신까지 포함한 총 체류시간 상한이 아니다. 현재 라운드형 서버 세션에는 별도의 180초 제한이 있다. [서버 시간 정책][S1]

### 1.2 재미, 공정성, 이미지 활용의 차이

아래 장단점은 규칙과 구현에서 도출한 해석이며, 사용자 만족도를 측정한 결과는 아니다.

| 게임 | 재미와 숙련의 중심 | 이미지가 하는 역할 | 강점 | 새 기획에서 피할 문제 |
|---|---|---|---|---|
| 인물 퀴즈 | 흐린 단서에서 아는 인물을 알아보기 | 인물의 정체를 맞히는 단서 | 선택 한 번으로 끝나고 팬에게 익숙함 | 모르는 인물의 사진과 이름을 연결할 근거가 부족함. 이미지 난도와 사전지식 격차가 큼 |
| 회전 퍼즐 | 그림의 연결부를 읽고 위치·방향 복구 | 완성해야 할 실제 콘텐츠 | 이미지 자체가 게임의 중심이고 완성감이 큼 | 단색·대칭 조각의 구별 어려움, 탭/드래그 혼동, 긴 최대 시간 |
| 짝맞추기 | 위치 기억, 실패에서 얻은 정보 활용 | 기억해야 하는 동일성 표식 | 친숙한 규칙, 이름 없이 가능 | 2초 선공개와 10초 보너스에 기억·조작속도 부담. 비슷한 프로필 구별 문제 |
| 시세 듀얼 | 카드 시장에 대한 지식과 예상 | 시세를 떠올리는 표식 | 서비스의 수집·거래 맥락과 연결됨 | 숨겨진 시세는 사진만으로 논리적으로 알 수 없음. 비팬에게는 추측에 가까워질 수 있음 |
| 확대 탐정 | 부분과 전체를 대조하는 시각 탐색 | 직접 비교할 근거 | 사전지식이 없어도 화면에서 정답을 찾을 수 있음 | 작은 단색 부분, 회전, 닮은 보기 때문에 확신 없이 찍는 상황이 생길 수 있음 |

현재 부족한 영역은 **공개된 정보를 이용한 연결 순서 계획, 경로 계획, 짧은 관계 추론**이다. 새 게임은 이 행동을 추가하는 방향으로 기획한다. 원본을 조금 더 흐리게 만들거나 조각 수만 바꾸는 안은 기존 게임과의 차이가 작다.

### 1.3 현재 구현에서 확인한 주의점

| 코드에서 확인한 사항 | 신규 기획에 반영할 결정 |
|---|---|
| 퀴즈 로비에는 아직 ‘15초’, ‘3초 안 정답 보너스’가 표시되지만 실제 판정은 5문제×10초·만점 보너스다 | 규칙·제한시간·보상 문구를 하나의 정의에서 가져와 일치시킨다 |
| 정식 퀴즈는 서버의 고정 흐림 이미지다. 연습 경로의 점진 복원과 다르다 | 연습과 보상 모드의 게임 규칙·이미지 표시를 같게 검증한다 |
| 퀴즈는 현재 답안 처리 때 다음 마감시간을 만들지만 UI에는 수동 ‘다음 문제’가 있다 | 결과를 읽는 시간과 다음 문제 제한시간을 분리한다 |
| `getUniquePlayableImageCards`의 중복 제거 단위는 채널이다 | 채널이 달라도 사진 내용이 같으면 구별 가능한 두 이미지로 취급하지 않는다 |
| 확대 탐정은 빈 부분을 재시도하지만 전부 실패하면 마지막 실제 부분을 사용한다 | 새 출제기는 품질 실패를 억지 출제로 끝내지 않고 대체 문제를 선택한다 |
| 개인 블라인드 목록 조회 실패 시 현재는 빈 목록으로 진행할 수 있다 | 신규 보상 게임은 필터를 확인하지 못하면 준비 단계에서 멈추고 티켓을 차감하지 않는다 |

이 항목들은 **소스에서 확인한 분기와 불일치**다. 브라우저에서 직접 재현한 버그 보고는 아니다. [퀴즈 로비][S4] · [이미지 변환][S5] · [퀴즈 다음 마감시간][S6] · [이미지 후보·블라인드][S7]

## 2. 모든 신규안에 적용할 계약

### 2.1 보상과 참가 정책

| 항목 | 신규안 공통 규칙 |
|---|---|
| 한 게임 | 총 5라운드 |
| 0~2라운드 성공 | 0 P |
| 3~4라운드 성공 | 정확히 1,000 P |
| 5라운드 성공 | 1,000 P + 보너스 200 P = 1,200 P |
| 빠르게 성공 | 기록 표시만 가능. 추가 포인트 없음 |
| 실수·되돌리기 | 추가 포인트 차감 없음. 게임별 합법 조작 범위에서 수정 가능 |
| 현재 결과로 마치기 | 서버에서 이미 확정한 성공 수를 보존하고 남은 문제를 미응답 실패로 정산. 3개 이상 성공했다면 1,000 P 지급 |
| 연습 | 티켓 미소모, 포인트 0 P. 보상 모드와 같은 규칙·시간으로 연습 가능 |
| 보상 게임 | 기존 오늘의 게임 선정과 티켓 1개 소비 구조 사용 |
| 보유 포인트 | 실패로 기존 잔액을 차감하지 않음. 참가 티켓 소모는 시작 전에 표시 |

현재 금액은 운영 설정키가 아니라 서버의 `BASE_REWARD = 1000`, `BONUS_REWARD = 200` 상수다. 각 DB 정산 구현도 `0 / 1000 / 1200`만 허용한다. 새 게임만의 점수 환율·콤보 배수·구간별 부분 보상은 추가하지 않는다. [보상 상수와 판정][S8] · [정산 허용액][S9]

기본 티켓은 최대 5개이며 충전 주기의 코드 기본값은 240분이다. 운영 설정으로 바뀔 수 있으므로 실제 운영 주기를 4시간으로 단정하지 않는다. 연습은 오늘의 게임 제한을 받지 않는다. 신규 게임을 오늘의 게임 목록에 추가하면 날짜별 선정 결과가 달라질 수 있으므로 KST 날짜 경계에서 적용하고, 이미 시작한 세션의 게임·보상을 보존한다. [충전·일일 선정][S10]

**동일 금액과 동일 체감 난도는 별개다.** 기대 지급량은 `1,000 × 성공 확률 + 200 × 만점 확률`이다. 실제 성공률 없이 다른 게임과 경제 효과까지 같다고 주장할 수 없다. 조정은 판의 복잡도와 읽을 수 있는 시간으로 하며, 포인트 금액을 바꾸거나 일부러 알아보기 힘든 사진을 넣는 방식은 사용하지 않는다.

### 2.2 짧은 플레이의 수치 기준

| 게임 | 라운드 제한 | 실제 조작 시간 상한 | 정상 통신에서 카운트다운·전환 포함 목표 상한 |
|---|---:|---:|---:|
| 공통 사진 한 장 찾기 | 10초×5 | 50초 | 약 57초 |
| 사진 도미노 | 12초×5 | 60초 | 약 67초 |
| 사진 길 잇기 | 12초×5 | 60초 | 약 67초 |
| 사진 저울 | 12초×5 | 60초 | 약 67초 |

카운트다운은 최초 3초, 중간 피드백은 최대 1초씩 4회다. 마지막 답안 이후는 결과 화면으로 넘어간다. 일찍 풀면 즉시 다음 라운드로 진행할 수 있어 상한만큼 기다릴 필요가 없다. 3라운드 성공·3라운드 실패만으로 강제 종료하지 않는다. 계속 플레이하거나 ‘현재 결과로 마치기’를 선택할 수 있다. 종료 버튼에는 서버에서 확인한 현재 지급 예정액을 표시해, 이미 확보한 3승 보상을 종료 때문에 잃지 않게 한다.

이 조기 종료는 기존 `abandon`의 0 P 처리와 다른 **신규 제안**이다. 남은 문제를 미응답 실패로 확정한 뒤 같은 `0 / 1000 / 1200` 정산표를 적용한다. 라운드당 부분 포인트를 지급하는 방식은 아니다. 답안 처리 중에는 그 판정이 끝난 뒤 종료를 처리한다.

이미지 준비는 티켓 소비 전 최대 10초를 목표로 별도 처리한다. 이 시간이 넘으면 끝없이 로딩하지 않고 재시도 가능한 준비 실패 화면을 보여준다. 성공적으로 준비되는 경우 시작 버튼부터 결과까지의 목표는 최대 약 67~77초다. 네트워크 장애·이용자의 결과 읽기까지 절대 시간 상한을 보장한다는 뜻은 아니다.

타이머를 모든 게임에 10초로 맞추지 않은 이유는 조작량 때문이다. 보기 하나를 고르는 게임과 여러 패·경로를 놓는 게임에 같은 시간을 주면 손의 속도가 지나치게 중요해진다. **12초 역시 플레이 테스트 전 초기값**이며, 늦은 기기를 불리하게 만드는 연출이나 추가 숨은 벌점은 두지 않는다.

### 2.3 이미지와 조작의 공통 품질

| 조건 | 구체적 설계 |
|---|---|
| 기존 이미지 사용 | 현재 카드 이미지 선택 함수를 활용한다. 요청 등급부터 낮은 등급의 등록 이미지를 찾고 최종적으로 로고를 사용한다. 선택 완료 후에는 같은 원본을 고정한다 |
| 동일성 | 같은 사진은 **같은 버전의 디코딩 결과와 표시 영역**을 사용한다. 같은 스트리머의 다른 사진을 같은 그림으로 판정하지 않는다 |
| 원본 표시 | 얼굴을 임의로 자르거나 변형하지 않고 전체 이미지를 공통 프레임 안에 표시한다. 화면에서 비교하는 모든 위치의 비율·여백 규칙을 동일하게 한다 |
| 구별 가능성 | URL 정규화와 콘텐츠 중복 검사 후, 실제 표시 크기에서 유사한 사진을 함께 쓰지 않는 검사를 추가한다. 해시만으로 사람의 구별 가능성이 보장되지는 않는다 |
| 이미지 품질 | 누락·투명·지나치게 작거나 거의 단색인 이미지는 후보에서 제외. 인물·방송 분야를 알아야만 구별되는 사진 조합도 제외 |
| 차단·제외 | 개인 블라인드를 반드시 존중한다. 퍼즐 전용 제외 목록의 사유를 확인해 새 게임에 필요한 제외 규칙을 적용한다. 모든 퍼즐 제외 사진을 무조건 불량 이미지로 간주하지 않는다 |
| 로딩 실패 | 문제 중 한 위치만 로고로 바꾸지 않는다. 준비 전에는 해당 원본 전체를 교체하고 다시 검증한다. 시작 후에는 같은 문제 복구 또는 검증된 장애의 무효 처리를 사용한다 |
| 입력 | 선택은 큰 버튼 전체를 터치한다. 드래그가 있는 게임은 탭 조작도 제공한다. 조립 중 잘못 누른 칸·패에는 포인트 벌점을 주지 않는다 |
| 정보 표시 | 이름·시세·별 등급은 정답 판단에 쓰지 않는다. 필요한 규칙·목표·진행 상황은 계속 표시한다 |
| 시각 부담 | 색만으로 판정하지 않고 테두리·연결선·형태도 사용한다. 점멸, 강제 화면 흔들림, 강한 실패음, 연속 입력을 막는 긴 연출은 사용하지 않는다 |

모바일 주요 조작 영역은 **44×44 CSS px 이상**, 사진을 읽어야 하는 영역은 **짧은 변 48px 이상을 초기 목표**로 잡는다. 이는 이 기획의 여유 있는 제품 기준이다. WCAG 2.2의 최소 타깃 기준은 예외를 포함한 24×24 CSS px이며, 44px가 해당 기준의 필수값이라는 뜻은 아니다. 드래그의 탭 대안도 제공한다. [W3C 타깃 크기](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) · [W3C 드래그 대체 조작](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)

규칙을 보이게 유지하고, 되돌릴 수 있게 하며, 실수를 유발하는 조건을 줄이는 평가 방향은 일반적인 사용성 원칙을 참고했다. 이 원칙이 게임의 재미를 증명해 주는 것은 아니다. [Nielsen의 사용성 원칙](https://www.nngroup.com/articles/ten-usability-heuristics/)

## 3. 사진 도미노 — 어떤 순서로 이어야 모두 쓸 수 있을까

**한 줄 규칙: “같은 사진끼리 이어서 모든 패를 사용하고, 도착 사진까지 연결하세요.”**

두 칸짜리 패에 프로젝트 사진을 한 장씩 넣는다. 패의 접점에 같은 사진이 오도록 연결하는 작은 도미노 퍼즐이다. 사진은 계속 공개된다. 기존 회전 퍼즐의 그림 복구와 달리, 여기서는 **남은 패를 모두 사용할 연결 순서**를 판단한다.

### 플레이와 화면

화면 위에는 출발 사진과 도착 사진, 중앙에는 연결 중인 사슬, 아래에는 남은 패를 보여준다. 세로 화면에서는 사슬을 큰 2열 지그재그 칸으로 배치하고 연결 화살표를 고정 표시한다. 작은 한 줄에 모든 사진을 욱여넣지 않는다.

1. 남은 패를 탭하면 현재 사슬 끝에 붙인다. 접점을 맞추는 좌우 방향은 자동으로 정한다. 사진 자체를 뒤집거나 회전시키지 않는다.
2. 현재 끝과 맞지 않는 패는 붙지 않는다. 짧은 테두리 피드백만 주며 패를 잃거나 추가 시간·점수 벌점을 받지 않는다. 라운드 타이머는 계속 흐른다.
3. ‘한 수 되돌리기’로 마지막 패를 돌려놓을 수 있다. 현재 가능한 패만 강조하거나 정답 순서를 추천하지 않는다.
4. 모든 패를 쓰고 도착 사진에 닿으면 라운드 성공이다. 중간에 도착에 닿아도 남은 패가 있으면 완료가 아니다.

다음은 사진을 문자로 바꿔 표시한 설명용 예시다. 실제 게임에는 A·B·C·D 문자 대신 프로젝트 사진이 나온다.

```text
출발 A                           도착 D
남은 패: [A | B] [B | C] [C | A] [A | D]

가능한 완성: A → B → C → A → D
다른 완성: A → C → B → A → D
```

`A–D`를 먼저 사용하면 나머지를 붙일 수 없다. 이를 보고 해당 패를 마지막에 남기는 것이 작은 전략이다. 막히더라도 마지막 패를 되돌려 수정할 수 있다. **위 두 완성 경로를 모두 정답으로 인정한다.**

### 출제·난도·판정

| 항목 | 기획 |
|---|---|
| 구성 | 5라운드×12초. 1~2라운드 3패, 3~5라운드 4패를 초기 구성으로 사용 |
| 학습 | 3패 라운드는 접점·도착 조건을 익히는 쉬운 판. 후기 판에는 합법적으로 붙일 수 있는 첫 패가 둘 이상인 작은 분기를 포함 |
| 금지 | 모든 판이 단순 사슬인 출제, 끝없는 막힘, 이중 패의 식별 혼란, 사진을 작게 만들어 올리는 난도 |
| 판 생성 | 먼저 완성 가능한 사슬·순환+꼬리 등 검증된 구조를 고르고 사진과 패 순서를 치환. 완전탐색으로 실제 해법 존재 확인 |
| 정답 | 출발·도착, 패 전부 정확히 1회 사용, 모든 접점의 사진 일치를 서버에서 검사. 저장된 예시 순서와 달라도 합법하면 성공 |
| 보상 | 3~4라운드 완성 1,000 P / 5라운드 완성 1,200 P. 되돌린 횟수와 무관 |
| 조작량 | 최적 플레이는 라운드당 패 3~4번 탭. 수정에 필요한 추가 조작은 별도 측정 |

**게임성의 한계:** 4패로 만들 수 있는 의미 있는 분기는 제한적이다. 예시처럼 마지막 패를 남기는 구조만 반복하면 요령을 익힌 뒤 단조로워진다. 사진 변경만을 새 문제로 계산하지 않고 구조별 반복률을 관리한다. 5패 확장은 터치 시간과 사진 크기가 검증된 뒤 고려하며 초기 출시 요건에는 포함하지 않는다.

**구현 범위:** 패·사슬 상태, 탭 부착·되돌리기, 소규모 그래프 출제·검증, 서버 조립 답안이 필요하다. 물리엔진이나 AI 이미지 분석은 필요 없다. 4패의 순열·방향 조합은 최대 `4! × 2⁴ = 384`로 작지만, 해법 검증이 쉽다는 것과 재미있는 판을 만드는 것은 별개의 문제다.

**출시 조건:** 실제 모바일에서 출발/도착과 자동 방향을 설명 없이 이해하고, 후기 판에서 선택의 이유를 말할 수 있어야 한다. 길이만 다른 강제 사슬만 만들어지는 출제기는 게임성 조건 미달이다.

## 4. 사진 길 잇기 — 다른 사진의 길을 남겨 두세요

**한 줄 규칙: “같은 사진끼리 길을 이으세요. 길은 서로 겹칠 수 없고, 빈칸은 남아도 돼요.”**

4×4 격자에 같은 사진 두 장씩을 끝점으로 놓는다. 플레이어는 같은 사진끼리 상하좌우 경로를 만든다. 전체 그림을 복구하거나 카드 위치를 기억하는 대신, **다른 쌍이 지나갈 공간을 남기는 판단**을 한다.

### 플레이와 화면

격자는 화면 중앙에 고정한다. 경로의 끝점에는 같은 원본 사진을 표시하고, 연결선은 보조 색·패턴으로 구분한다. 색은 사진 동일성의 대체 정답이 되지 않는다.

1. 한 사진에서 같은 사진까지 드래그하거나, 시작 사진을 누른 뒤 인접 칸을 차례로 탭한다.
2. 대각선 이동, 다른 쌍의 끝점 통과, 경로 교차는 허용하지 않는다. 잘못된 입력은 직전 유효 칸을 유지한다.
3. 뒤로 되짚으면 현재 길을 줄인다. 완성된 쌍의 사진을 누르면 그 쌍의 길만 다시 그릴 수 있다.
4. 모든 사진 쌍을 연결하면 성공한다. 비어 있는 칸은 실패 이유가 아니다.

```text
A · · B
· · · ·
· A · ·
B · · ·

한 가지 해법:
A: (1,1) → (1,2) → (2,2) → (3,2)
B: (1,4) → (2,4) → (3,4) → (4,4) → (4,3) → (4,2) → (4,1)
```

문자는 실제 사진을 대신한 표기다. 좌표는 기획 설명용이며 게임에서 좌표 계산을 요구하지 않는다. 위처럼 연결 가능하다는 사실만으로 적절한 난도라고 판단하지 않는다. 출시 판에는 짧게 우회할 이유가 있는 배치도 포함한다.

### 출제·난도·판정

| 항목 | 기획 |
|---|---|
| 구성 | 5라운드×12초, 4×4 격자·2쌍 고정으로 초기 출시 |
| 난도 | 초반은 독립 경로, 후반은 한 쌍의 직선 경로가 다른 쌍의 통로를 막는 작은 혼잡을 활용. 장시간 탐색하는 미로는 제외 |
| 길이 | 두 경로의 합계 방문 칸 6~12칸을 초기 필터로 삼고 실제 손가락 조작 시간으로 조정. 끝점도 방문 칸에 포함 |
| 판 생성 | 서로 겹치지 않는 완성 경로에서 끝점을 추출한 뒤 경로 탐색으로 다시 검증. 좌표만 무작위로 뿌리지 않음 |
| 정답 | 모든 쌍 연결, 상하좌우 인접, 다른 끝점 침범 없음, 경로 간·자기 경로 내 중복 없음. 저장된 해답과 달라도 조건을 만족하면 인정 |
| 보상 | 3~4라운드 완성 1,000 P / 5라운드 완성 1,200 P. 경로 수정에 추가 벌점 없음 |
| 제외 | 막힌 판, 모든 쌍이 바로 인접한 판의 반복, 격자 밖 우회, 보이지 않는 장애물, 제한시간 중 무작위 판 변경 |

손가락이 칸 경계를 조금 벗어나도 가까운 인접 칸에 붙도록 하되, 멀리 떨어진 칸까지 자동으로 경로를 풀어주지는 않는다. 미세한 입력 오차를 보정하고 공간 판단은 플레이어에게 남긴다.

**게임성의 한계:** 4×4·2쌍·빈칸 허용은 쉬운 배치가 많다. 반대로 난도를 급격히 높이면 짧은 게임의 장점이 사라진다. 후기 판에서 한 번 정도 우회를 판단하게 하는 정도로 제한한다. 3쌍과 ‘모든 칸 채우기’는 초기 규칙에 추가하지 않는다.

**이미지 활용의 한계:** 사진은 연결 대상을 식별하는 필수 표식이지만, 사진의 표정·배경 자체를 분석하는 게임은 아니다. 이미지 콘텐츠를 깊이 관찰하는 경험은 공통 사진이나 기존 확대 탐정이 더 강하다.

**구현 범위:** 격자 상태, 경로 편집·스냅, 터치/탭 대안, 경로 탐색기, 서버 경로 검증이 필요하다. SVG 연결선과 일반 웹 UI로 구현 가능하다. 네 후보 중 입력·출제 검증 부담이 가장 크다.

**출시 조건:** 최소 화면에서 드래그와 탭 모두로 완주하고, 합법적인 대체 경로가 거절되지 않아야 한다. 정답 경로를 찾았는데 손가락 오차로 지워지는 문제가 남으면 보상 게임으로 출시하지 않는다.

## 5. 사진 저울 — 보이는 균형을 다른 묶음에 적용하세요

**한 줄 규칙: “위 저울을 보고, 아래 묶음과 무게가 같은 사진 묶음을 고르세요.”**

사진이 찍힌 토큰을 사용하는 짧은 치환 퍼즐이다. 사람의 몸무게나 카드의 실제 가격을 묻지 않는다. **균형 관계를 화면에 모두 공개하고**, 그 관계만으로 답을 증명할 수 있게 한다. 현재 시세 듀얼처럼 외부 지식이나 숨겨진 수치를 추측하지 않는다.

토큰의 무게는 모두 양수로 정의한다. 0이나 음수의 숨은 예외는 없으며, 같은 사진 토큰은 항상 같은 무게다.

### 플레이와 화면

상단에 균형 예시, 중앙에 맞춰야 할 묶음, 하단에 사진 묶음 보기 4개를 세로로 배치한다. 사진을 2×2 보기 안에 작게 넣지 않고 행 전체를 선택 버튼으로 쓴다. 한 묶음은 최대 3장이다.

```text
위의 균형:  [A]       = [B][B]
찾을 묶음:  [A][B]    = ?

보기 1  [B][B][B]   ← 정답
보기 2  [A][A]
보기 3  [B][B]
보기 4  [B]
```

플레이어는 A 한 장을 B 두 장으로 바꾸면 B 세 장이 된다는 사실을 이용한다. 실제 화면은 저울·사진으로 보여주며 문자 수식 입력을 요구하지 않는다.

보기 선택 후 ‘확정’을 누른다. 확정 전에는 자유롭게 바꿀 수 있고, 확정 후에는 해당 라운드를 종료한다. 오답이라면 `A 한 장 ↔ B 두 장`의 교환을 짧게 보여주어 정답의 이유를 설명한다.

### 출제·난도·판정

| 항목 | 기획 |
|---|---|
| 구성 | 5라운드×12초. 초기 버전은 사진 2종·균형 관계 1개 중심 |
| 사고량 | 한 종류의 치환 규칙을 한 번 적용하거나 묶는 정도. 연립방정식·숨은 무게 찾기 제외 |
| 템플릿 | `A=BB`에서 `AB→BBB`, `BBB→AB`, `AA→ABB`, `ABB→AA` 등을 섞는다. 목표와 완전히 같은 묶음을 정답 보기로 복사하지 않음 |
| 보기 | 최대 3장씩 4보기. 주어진 관계에서 정답이 정확히 1개여야 함. 오답이 왜 다른지도 같은 정보로 판정 가능해야 함 |
| 판 생성 | 검증된 기호 템플릿에 서로 구별되는 실제 사진을 대입. 내부 임의 무게만으로 정답을 만드는 방식 금지 |
| 정답 | 서버가 발급한 보기 ID와 공개 관계에서 증명된 정답을 비교. 한 라운드 최종 확정 1회 |
| 보상 | 3~4정답 1,000 P / 5정답 1,200 P. 반응속도에 따른 추가 지급·삭감 없음 |

`A=B+C` 한 줄만 보여주고 B와 C 중 더 무거운 것을 묻는 문제는 출제하지 않는다. 보이는 정보로 관계를 결정할 수 없기 때문이다. 내부에 정답 숫자가 존재하는 것만으로 공정한 문제가 되지 않는다.

**게임성의 한계:** 새로운 사진을 넣어도 같은 교환만 반복하면 계산 과제처럼 느껴질 수 있다. 여러 템플릿과 정방향·역방향 치환을 섞되, 재미 부족을 해결하려고 관계식을 늘리거나 보기 사진을 작게 만드는 것은 피한다. 네 후보 중 규칙 설명과 반복 재미의 검증 필요성이 크다.

**이미지 활용의 한계:** 사진은 치환할 대상을 구분하는 기호다. 이미지를 보고 플레이할 수 있지만 그림의 내용 자체를 활용하는 깊이는 낮다. 이름을 몰라도 된다는 요구와, 그림의 특성을 적극 활용한다는 특성은 구분해서 평가한다.

**구현 범위:** 저울·묶음 UI, 작은 템플릿 출제기, 사진 대입, 보기 ID 채점이면 된다. 물리 시뮬레이션은 필요 없으며 균형 애니메이션은 장식으로만 사용한다. 정답 유일성은 공개 관계를 단순화한 계수로 검증한다.

**출시 조건:** 한 번의 예시 뒤 ‘어떻게 답을 알았는지’를 비팬도 설명할 수 있어야 한다. 숫자를 적거나 오래 계산해야 하는 문항은 초기 풀에서 제외한다.

## 6. 공통 사진 한 장 찾기 — 두 앨범에 함께 있는 사진

**한 줄 규칙: “위아래 앨범에 모두 있는 사진 한 쌍을 찾으세요.”**

위·아래 두 앨범에 사진을 6장씩 배치한다. 두 앨범이 공유하는 사진은 정확히 한 장이며, 나머지는 서로 다르다. 이미지는 가리거나 확대하지 않고 계속 보여준다.

```text
위 앨범       아래 앨범
A  B  C       G  H  D
D  E  F       I  J  K

정답: 양쪽의 D 사진
```

실제 휴대폰에서는 두 앨범을 위아래로 배치하고 각각 2행×3열로 만든다. 한쪽에서 사진을 고르고 다른 쪽의 같은 사진을 고른 뒤 ‘확정’한다. 확정 전 수정은 자유롭고, 한 라운드 최종 확정은 1회다. 후보를 반복해서 눌러 정답 여부를 탐색하는 방식은 허용하지 않는다.

| 항목 | 기획 |
|---|---|
| 구성 | 5라운드×10초. 앨범당 6장으로 고정 |
| 이미지 수 | 한 문제에 서로 다른 사진 11종, 배치 12칸. 한 앨범 내부 중복 0, 두 앨범 교집합 정확히 1 |
| 숙련 | 특징이 선명한 사진부터 훑고, 확인한 후보를 제외하며 비교 범위를 줄이는 시각 탐색 |
| 출제 | 이미지 내용의 중복·유사성 검사 후 공통 사진 1종과 나머지 10종 선택. 정답 위치를 양쪽에서 독립적으로 섞음 |
| 정답 | 양쪽에서 선택한 인스턴스가 출제된 공통 이미지의 두 배치인지 서버 판정 |
| 보상 | 3~4정답 1,000 P / 5정답 1,200 P |
| 금지 | 정답만 크게 표시, 닮은 얼굴·다른 버전 사진으로 혼동 유발, 한쪽만 회전·반전, 진행 중 재배치 |

**차별점과 한계:** 기존 짝맞추기의 위치 기억이나 확대 탐정의 부분 복원이 아니라 두 집합의 즉시 대조다. 조작과 설명은 가장 가볍지만, ‘같은 이미지 찾기’라는 큰 행동은 기존 게임과 가까워 신규성은 중간 수준이다. 독특한 신작을 최우선으로 선택한다면 이 약점을 총점과 별도로 고려해야 한다.

**구현 범위:** 두 이미지 집합, 선택·확정 UI, 교집합 출제 검증, 서버 두 인스턴스 채점이다. 게임 고유 기능은 가장 단순하지만, 11종의 사진을 동시에 구별 가능하게 고르는 품질 검사는 필요하다.

**출시 조건:** 360px 폭의 작은 화면에서 두 앨범·버튼·타이머를 스크롤 없이 볼 수 있고 사진을 구별할 수 있어야 한다. 사진을 더 작게 만들어 억지로 맞추지 않는다. 적합한 이미지 11종을 확보하지 못하면 티켓 소비 전에 시작을 보류한다.

## 7. 같은 기준으로 비교한 평가

### 7.1 총점으로 덮을 수 없는 필수 조건

아래 ‘충족’은 문서에 정한 범위로 구현할 경우의 설계 판정이다. 실제 출시 통과를 뜻하지 않는다. 네 안 모두 프로젝트의 현재 5종에 없는 규칙 구성을 제안하며, 그중 도미노·길 잇기·저울은 새로운 판단 행동을 추가하는 세 후보다.

| 필수 조건 | 도미노 | 길 잇기 | 저울 | 공통 사진 |
|---|---|---|---|---|
| 프로젝트의 기존 이미지 사용 | 충족 | 충족 | 충족 | 충족 |
| 스트리머 지식 없이 화면만으로 해답 도출 | 충족 | 충족 | 공개 관계로 충족 | 충족 |
| 짧은 한 판 | 60초 조작 상한 | 60초 조작 상한 | 60초 응답 상한 | 50초 응답 상한 |
| 동일 1,000 P / +200 P 정량 보상 | 충족 | 충족 | 충족 | 충족 |
| 운 때문에 해결 불가능한 문제 배제 | 해법 검사 | 경로 검사 | 정답 유일성 검사 | 교집합·시각 중복 검사 |
| 정답 근거·실수 처리의 납득 가능성 | 접점 확인·되돌리기 | 경로 확인·수정 | 교환 과정 설명 | 같은 원본 대조 |
| 현실적인 웹 구현 | 소규모 조립·그래프 | 격자·경로 편집 | 템플릿·선택 UI | 집합 생성·선택 UI |
| 게임성의 핵심 | 순서 계획 | 공간 확보 | 관계 치환 | 탐색 순서 |

필수 검사가 실패한 문제는 낮은 점수를 주고 출시하는 대상이 아니라 **출제에서 제외할 대상**이다. ‘쉽고 직관적’, ‘불쾌하지 않음’, ‘게임성이 있음’은 사용자 반응을 포함하므로 다음 절의 점수와 출시 실험을 함께 봐야 한다.

### 7.2 평가 방법

점수는 1~5 정수이며, 가중 총점은 `Σ(항목 점수 ÷ 5 × 가중치)`로 계산한다. 프로젝트 분석 후 별도의 비판 검토를 거쳐 단순 사슬 반복, 터치 부담, 이미지가 기호로만 쓰이는 한계 등을 감점했다. 이는 설계 판단을 드러내는 비교표이며 통계적 객관성을 주장하는 수치가 아니다.

| 항목 | 가중치 | 평가 질문 |
|---|---:|---|
| 직관성·친숙함 | 15 | 한 문장과 예시로 첫 행동을 알 수 있는가? |
| 게임성·숙련 | 20 | 반복 클릭 외에 판단·계획이 있고, 잘하게 될 여지가 있는가? |
| 프로젝트 내 새로움 | 15 | 현재 5종과 다른 핵심 사고·행동을 제공하는가? |
| 공정성·불쾌감 억제 | 15 | 해답과 실패 이유가 납득되고, 사진·기기·조작 오류에 덜 흔들리는가? |
| 이미지·지식 독립성 | 10 | 실제 프로젝트 사진을 사용하며 이름·가격 지식 없이 풀 수 있는가? |
| 짧은 시간 적합성 | 10 | 생각·입력·전환을 짧은 범위에 담을 수 있는가? |
| 구현·운영 가능성 | 10 | 현재 기술로 출제·판정·품질 관리를 현실적으로 할 수 있는가? |
| 반복성 | 5 | 사진뿐 아니라 의미 있는 문제 구성이 달라지는가? |

공통 척도는 **1: 요구와 충돌 / 2: 큰 보완 필요 / 3: 가능하지만 명확한 약점 / 4: 잘 맞으며 검증 과제 존재 / 5: 규칙 구조상 특히 유리**다. 재미·반복성 5점은 현재 제안에 부여하지 않았다. 새로움은 세계 시장의 독창성 순위가 아니다.

| 후보 | 직관 15 | 게임성 20 | 새로움 15 | 공정 15 | 이미지 10 | 시간 10 | 구현 10 | 반복 5 | 총점 /100 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 공통 사진 한 장 찾기 | 5 | 3 | 3 | 4 | 5 | 5 | 5 | 3 | **81** |
| 사진 도미노 | 4 | 3 | 4 | 4 | 5 | 4 | 3 | 3 | **75** |
| 사진 길 잇기 | 4 | 3 | 4 | 3 | 5 | 4 | 3 | 3 | **72** |
| 사진 저울 | 3 | 3 | 4 | 4 | 5 | 4 | 4 | 3 | **74** |

| 후보 | 높은 점수의 이유 | 주요 감점 근거 | 점수가 달라질 수 있는 확인 사항 |
|---|---|---|---|
| 공통 사진 | 규칙·입력·기술이 단순하고 전체 사진을 직접 비교 | 기존의 같은 그림 찾기와 유사, 전략 깊이·반복 변화 제한 | 두 앨범의 작은 화면 가독성, 유사 이미지 발생률 |
| 도미노 | 기존에 없는 연결 순서 판단, 수정 가능, 모든 합법해 인정 | 3~4패에서는 강제 사슬이나 같은 분기 반복이 되기 쉬움. 흥미로운 출제 비용 | 실제 분기 선택 비율, 자동 방향 이해, 4패 반복의 재미 |
| 길 잇기 | 공간을 남기는 판단, 이름 없이 해결 가능한 규칙 | 터치 편집 부담, 쉬운 판·막힌 판을 걸러낼 출제 부담 | 입력 때문에 실패하는 비율, 경로 수정 횟수, 후기 판의 적정 난도 |
| 저울 | 시세 지식 대신 공개 정보로 증명, 작은 템플릿으로 구현 | 규칙을 수식처럼 느낄 수 있고 사진은 주로 기호 역할, 반복 치환 피로 | 첫 예시 이해율, 계산 과제로 느끼는지, 작은 화면의 보기 크기 |

**선택 해석:** 총점이 가장 높은 공통 사진은 직관성과 구현 부담에서 유리하다. 사용자의 ‘새롭고 독특한 게임’을 더 우선하면 도미노를 먼저 시험할 이유가 있다. 길 잇기와 저울의 2점 차이를 확실한 우열로 해석하지 않는다. 예를 들어 게임성 점수를 1점만 다르게 평가해도 총점은 4점 변한다.

가중치의 영향도 있다. 새로움 25·게임성 25·직관 10·공정 15·이미지 10·시간 5·구현 5·반복 5로 바꾸면 공통 사진과 도미노는 모두 75점이다. 따라서 가중치를 숨긴 단일 순위만으로 결정을 내리기보다, **직관성 우선인지 새로운 사고 경험 우선인지**를 함께 봐야 한다.

### 7.3 검토 후 우선순위를 낮춘 방향

| 방향 | 장점 | 이번 요구에 약한 이유 |
|---|---|---|
| 사진 몇 장을 숨긴 뒤 바뀐 한 장 찾기 | 구현이 쉽고 기억 게임으로 친숙 | 기존 짝맞추기와 기억 부담이 겹쳐 신규성이 작음 |
| 이미지에 작은 차이를 자동 생성하는 틀린그림찾기 | 사진 관찰이 중심이고 익숙함 | 의미 없는 배경 변화, 작은 차이, 이미지 훼손을 피하려면 별도 품질 검증 비용이 큼 |
| 카드 이미지 리듬·순간 반응 게임 | 규칙과 결과가 즉각적 | 지연·기기·손의 속도 영향이 커지고 사진은 장식에 가까워질 수 있음 |
| 더 흐린 사진·실루엣으로 인물 맞히기 | 기존 구조를 재사용하기 쉬움 | 스트리머 지식 의존과 이미지별 모호함이 남고 퀴즈·탐정과 가까움 |
| 카드 이미지 벽돌깨기·장시간 합치기 | 익숙한 조작, 반복할 거리 | 사진 활용이 약하거나 종료 시간이 길어지기 쉬워 현재 목표와 덜 맞음 |

| 오늘의 게임 | KST 날짜별 선정과 연습 구조 | 신규 목록 반영, 날짜 경계 전후·기존 세션 검증 |

현재 이미지 보호 토큰은 `quiz | crop`만 지원한다. 신규 게임에 범용 보호 이미지 참조가 필요하면 종류·유효기간·세션 귀속을 확장해야 한다. 이미 모든 신규 이미지에 적용할 수 있는 기능이라고 가정하지 않는다. [이미지 토큰][S11]

프런트 `GameType`, 서버 `MinigameType`, 시작 허용 목록, 라운드 판별, 세 DB repository와 Postgres RPC 등을 함께 확인해야 한다. 게임 종류 컬럼은 현재 TEXT/VARCHAR 계열이지만 새 준비 상태·무효 처리 계약은 DB 변경이 필요할 수 있다. ‘화면 한 개만 추가하면 완료’인 작업이 아니다. [세션 인터페이스][S12] · [API 경로][S13]

### 8.2 시작·실패·복구

권장 흐름은 `준비 → 이미지 검증 → 티켓 소비·시작 확정 → 라운드 진행 → 서버 정산`이다. **현재 공통 기능이 아니라 신규 구현 제안**이다.

1. 준비 단계에서는 개인 블라인드, 사용 가능한 사진, 생성된 문제의 정합성을 확인한다. 클라이언트는 이미지를 미리 받아 디코딩한다. 문제 배치·해답 관계는 시작 확정 전 노출하지 않는다.
2. 준비는 사용자별 한 건으로 제한하고 유효기간을 둔다. 시작 확정 시 오늘의 게임·티켓·세션 상태를 다시 확인하고 티켓 한 개를 원자적으로 소비한다.
3. 각 라운드는 앞선 피드백과 필요한 이미지 준비가 끝난 뒤 한 번만 시작한다. 프런트 입력 가능 상태와 서버 마감시간을 맞춘다. 준비 확인 신호를 보냈다는 사실만으로 서버가 실제 화면 표시를 완벽히 증명할 수는 없다.
4. 정답·오답 또는 제한시간 종료 후 다음 라운드로 진행한다. 네트워크 대기는 진행 중임을 표시하고 사용자에게 끝없는 대기를 강요하지 않는다. 타이머를 다시 시작해 추가 풀이 시간을 무한히 얻을 수 없게 한다.
5. 재연결은 같은 문제·같은 마감시간과 서버에 확정된 라운드 진행을 복구한다. 도미노 배치와 그리는 중인 경로는 유효 조작마다 세션·라운드·문제 버전에 묶어 로컬에 저장하고, 같은 기기에서 재개할 때 서버 문제와 대조해 복원한다. 다른 기기로의 미완성 편집 이전은 초기 범위에서 제외한다. 로컬 편집 상태는 정답·보상 증거로 신뢰하지 않는다. 이미 서버가 받은 답안은 중복 처리하지 않는다.
6. 서버에서 확인한 이미지·세션 장애로 게임이 성립하지 않으면 결과를 무효 처리하고 소비한 티켓 종류를 한 번만 복구한다. 포인트와 환급을 동시에 중복 지급하지 않는다. 클라이언트의 단순 실패 주장만으로 반복 환급하지 않는다.

현재 포기와 세션 만료에는 자동 티켓 반환이 없다. 따라서 위 무효·복구 기능을 이미 존재한다고 보고 구현 비용에서 빼면 안 된다. 신규의 ‘현재 결과로 마치기’도 티켓을 반환하는 동작은 아니다. 사용자 종료, 실제 플레이 시간 초과, 서버가 확인한 장애를 구분한다. [현재 포기 처리][S14] · [원자적 정산][S9]

### 8.3 답안과 부정 지급 검증

| 게임 | 클라이언트 제출 | 서버 판정 |
|---|---|---|
| 도미노 | 세션·라운드·패 인스턴스 순서와 방향 | 발급한 패인지, 중복 사용 없는지, 접점·출발·도착·전 패 사용 조건 |
| 길 잇기 | 각 쌍에 연결한 칸 ID 순서 | 발급한 끝점, 인접성, 격자 범위, 교차·다른 끝점 침범 여부 |
| 저울 | 선택한 보기 인스턴스 ID | 공개 관계에서 유일하게 성립하는 보기와 일치 |
| 공통 사진 | 양쪽에서 선택한 사진 인스턴스 ID | 각 앨범 소속과 공통 이미지 쌍 일치 |

현재의 `selected_channel_id`를 경로나 사진 묶음 답안에 억지로 사용하지 않는다. 게임별 답안 스키마를 두고 서버가 문제·판정·포인트를 소유한다. 클라이언트가 보낸 성공 여부·보상액·자의적 남은 시간만 믿지 않는다.

‘현재 결과로 마치기’ 요청은 서버에 확정된 성공 수만 사용한다. 미응답 라운드를 실패로 닫고 최종 정산하는 과정을 원자적으로 처리하며, 동시 답안 제출·종료 재시도에서 결과가 바뀌거나 중복 지급되지 않게 한다.

이 구조는 위조 지급과 중복 정산을 막기 위한 것이다. 공개 이미지를 비교하거나 공개 퍼즐을 자동으로 푸는 프로그램까지 완전히 차단하지는 못한다. 같은 사진의 URL이나 내부 식별자만 비교해 답을 알아내기 쉽게 만드는 것은 줄이되, 정상 사용자에게 왜곡된 이미지·과도한 대기·임의의 초고속 성공 처벌을 넣지 않는다.

### 8.4 구현 규모의 비교

아래는 현재 프로젝트에 익숙한 개발자 1명의 작업량을 **인일 단위로 추정**한 것이다. 일정 약속이나 실제 측정치가 아니며 공통 작업은 한 번만 계산한다.

| 작업 | 초기 추정 | 포함 범위 |

| 공통 기반 | 5~9인일 | 준비/시작, 이미지 품질·중복 정책, 게임 등록·답안 계약, 무효/복구, DB별 정산 검증 |
| 공통 사진 고유 기능 | 추가 2~3인일 | 집합 출제, 선택 UI, 작은 화면 검증 |
| 도미노 고유 기능 | 추가 4~6인일 | 패·사슬 UI, 검증된 구조 풀, 조립 답안·되돌리기 |
| 길 잇기 고유 기능 | 추가 5~8인일 | 경로 입력·수정, 판 생성·경로 검사, 실제 터치 튜닝 |
| 저울 고유 기능 | 추가 3~5인일 | 사진 묶음·저울 UI, 템플릿·정답 검증, 설명 피드백 |
| 공통 사용자 검증 | 추가 2~4인일 | 테스트 준비·진행·문항 조정. 참가자 모집 대기 제외 |

기존 기능과의 회귀 문제나 실제 이미지 품질에 따라 범위는 늘 수 있다. 새로운 AI 모델, 생성 이미지, 대규모 수작업 인물 라벨링, 실시간 대전 서버는 필요 없다.

## 9. 출시 여부를 결정할 검증

### 9.1 실제로 확인한 것

현재 5종의 코드상 규칙·보상·이미지 흐름을 읽고, 도미노와 저울 예시의 구조 및 보상 확률을 작은 독립 계산으로 검산했다. 프로덕션 코드와 테스트는 변경하지 않았다.

| 확인 항목 | 결과 | 확인하지 못하는 것 |
|---|---|---|
| 도미노 예시의 모든 패 순서·방향 탐색 | A→D에 합법해 2개. `AB,BC,CA,AD`와 `AC,CB,BA,AD`. AD부터 쓰면 완성해 0개 | 실제 유저가 12초 안에 재미있게 푸는지 |
| 저울 예시의 계수 비교 | B의 무게가 양수일 때 목표는 3B, 보기는 3B·4B·2B·B로 정답 1개 | 실제 사진 구별과 첫 규칙 이해 |
| 4지선다 5문제 무작위 응답 | 3개 이상 정답 `106/1024 ≈ 10.35%`, 만점 `1/1024 ≈ 0.098%`, 기대 지급 약 `103.71 P` | 실제 성공률, 조립형 게임의 무작위 성공률 |

확률은 각 문항의 정답이 하나이고, 독립적으로 균등 선택하며, 모두 응답한다는 가정이다. 전체 4⁵개 답안 또는 이항분포로 재현할 수 있다. 도미노·길 잇기에 4지선다의 정답 확률을 그대로 적용하지 않는다.

### 9.3 비팬을 포함한 짧은 플레이 테스트

최소 24명을 모집하고 스트리머를 거의 모르는 이용자와 아는 이용자를 절반씩 포함한다. 모바일을 절반 이상 포함하고 게임 순서를 교차 배정한다. 게임별 같은 규칙 예시를 제공한 뒤 3게임씩 플레이한다. 이 규모는 초기 문제 발견용이며 통계적 우열 확정용이 아니다.

| 측정 항목 | 초기 목표·출시 판단 |
|---|---|
| 규칙 이해 | 10초 내 예시 후 80% 이상이 목표와 첫 조작을 설명. 미달이면 시간부터 줄이지 말고 규칙·화면 수정 |
| 성공률 | 전체 70~90%를 초기 탐색 범위로 관찰. 기존 이미지 게임의 실제 분포와도 비교하고 무조건 맞추지는 않음 |
| 만점률 | 20~50%를 초기 탐색 범위로 관찰. 기대 지급량과 난도의 차이를 함께 보고 후속 조정 |
| 플레이 시간 | 준비 완료 후 최초 카운트다운부터 결과 화면까지 측정. 중앙값 30~50초 목표, 정상 환경의 95백분위가 게임별 57/67초 상한 안에 들어오는지 확인. 준비 시간은 별도 기록 |
| 사전지식 영향 | 비팬이 화면 정보만으로 이유를 설명할 수 있어야 함. 집단 성공률 차이 10%p 이상이면 원인 조사·추가 표본 확보 |
| 기기·입력 영향 | 입력 오류로 인한 실패가 전체 라운드의 5%를 넘으면 보상 출시 보류 |
| 납득 가능성 | 풀 수 없음·다중 정답 거절·이미지 불일치 사례 0건 목표. 발견 시 해당 출제 구조 차단 |
| 재미·반복 | 게임별 ‘한 번 더 하고 싶다’ 5점 척도 중앙값 4 이상을 목표로 하고 자유 의견을 함께 읽음 |

이 목표값들은 사용자 데이터에서 얻은 현재 수치가 아니라 **출시 판단을 위한 제안**이다. 표본이 작으므로 80%·10%p 등의 경계에서 기계적으로 합격/불합격시키지 않고 실제 실패 원인을 확인한다.

도미노의 첫 검증은 ‘의미 있는 순서 선택이 생기는가’, 길 잇기는 ‘터치 실수가 사고보다 더 큰 장애가 되는가’, 저울은 ‘짧은 퍼즐인가 계산 숙제인가’, 공통 사진은 ‘한 화면에서 편하게 비교되는가’에 집중한다. 이 질문에서 문제가 확인되면 보상 금액을 바꾸기 전에 해당 게임의 출제와 조작을 수정한다.
